Top level

STREAM.STREAM — Module
STREAM

Thermal-hydraulic and neutronic modelling for research reactors, built on ModelingToolkit. A model is assembled from acausal components, compiled with mtkcompile, and solved through solve_steady or solve_transient.

The submodule stack

Each submodule reaches only downward, so the dependency order is also the reading order:

Substances -> Dimensionless -> {HTC, Friction, LocalLoss, Thresholds}           -> Components -> {DecayHeat, Assemblies} -> Solvers
ModuleWhat lives there
Substancescoolants and their property correlations
HTCwall heat transfer models and Nusselt correlations
FrictionDarcy friction factor models and correlations
LocalLossIdelchik minor losses for sudden area changes, and discharge coefficients
Thresholdssafety limits and the post-solve analysis that applies them
Componentsthe MTK components a model is built from
DecayHeatdecay heat contributions and the standards behind them
Assemblieswiring verbs and named arrangements of components
Utilitiesgrid resampling and axial profile helpers

assembly composes components with a list of connections, and port reaches one cell of a per-cell connector array. Every submodule can use both.

STREAM.AbstractShape — Type
AbstractShape

The cross-section of a Duct: Rectangular, Circular, Annular, or Effective for one known only by its area and perimeter.

A new shape defines flow_area, wetted_perimeter and walls. Correlations that only hold for one shape dispatch on it, as Duct{<:Rectangular}.

Annular(D1, D2) <: AbstractShape

The ring between two concentric circles, such as the coolant gap around a fuel rod in a tube. The diameters go in either order: D_in is the smaller and D_out the larger. Either may be a design knob. Its walls are inner and outer.

STREAM.Duct — Type
Duct(L, shape; heated)

A straight duct of length L and constant cross-section, heated over some of its walls.

Each heated wall is one face of a channel built on the duct, with its own wall temperature and heat flow, named after the wall: left and right for a rectangle, outer for a circle, inner and outer for an annulus. A wall left out of heated is not heated, and the channel gives it no face. The defaults heat both long walls of a rectangle across their width, a circle's whole wall, and an annulus's inner wall, the rod. An Effective duct has no default.

\[D_h = 4A / P_{wet}\]

Any length may be a design knob (see @design_knob).

Arguments

  • L: length [m]
  • shape: the cross-section, an AbstractShape
  • heated: the heated width of each heated wall [m], as a named tuple such as (left=0.063, right=0.063). A number gives every default wall that width.

Returns

A Duct with fields L, shape and heated. flow_area, hydraulic_diameter, wetted_perimeter and heated_perimeter give the rest.

Throws

  • ArgumentError: for a wall the shape does not have, or a heated width that is not positive or is wider than its wall

Examples

A 70 mm by 1.27 mm MTR channel, 0.6 m long, and the same channel heated on one side:

julia> d = Duct(0.6, Rectangular(0.07, 0.00127))Duct, 0.6 m long, Rectangular(0.07, 0.00127)  flow area           8.89e-5 m^2  hydraulic diameter  0.0024947 m  heated              0.07 m left, 0.07 m rightjulia> Duct(0.6, Rectangular(0.07, 0.00127); heated=(left=0.063,)).heated(left = 0.063,)

STREAM.flow_regime_blend — Method
flow_regime_blend(Re, re_bounds, laminar, turbulent)

Choose between a laminar and a turbulent value on Reynolds number, blending linearly across the transition band.

re_bounds is (re_lo, re_hi): at or below re_lo the flow is laminar, above re_hi it is turbulent, and between them the two values are interpolated linearly in Re. Both values are evaluated whichever is returned, so each must be finite everywhere.

Arguments

  • Re: Reynolds number to classify
  • re_bounds: (re_lo, re_hi) band edges
  • laminar, turbulent: the two values to select between or blend

Returns

The laminar value, the turbulent value, or their linear blend.

Examples

julia> [flow_regime_blend(Re, (2000.0, 5000.0), 4.0, 100.0) for Re in (1000.0, 3500.0, 8000.0)]3-element Vector{Float64}:   4.0  52.0 100.0

STREAM.knob_defaults — Method
knob_defaults(knobs) -> Vector{Pair}

Collect each knob's stored default into operating-point pairs. GlobalScope parameters are not auto-applied from symbol metadata at problem build, so a model assembles its baseline operating point as [knob_defaults(knobs); state_guesses...] to run on the declared defaults with no caller input.

Arguments

  • knobs: iterable of design knobs (from @design_knob)

Returns

Vector{Pair} mapping each knob to its default value.

source
STREAM.@design_knob — Macro
@design_knob name = default

Declare a design knob, a parameter that can change between solves without recompiling.

A knob is a named scalar input that drives geometry, or any other parameter, across one or more components, and is varied at solve time through the operating point or remake.

The knob is a GlobalScope parameter, so the same knob passed into several composed components stays one un-namespaced parameter at the root system. remake(name => x) sets it once and the change reaches every component that uses it. The default is stored on the knob; knob_defaults gathers it into the operating point so a model runs without the caller supplying a value.

Example

gap = @design_knob gap = 0.0024geometry = Duct(0.6, Rectangular(0.067, gap); heated=0.063)   # build with it, then:solve_steady(sys, [gap => 0.0027, ...])                         # a new gap, no rebuild

See Scan a design parameter.

Returns

Binds name in the caller's scope to the knob and returns it.
