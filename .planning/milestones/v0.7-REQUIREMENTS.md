# Requirements: STREAM.jl

**Defined:** 2026-03-27
**Core Value:** A Julia MTK-based thermal-hydraulics library that matches Python STREAM results, proving the architecture is sound before large-scale porting begins.

## v0.7 Requirements

### Pressure Field

- [x] **PRES-01**: Per-cell pressure drop dp[i] computed individually for each axial cell (replaces single i_mid lump in _channel_base_eqs); dP = sum(dp[i]) becomes the exact total
- [x] **PRES-02**: Per-cell absolute pressure P[i] available as observed variables in Channel, ChannelAndContacts, and ChannelHeatFlux (P[i] ~ inlet.P - cumsum(dp[1:i]))
- [x] **PRES-03**: sat_temperature(P) added as @register_symbolic function in fluids.jl (Simantov or Antoine equation for light water saturation temperature vs. pressure)
- [x] **PRES-04**: T_sat[i] and T_ONB[i] available as observed variables in ChannelAndContacts and ChannelHeatFlux (T_ONB via Bergles-Rohsenow dT_ONB formula using P[i] and q_wall[i])
- [x] **PRES-05**: Transient loop with step pump dP change: dp[i] and P[i] respond correctly during transient; dP = inlet.P - outlet.P captures total drop including inertia; at new steady state the (i/n) correction term approaches 0
- [x] **PRES-06**: Momentum ODE numerical consistency: (L/A)*Dt(mdot) = (P_in - P_out) - sum(dp) residual within ODE solver tolerance throughout transient
- [x] **PRES-07**: Channel alone (no standalone Inertia in loop) produces physically reasonable transient: mdot evolves smoothly from initial to final steady state, no NaN or Inf
- [x] **PRES-08**: All three channel variants (Channel, ChannelAndContacts, ChannelHeatFlux) have momentum ODE present; steady-state dP = sum(dp[i]) and P[i] = inlet.P - cumsum(dp) (correction = 0 at Dt(mdot)=0)
- [x] **PRES-09**: ChannelAndContacts (observed_mode=true path in _channel_base_eqs) transient solves without error; T_sat[i] and T_ONB[i] accessible during transient
- [x] **PRES-10**: ChannelHeatFlux transient solves without error; T_sat[i] and T_ONB[i] accessible during transient
- [x] **PRES-11**: Channel + standalone Inertia in series: mtkcompile succeeds (no over-constraint). Transient solve is NOT supported -- two competing Dt(mdot) ODEs for the same flow variable (distributed channel inertia + concentrated Inertia component) causes solver instability. This is a physical over-specification, not a bug.
- [x] **PRES-12**: n=1 channel edge case: P[1] = outlet.P (formula reduces correctly for single cell)
- [ ] **VAL-PRES-01**: Quantitative cross-validation of dp[i] and P[i] against Python STREAM pressure_diff with mdot2 != 0; dp[i] within 1%, P[i] within 0.1% relative to inlet.P scale. Deferred: requires Python reference data generation.

### Subcooled Boiling Correlations

- [x] **SCB-01**: McAdams_SCB_heat_flux(T_sat, T_wall) → W/m² implemented as standalone Julia function in src/physical_models/subcooled_boiling.jl
- [x] **SCB-02**: Bergles_Rohsenow_SCB_heat_flux(T_wall, T_sat, pressure, ...) → W/m² implemented with surface tension / latent heat inputs
- [x] **SCB-03**: partial_SCB_correction(q_spl, q_scb, q_scb_inc) → dimensionless factor; Bergles-Rohsenow smooth SPL↔SCB blend
- [x] **SCB-04**: regime_dependent_q_scb(; pressure, Re_transition) factory → (T_wall, T_sat, Re) closure; selects McAdams (turbulent) or Bergles-Rohsenow (laminar) by Re

### In-loop SCB in Channels

- [x] **ISCB-01**: ChannelAndContacts accepts optional scb_correction kwarg (closure or nothing); when provided, h_tc[i] is replaced by ifelse(T_wall[i] >= T_ONB[i], h_spl[i] * partial_scb_factor, h_spl[i]) using the ifelse() MTK pattern
- [x] **ISCB-02**: In-loop SCB correction validated: with T_wall >> T_sat the effective HTC increases relative to pure single-phase; with T_wall < T_ONB the result matches the base single-phase case exactly

### Threshold Analysis — Physics Layer

- [x] **THRS-01**: Bergles_Rohsenow_T_ONB(pressure, q_wall, T_sat) → temperature at onset of nucleate boiling [K]
- [x] **THRS-02**: q_boiling_onset(mdot, T_sat, T_inlet, cp) → power at which bulk reaches saturation [W]
- [x] **THRS-03**: q_OFI_whittle_forgan(mdot, T_sat, T_inlet, pipe) → onset of flow instability power [W/m²]
- [x] **THRS-04**: q_OSV_saha_zuber(T_inlet, mdot, pipe, ...) → onset of significant void heat flux [W/m²]; self-consistent formulation (Saha-Zuber computed_bulk variant)
- [x] **THRS-05**: q_CHF_sudo_kaminaga(T_bulk, mdot, pipe, gravity) → critical heat flux [W/m²]; Kaminaga 1998
- [x] **THRS-06**: q_CHF_mirshak(T_bulk, T_sat, pressure, v) → CHF [W/m²]; valid for v > 1.5 m/s
- [x] **THRS-07**: q_CHF_fabrega(T_inlet, T_sat, pipe) → CHF [W/m²]; valid for v < 0.5 m/s
- [x] **THRS-08**: twall_limit(T_wall, inhomogeneity_factor) → effective wall temperature after inhomogeneity scaling

### Threshold Analysis — Post-process Layer

- [x] **THRS-09**: threshold_analysis(sol, channel_sys; kwargs...) → NamedTuple; extracts T[i], mdot, T_wall[i], P[i] from MTK solution and calls user-specified threshold functions; returns one named field per function; handles both steady-state and transient ODESolution uniformly (scalar per cell for steady; vector-over-time per cell for transient)

### HTC Library Completions

- [x] **HTC-01**: Marco_Han_Nusselt(aspect_ratio) → Nu for fully-developed laminar flow in rectangular duct with uniform wall temperature (4-sided heating)
- [x] **HTC-02**: fully_developed_laminar_h_spl(; Dh, aspect_ratio) → correlation closure (Re, Pr, T_bulk, T_wall) -> Nu using Marco-Han
- [x] **HTC-03**: developing_laminar_h_spl(; Dh, develop_length, aspect_ratio) → correlation closure; Shah & London interpolation for thermally developing flow
- [x] **HTC-04**: maximal_htc(correlations...) → correlation closure that returns elementwise max Nu across all provided correlations at each call

### Friction Library Completions

- [x] **FRIC-01**: turbulent_friction(Re, epsilon=0) → Darcy friction factor via Colebrook-White approximation (RELAP/KAERI form); epsilon is relative roughness, defaults to smooth pipe
- [x] **FRIC-02**: viscosity_correction(heat_wet_ratio, mu_ratio) → multiplicative correction factor for temperature-dependent viscosity in friction calculations

## v0.8 Requirements (STREAM Composer GUI)

> **Separate project track.** These requirements are for the STREAM Composer desktop GUI application, not the Julia library. The GUI lives in `gui/` within this repo (or a sibling repo). The coupling contract between the two is the **component metadata registry** (`gui/src/registry/components.json`), which maps STREAM.jl's public component API to GUI node descriptors. Updating it for a new STREAM.jl component is a JSON edit, not a rebuild.
>
> **Research basis:** `.planning/research/gui-feasibility/RESEARCH.md`

### Scaffold & Infrastructure

- [x] **SCAF-01**: Developer can run the GUI app locally in dev mode with hot-reload on both Windows and Linux (`npm run tauri dev`)
- [x] **SCAF-02**: User can install the GUI as a native desktop app — `.exe` installer on Windows, `AppImage` on Linux
- [x] **SCAF-03**: Component metadata registry JSON defines all 12 STREAM.jl components (9 hydraulic + 3 thermal: ChannelAndContacts, HeatDiffusion, ConstantTemperature) with their ports (name, type, side), constructor signatures (positional vs keyword per CLAUDE.md), parameter types, units, defaults, and descriptions
- [x] **SCAF-04**: Adding a new STREAM.jl component to the GUI requires only a JSON entry in the registry — no TypeScript changes, no recompilation
- [x] **SCAF-05**: Registry records the STREAM.jl target version so the GUI can display which library version it was built against

### Canvas & Node Editor

- [x] **CANV-01**: User sees an empty canvas with working zoom (scroll), pan (drag), minimap, and fit-to-view controls
- [x] **CANV-02**: User can drag a component type from the left toolbox onto the canvas to create a named instance (default name: `comp_type_N`)
- [x] **CANV-03**: User can connect two components by dragging from a FlowPort-out handle to a FlowPort-in handle; the edge represents a STREAM.jl `connect(a.outlet, b.inlet)` call
- [x] **CANV-04**: User can select and delete components and connections individually or as a group
- [x] **CANV-05**: User can freely drag-reposition components on the canvas without losing their connections
- [x] **CANV-06**: Each canvas node displays the component type label and user-assigned instance name
- [x] **CANV-07**: User can undo and redo canvas operations (add node, delete node, add edge, delete edge, move node)

### Parameter Editing

- [x] **PARA-01**: User can click any canvas node to open a parameter editing sidebar on the right panel
- [x] **PARA-02**: User can edit all scalar parameter values for the selected component; changes are reflected immediately in the code preview
- [x] **PARA-03**: User can toggle Pump mode between fixed-dP and fixed-mdot; the sidebar shows the appropriate parameter field(s) for the selected mode
- [x] **PARA-04**: User can configure PipeGeometry for channel components: choose circular vs rectangular via a picker, enter the required dimensions (L, D for circular; L, W, H for rectangular)
- [x] **PARA-05**: User can rename a component instance; the name becomes the `@named` variable name in generated code; invalid Julia identifiers are rejected with an inline error
- [x] **PARA-06**: Sidebar shows a per-field validation error when a value is the wrong type, empty, or out of a reasonable physical range

### Code Generation

- [x] **CODE-01**: User can view a live-updating read-only preview of the complete generated Julia code in a collapsible bottom panel or sidebar tab
- [x] **CODE-02**: User can export the composed system as a `.jl` file to a user-chosen disk location via native file save dialog
- [x] **CODE-03**: Generated code declares all components with `@named` macro using correct positional vs keyword arguments matching STREAM.jl CLAUDE.md conventions (e.g., `@named pump = Pump(30000.0)`, not `Pump(dP_pump=30000.0)`)
- [x] **CODE-04**: Generated code includes one `connect(a.outlet, b.inlet)` call per canvas edge, using STREAM.jl port names exactly
- [x] **CODE-05**: Generated code includes `@named sys = compose(System(connections, t; name=:sys), components...)` + `ssys = mtkcompile(sys)` boilerplate
- [x] **CODE-06**: User can configure boundary conditions (pressure anchor `pump.inlet.P ~ 1.0e5`, fixed-temperature thermal pins) via a dedicated BC panel; generated code pushes these into the connections list
- [x] **CODE-07**: Generated Julia identifiers are validated: no spaces, no Julia reserved words, no characters illegal in Julia symbols; component names start with a letter

### Project Persistence

- [x] **PERS-01**: User can save the full canvas state (nodes, edges, positions, parameter values, BC config) as a `.streamgui` JSON file via Ctrl+S / File→Save
- [x] **PERS-02**: User can open an existing `.streamgui` file to fully restore the canvas via Ctrl+O / File→Open
- [x] **PERS-03**: App shows an "unsaved changes" confirmation dialog before closing, creating new, or opening a project when there are unsaved changes
- [x] **PERS-04**: App shows a "Recent Projects" list on the startup/empty canvas screen (last 5 opened files)

### UI Design Quality

- [x] **DSGN-01**: App uses shadcn/ui for all UI primitives (buttons, inputs, dropdowns, panels, dialogs, tooltips) — no hand-rolled CSS component implementations
- [x] **DSGN-02**: App has a fixed three-panel layout: left toolbox (collapsible) → center ReactFlow canvas → right parameter sidebar (collapsible)
- [x] **DSGN-03**: Toolbox groups components into labeled categories (`Hydraulic`, `Thermal`) with a distinct icon per component type
- [x] **DSGN-04**: Canvas nodes are visually differentiated by component type using consistent color coding and/or icons
- [x] **DSGN-05**: Every frontend phase is preceded by `/gsd:ui-phase` which produces a UI-SPEC.md design contract before any component is coded; every frontend phase output is audited by `/gsd:ui-review` before marking complete

### Topology Validation Alerts

- [x] **VALD-01**: App renders a visual warning indicator on any canvas node that has a mandatory unconnected FlowPort (inlet or outlet with no edge attached)
- [x] **VALD-02**: App detects the absence of a pressure boundary condition in the system and shows a non-blocking alert banner (no pressure anchor means the system is underdetermined)
- [x] **VALD-03**: App detects a system with no driving element (no Pump or Gravity component) and shows a non-blocking alert banner

### Thermal Composition (Phase 40)

- [x] **THERM-01**: ChannelAndContacts canvas node displays thermal_left[i] and thermal_right[i] port arrays as stacked handles along the node edge, where the number of handles equals parameter `n`
- [x] **THERM-02**: User can connect a HeatDiffusion node's thermal_left[i] / thermal_right[i] ports to the corresponding ChannelAndContacts thermal handles
- [x] **THERM-03**: Code generator detects symmetric/asymmetric/one-sided thermal topologies and emits the appropriate STREAM.jl composition helper call (`symmetric_plate(cac, fuel)`, `plate(cac, fuel)`, or `one_sided_connection(cac, fuel, :left)`) instead of raw connect() calls for thermal arrays

## Out of Scope

| Feature | Reason |
|---------|--------|
| Subcooled boiling two-phase drift-flux model | Out of scope — single-phase effective HTC only |
| In-loop boiling in Channel / ChannelHeatFlux | Only ChannelAndContacts gets SCB correction (it has the ThermalPort needed to resolve T_wall[i]) |
| Surface tension / latent heat as @register_symbolic | Only needed for Bergles-Rohsenow SCB; will pass as scalar constants for now |
| Sequential quasi-static solver | Deferred — not blocking current use cases |
| State serialization (YAML/DataFrame) | Deferred — ODESolution sufficient for now |
