## Color

### Light Mode (`:root`)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` oklch(1 0 0) = white | Canvas background, panel backgrounds |
| Secondary (30%) | `var(--card)` oklch(1 0 0) / `var(--muted)` oklch(0.97 0 0) | Node cards, sidebar, toolbox, toolbar |
| Accent (10%) | blue-500 #3b82f6 / amber-500 #f59e0b | Node category stripes, thermal edges |
| Destructive | `var(--destructive)` oklch(0.577 0.245 27.325) | Validation error rings |

### Dark Mode (`.dark`)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` oklch(0.145 0 0) = near-black | Canvas background, panel backgrounds |
| Secondary (30%) | `var(--card)` oklch(0.205 0 0) / `var(--muted)` oklch(0.269 0 0) | Node cards, sidebar, toolbox, toolbar |
| Accent (10%) | blue-500 #3b82f6 / amber-500 #f59e0b | Node category stripes, thermal edges (unchanged) |
| Destructive | `var(--destructive)` oklch(0.704 0.191 22.216) | Validation error rings (lighter red for dark bg) |

All CSS variables already defined in `gui/src/index.css` lines 6-73. No manual color additions needed.

### ReactFlow Canvas Colors

| Element | Light Mode | Dark Mode | Source |
|---------|------------|-----------|--------|
| Background dots | `#ccc` | `#555` | Explicit `color` prop on `<Background>` |
| Controls/MiniMap | ReactFlow light defaults | ReactFlow dark defaults | `colorMode` prop on `<ReactFlow>` |

### Hardcoded Colors -- No Changes

These hardcoded hex values remain identical in both themes. They were chosen for legibility on both light and dark backgrounds:

| Element | Color | Light BG Contrast | Dark BG Contrast |
|---------|-------|-------------------|------------------|
| FlowPort outlet handle | #60a5fa (blue-400) | PASS | PASS |
| FlowPort inlet handle | #94a3b8 (slate-400) | PASS | PASS |
| Thermal edge stroke | #f59e0b (amber-500) | PASS | PASS |
| Error ring | `var(--destructive)` | PASS (theme-adaptive) | PASS (theme-adaptive) |

CRITICAL: Do NOT change the thermal edge stroke color `#f59e0b` between themes. `CanvasPanel.tsx` line 74 uses string comparison `edge.style?.stroke === "#f59e0b"` for thermal edge detection. Changing this value breaks layer filtering.

### Layer Toggle Dark Mode Fix

The Toolbar layer toggle items use these Tailwind classes that need `dark:` variant overrides for legibility:

| Toggle | Current Class | Dark Mode Override |
|--------|--------------|-------------------|
| Hydraulic (active) | `data-[state=on]:text-blue-700` | Add `dark:data-[state=on]:text-blue-300` |
| Hydraulic (active bg) | `data-[state=on]:bg-blue-500/25` | No change needed (transparent overlay works on both) |
| Both (active) | `data-[state=on]:bg-slate-200 data-[state=on]:text-slate-700` | Add `dark:data-[state=on]:bg-slate-700 dark:data-[state=on]:text-slate-200` |
| Thermal (active) | `data-[state=on]:text-amber-700` | Add `dark:data-[state=on]:text-amber-300` |
| Thermal (active bg) | `data-[state=on]:bg-amber-500/25` | No change needed (transparent overlay works on both) |

Accent reserved for: node category left-border stripes, toolbox category indicators, thermal edge stroke. NOT for the theme toggle button itself.

## useTheme Hook Contract

| Property | Value |
|----------|-------|
| File | `gui/src/hooks/useTheme.ts` |
| Return type | `{ theme: Theme, resolvedTheme: "light" \| "dark", setTheme: (t: Theme) => void }` |
| Theme type | `"light" \| "dark" \| "system"` |
| Storage key | `"stream-composer-theme"` |
| Storage mechanism | `localStorage` (not Zustand, not Tauri plugin-store) |
| Class target | `document.documentElement` (the `<html>` element) |
| Class toggled | `"dark"` |
| System detection | `window.matchMedia("(prefers-color-scheme: dark)")` with `change` event listener |
| Listener cleanup | `useEffect` cleanup function removes listener when theme changes away from `"system"` or on unmount |

---

## FOUC Prevention Contract

| Property | Value |
|----------|-------|
| Mechanism | Synchronous inline `<script>` in `gui/index.html` `<head>`, before any CSS or JS bundle |
| Logic | Read `localStorage.getItem("stream-composer-theme")`, resolve "system" via `matchMedia`, add `"dark"` class to `document.documentElement` if resolved dark |
| Constraint | Must execute before first paint -- no `defer`, no `async`, no module script |

## Integration Points

### CanvasPanel.tsx

| Change | Details |
|--------|---------|
| `colorMode` prop | Pass `resolvedTheme === "dark" ? "dark" : "light"` to `<ReactFlow>` |
| `Background` color | Pass `color={resolvedTheme === "dark" ? "#555" : "#ccc"}` to `<Background>` |
| Data flow | `resolvedTheme` comes from `useTheme()` called in `App.tsx` and passed via props or React context |

### App.tsx

| Change | Details |
|--------|---------|
| `useTheme()` call | Call the hook at the app root level. It manages the `dark` class side effect. |
| Pass `resolvedTheme` | Either via props drilling to CanvasPanel and ThemeMenu, or via a minimal React context |

### Toolbar.tsx

| Change | Details |
|--------|---------|
| ThemeMenu placement | Add `<ThemeMenu>` in the right section `<div>`, before the Export button |

## Implementation Boundaries

### In Scope for Phase 44
