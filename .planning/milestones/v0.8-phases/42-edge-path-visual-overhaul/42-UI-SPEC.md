## Arrowhead Spec (D-01, D-02)

### Hydraulic Edges: Filled Arrowhead at Target

Applied via `markerEnd` on each hydraulic edge object in the `addEdge` store action.

```typescript
markerEnd: {
  type: MarkerType.ArrowClosed,
  width: 16,
  height: 16,
  color: '#b1b1b7',
}
```

- Width/height: 16px -- visible at default zoom without being oversized
- Color: matches edge stroke color for visual continuity
- Position: ReactFlow places the marker at the target end automatically
- `strokeWidth` on the edge remains at the ReactFlow default (1px)

### Thermal Edges: No Arrowhead

Thermal edges retain their existing style (`stroke: "#f59e0b"`, `strokeDasharray: "6 3"`) with no `markerEnd`. Symmetric heat exchange has no meaningful direction.

### Edge on Project Load

When loading a `.streamgui` file, edges serialized without `markerEnd` must be re-enriched. The `deserializeProject` function (or the store's `loadProject` action) must re-apply `markerEnd` to all hydraulic edges and the parallel offset to bidirectional pairs, using the same logic as `addEdge`.

## Parallel Edge Routing Spec (D-03, D-04)

### Detection

When `addEdge` is called, check if a reverse edge already exists:

```typescript
// Reverse edge: same node pair, opposite handle assignment
const reverseExists = edges.some(e =>
  e.source === connection.target &&
  e.target === connection.source &&
  e.sourceHandle === connection.targetHandle &&
  e.targetHandle === connection.sourceHandle
);
```

### Offset Application

If a reverse edge exists, apply symmetric offset to BOTH edges in the pair:

| Edge Direction | pathOptions.offset |
|---------------|-------------------|
| Original (first added) | +10 |
| Reverse (second added) | -10 |

Symmetric +/-10px gives 20px total separation between parallel paths. The 20px total separation is a ReactFlow `pathOptions.offset` rendering constant tuned for visual clarity of parallel smoothstep edges at default zoom -- it is not a layout spacing token.

Implementation: When the reverse edge is detected, mutate the existing edge in the array to add `pathOptions: { offset: 10 }` and set the new edge to `pathOptions: { offset: -10 }`.

### Edge Removal Cleanup

When an edge is removed via `removeEdge` or `onEdgesChange`, check if its partner in a bidirectional pair still exists. If so, remove the offset from the surviving partner edge (set `pathOptions` to `undefined` or remove the `offset` property) so it routes centrally again.

## FlowPort Handle Polarity Spec (D-06, D-07)

### Direction Detection

Port direction is inferred from the port name, consistent with the existing pattern in StreamNode.tsx:

```typescript
const isInPort = port.name.includes("in");  // inlet -> target
const isOutPort = port.name.includes("out"); // outlet -> source
```

No registry schema changes needed. The existing `port.name` convention (`inlet`, `outlet`) is the source of truth.

### Handle Style Application

In `StreamNode.tsx`, the FlowPort handle rendering loop applies polarity colors:

```typescript
// For FlowPort handles:
const isInPort = port.name.includes("in");
const handleStyle = {
  background: isInPort ? "#93c5fd" : "#1d4ed8",
  border: `1.5px solid ${isInPort ? "#3b82f6" : "#1e40af"}`,
  ...(dimFlowHandles ? { opacity: 0.2, pointerEvents: "none" as const } : {}),
};
```

The existing dimming logic from Phase 41 is preserved -- when `dimFlowHandles` is true, opacity overrides the polarity color.

## Cursor Glitch Fix (D-08)

### Root Cause

ReactFlow handle elements (`.react-flow__handle`) lose their cursor style during edge drag operations due to CSS specificity conflicts or missing cursor declarations on handle pseudo-states.

### Fix

Add to `gui/src/index.css` (after the ReactFlow style import in the component tree):

```css
.react-flow__handle {
  cursor: crosshair;
}

.react-flow__handle:hover {
  cursor: crosshair;
}
```

If the root cause is a pointer-events issue during drag (cursor disappears mid-drag), investigate `.react-flow__edge-interaction` and `.react-flow__connection` overlay elements. The fix must ensure cursor remains visible throughout the entire connect-drag interaction.

## Rename Counter Bug Fix (D-09)

### Current Behavior (Buggy)

`reconstructInstanceCounters` in `gui/src/lib/projectIO.ts` uses a generic regex that matches any node name ending in `_N`, which incorrectly updates counters for custom-renamed nodes.

### Fixed Behavior

```typescript
function reconstructInstanceCounters(nodes: SerializedNode[]): Record<string, number> {
  const counters: Record<string, number> = {};
  for (const node of nodes) {
    const key = node.data.componentId.toLowerCase();
    const pattern = new RegExp(`^${key}_(\\d+)$`);
    const match = node.data.instanceName.match(pattern);
    if (match) {
      const num = parseInt(match[1], 10);
      counters[key] = Math.max(counters[key] ?? 0, num);
    }
  }
  return counters;
}
```

Only nodes whose `instanceName` matches the exact pattern `<componentId_lowercase>_<number>` contribute to counter reconstruction. Custom-renamed nodes (e.g., `my_special_pump`) are ignored.
