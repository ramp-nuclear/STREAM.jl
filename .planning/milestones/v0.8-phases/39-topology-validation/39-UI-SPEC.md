### Error Ring Specification

- Class: `ring-2 ring-destructive ring-offset-1`
- Applied to: StreamNode outer card `<div>` when `errorNodeIds.has(node.id)` is true
- Coexistence with selection ring: Both rings render simultaneously. Selection ring is `ring-2 ring-[var(--ring)]`. When both are active, the destructive ring takes visual priority via `ring-offset-1` creating a 2px gap outside the selection ring. Implementation: apply destructive ring as an outer wrapper or use `outline` for one of the two rings (Claude's discretion per D-07).
- Persistence: Ring appears after validation dialog is dismissed. Clears reactively when the underlying port gets connected (edge added).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Dialog title | "Validation Failed" |
| Dialog description | "Fix the following issues before exporting." |
| Node error group heading | "Node Errors" |
| System error group heading | "System Errors" |
| Unconnected port line | "{instanceName}: {portName} unconnected" |
| No pressure anchor line | "No pressure boundary condition" |
| No driving element line | "No driving element (add a Pump or Gravity component)" |
| Dialog dismiss button | "Back to Canvas" |
| Dialog icon | `AlertTriangle` from lucide-react, 16px, `text-destructive` inline with title |

### Copywriting Notes

- Error lines are plain text, not links or buttons. The user fixes them on the canvas after dismissing.
- Node errors (VALD-01) are listed first, grouped under "Node Errors". One line per unconnected port.
- System errors (VALD-02, VALD-03) are listed second, grouped under "System Errors".
- If only one group has errors, the other group heading is omitted entirely.
- If only system errors exist (no node errors), no red rings appear on nodes.

## Interaction Contract

### Validation Trigger (D-01, D-02)

Validation runs ONLY when the user clicks "Export .jl" (Toolbar) or triggers Save (Ctrl+S / File > Save). It does NOT run continuously during canvas construction.

| Trigger | Location | Behavior on Failure |
|---------|----------|---------------------|
| Export .jl button | `Toolbar.tsx` | Block export, show AlertDialog |
| Save project (Ctrl+S) | Store `saveProject` action | Block save, show AlertDialog |

On success (no validation errors): proceed with export/save as normal.

### Post-Dialog Behavior (D-05, D-06)

After the user clicks "Back to Canvas" to dismiss the dialog:
1. `errorNodeIds` set in store is populated with IDs of nodes that have unconnected FlowPorts.
2. Red rings appear on those nodes immediately.
3. When the user connects a port (adds an edge), the store checks if both ports on the affected nodes are now connected. If so, removes the node ID from `errorNodeIds`. Ring disappears reactively.
4. System-level errors (VALD-02, VALD-03) produce dialog text only -- no rings, no persistent indicators.

### What Counts as Connected (D-10, D-11, D-12)

| Check | Condition |
|-------|-----------|
| Port connected | At least one edge in `edges` with `sourceHandle` or `targetHandle` matching the port name on that node |
| Pressure anchor | `bcs.length > 0` |
| Driving element | At least one node with `componentId === "Pump"` OR `componentId === "Gravity"` |

ThermalPorts are NOT checked in this phase (Phase 40 scope).
