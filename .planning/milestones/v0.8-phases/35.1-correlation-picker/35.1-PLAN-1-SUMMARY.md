# Phase 35.1 Plan 1: Types and Registry Schema Summary

**One-liner:** TypeScript interfaces extended with `sub_parameters` on `FunctionOption` and new `FactoryCorrelationValue`; `components.json` factory options now carry full nested sub-parameter definitions for all three Channel-family components.

## What Was Built

Established the type-safe schema foundation for the correlation picker UI.

### Task 1 — `registry/types.ts`

- Added `sub_parameters?: Parameter[]` to `FunctionOption` (forward reference to `Parameter`, valid in TypeScript)
- Added new exported `FactoryCorrelationValue` interface: `{ kind: "factory"; value: string; subParams: Record<string, unknown> }`

### Task 2 — `registry/components.json`

Updated `htc_correlation.options` in all three Channel-family components (`Channel`, `ChannelAndContacts`, `ChannelHeatFlux`) to add `sub_parameters` to the three factory options:

| Factory option | `sub_parameters.length` | Sub-params |
|---|---|---|
| `regime_dependent` | 3 | `htc_forced` (Function), `htc_natural` (Function), `threshold` (Real) |
| `elenbaas_htc` | 4 | `b`, `L`, `Dh`, `g` (all Real) |
| `maximal_htc` | 2 | `htc1`, `htc2` (both Function) |

The `regime_dependent.htc_forced` and `regime_dependent.htc_natural` sub-parameters each carry their own `options` list that includes `elenbaas_htc` with its own nested `sub_parameters` — the schema is recursively consistent.
