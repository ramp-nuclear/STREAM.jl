Gravity wiring topology for vertical loop:
```
Pump -> TempBC -> Channel(g_acc=9.80665) -> Gravity(H=L_ch) -> Pump
                  [upward leg, L_ch tall]    [return leg, H=L_ch]
```
Gravity.inlet = bottom of return leg (connected to Channel.outlet)
Gravity.outlet = top of return leg (connected to Pump.inlet)

Wait — in the return leg the fluid flows DOWN (from Channel outlet at top back to Pump inlet at bottom). The Gravity component convention is inlet=bottom, outlet=top, giving:
  inlet.P - outlet.P ~ rho * g * H   (pressure increases going down)
So for downward flow in the return leg: connect Channel.outlet -> Gravity.inlet is WRONG if inlet=bottom.

The correct wiring depends on the physical layout:
- Channel goes UP: inlet at bottom, outlet at top (fluid rises L_ch)
- Return leg goes DOWN: fluid falls H = L_ch back to pump inlet
- Gravity component: inlet.P - outlet.P ~ rho * g * H
  - This means pressure at inlet > pressure at outlet (inlet is the high-pressure = bottom end)
  - For the return leg (fluid flowing down from channel outlet to pump inlet):
    - Flow direction: channel_out (top) -> pump_in (bottom)
    - inlet connects to channel_out (top of return leg, LOW pressure)
    - outlet connects to pump_in (bottom of return leg, HIGH pressure)
    - But that gives outlet.P > inlet.P, contradicting the equation...

  REREAD the equation: inlet.P - outlet.P ~ rho * g * H
  If flow goes from inlet to outlet (top to bottom), inlet is top (low pressure from friction alone),
  but gravity adds pressure: the fluid GAINS pressure going down, so outlet.P > inlet.P.
  That means inlet.P - outlet.P ~ -rho*g*H (negative), but H>0 means the equation gives a NEGATIVE dP...

  Actually let's think carefully. The Gravity component equation as written:
    inlet.P - outlet.P ~ rho * g * H  (positive H, positive rho, positive g)
  This means inlet.P > outlet.P: inlet has HIGHER pressure than outlet.
  So inlet is the BOTTOM of the component (higher pressure in hydrostatic column).

  For the return leg (fluid flows downward from channel top-outlet to pump bottom-inlet):
    - connect(ch.outlet, grav.outlet)  -- channel outlet (top) = grav outlet (top, low P)
    - connect(grav.inlet, pump.inlet)  -- grav inlet (bottom, high P) = pump inlet

  Alternatively, read Gravity component as: fluid goes IN at bottom (inlet, high P) and exits at top (outlet, low P). That's an upward-flowing component. For a downward return leg, you'd connect it "backwards" or use negative H.

  SIMPLEST APPROACH: Use H with the correct sign to model the return leg. Since the return leg adds pressure (fluid falls back down), place Gravity in the loop with connect in the flow direction, using the equation as-is with positive H to represent the net pressure gain of descending fluid.

  Actually the simplest and most robust approach: just connect Gravity in the flow path as:
    connect(ch.outlet, grav.inlet)
    connect(grav.outlet, pump.inlet)
  Then Gravity's equation: inlet.P - outlet.P ~ rho*g*H
  With H > 0: inlet.P > outlet.P (pressure drops from inlet to outlet).
  If this represents the RETURN LEG going DOWN, the fluid should GAIN pressure going down — so this convention has inlet at the TOP (low static pressure) and outlet at the BOTTOM (high static pressure)? No, that contradicts the equation (it says inlet.P > outlet.P, so inlet has higher pressure = inlet is at the bottom).

  Let the MTK solver sort out signs. The key physical constraint is:
    Channel (upward): adds gravity head loss = rho * g_acc * L (pressure drops going up)
    Return leg (downward): adds gravity head gain = rho * g * H (pressure gains going down)
  For cancellation: H = L_ch, g_acc = 9.80665

  Connect Gravity in flow direction (ch.outlet -> grav.inlet -> pump.inlet). MTK will handle the sign bookkeeping via the port pressure equations. The key is that Channel's g_acc term and Gravity's H term have OPPOSITE effects on the loop's net pressure balance, giving cancellation when H = L_ch.

```julia
@testset "STREAM Phase 6 Tests" begin

# ─────────────────────────────────────────────────────────────────
# GRAV-01: Vertical closed loop assembles, compiles, and solves
# Topology: Pump -> TempBC -> Channel(g_acc=9.80665, L=0.6m) -> Gravity(H=0.6m) -> Pump
# Channel carries g_acc for the upward leg; Gravity carries the return leg.
# ─────────────────────────────────────────────────────────────────
@testset "GRAV-01: vertical loop mtkcompiles" begin
    ssys_v = build_loop_vertical()
    @test ssys_v isa ModelingToolkit.AbstractSystem
end

@testset "GRAV-01: vertical loop solves" begin
    n = 10; T_inlet = 313.15
    ssys_v = build_loop_vertical(T_inlet=T_inlet)
    T_guess = steady_state_guess(T_inlet=T_inlet, Q_wall=1e4, mdot_guess=0.490, n=n)
    op = [ssys_v.ch.T[i] => T_guess[i] for i in 1:n]
    push!(op, ssys_v.ch.inlet.mdot => 0.490)
    sol = solve_steady(ssys_v, op)
    @test sol.retcode == ReturnCode.Success
    @test sol[ssys_v.ch.inlet.mdot] > 0
end

# ─────────────────────────────────────────────────────────────────
# GRAV-02: Gravity cancellation — equal up/down height gives same
# steady-state mass flow as horizontal reference loop (within 1%)
#
# Physics: Channel dP includes +rho*g_acc*L (head loss going up).
# Gravity component adds rho*9.80665*H to the return leg (head gain going down).
# When H == L_ch == 0.6m, the two terms cancel; net gravity effect = 0.
# The cancellation loop should therefore match the horizontal loop's mdot.
# ─────────────────────────────────────────────────────────────────
@testset "GRAV-02: gravity cancellation within 1% of horizontal" begin
    n = 10; T_inlet = 313.15; L_ch = 0.6

    # Horizontal reference (g_acc=0, no Gravity component)
    ssys_h = build_loop(T_inlet=T_inlet)
    T_guess = steady_state_guess(T_inlet=T_inlet, Q_wall=1e4, mdot_guess=0.490, n=n)
    op_h = [ssys_h.ch.T[i] => T_guess[i] for i in 1:n]
    push!(op_h, ssys_h.ch.inlet.mdot => 0.490)
    sol_h = solve_steady(ssys_h, op_h)
    mdot_horiz = abs(sol_h[ssys_h.ch.inlet.mdot])

    # Vertical cancellation loop (g_acc=9.80665, H_return=L_ch)
    ssys_v = build_loop_vertical(T_inlet=T_inlet, L_ch=L_ch, H_return=L_ch)
    op_v = [ssys_v.ch.T[i] => T_guess[i] for i in 1:n]
    push!(op_v, ssys_v.ch.inlet.mdot => 0.490)
    sol_v = solve_steady(ssys_v, op_v)
    mdot_vert = abs(sol_v[ssys_v.ch.inlet.mdot])

    @test isapprox(mdot_vert, mdot_horiz; rtol=0.01)
end

end  # @testset "STREAM Phase 6 Tests"
```

NOTE on GRAV-02 physics: the Channel equation already has `rho_water(T[i_mid]) * g_acc * L` evaluated at the midpoint temperature, and Gravity uses `rho_water(T_in)` evaluated at the inlet temperature. These use slightly different temperatures, so cancellation may not be exact to machine precision. The 1% tolerance accounts for this temperature-dependent density mismatch. If the test fails with >1% discrepancy, investigate whether the density evaluation points need to be reconciled (raise to user if so).
