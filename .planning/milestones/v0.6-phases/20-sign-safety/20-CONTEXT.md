<decisions>
## Implementation Decisions

### Upwinding strategy
- Use `ifelse(inlet.mdot >= 0, T_up_fwd, T_up_rev)` per-cell — same `ifelse()` idiom as `regime_dependent` and the dP formula
- Forward upstream: `T_up_fwd = (i == 1) ? instream(inlet.T) : T[i-1]`
- Reverse upstream: `T_up_rev = (i == n) ? instream(outlet.T) : T[i+1]`
- `instream(outlet.T)` is the correct MTK idiom for the reverse-flow boundary inlet — it returns the temperature entering through outlet from the connected component
- No tanh blend: tanh introduces a tuning parameter and non-physical diffusion near mdot = 0, which is exactly when the loss-of-flow transient (Phase 24) matters most
- No event-based switching: belongs in Phase 23 (Flapper); the Flapper's ContinuousCallback will trigger before mdot = 0 in the full scenario anyway

### Port stream variable fix
- `inlet.T ~ T[1]` — replaces the current wrong equation `inlet.T ~ instream(outlet.T)`
- Meaning: "if fluid exits through inlet (reverse flow), it exits at T[1]"
- `outlet.T ~ T[n]` — unchanged, already correct
- This fix is required in all three channel variants (Channel, ChannelAndContacts, ChannelHeatFlux) and in `_channel_base_eqs`
- Junction temperature mixing is handled automatically by MTK's `connect()` + `instream()` — no Junction component needed. The flow-weighted mixing formula `instream(p.T) = Σ max(-mk,0)·mk.T / Σ max(-mk,0)` is generated by MTK. The `inlet.T ~ T[1]` fix makes B and C contribute the correct T[1] values to that formula under reverse flow.
- Why the current bug was silent: under forward-only flow, `inlet.T` gets zero weight in every `instream()` computation (max(-mdot,0) = 0 when mdot > 0), so the wrong equation never affected results

### T_out convention
- `T_out ~ T[n]` stays as-is — positional alias for the last axial cell temperature
- Does NOT affect port temperature propagation (that is `outlet.T` and `inlet.T`)
- Under reverse flow: T[n] is the reverse-flow inlet (hot end), T[1] is the reverse-flow outlet (cool end); the reversed profile is readable from T[1..n] in order
- No direction-dependent `T_out = ifelse(...)` — keeping positional is cleaner and sufficient for diagnostics

### Velocity observable sign
- `v[i]` stays **signed**: `inlet.mdot / (rho * A)` — user can read flow direction from sign
- `velocity[i]` changed to **unsigned**: `abs(inlet.mdot) / (rho * A)` — speed magnitude, satisfies SIGN-02 "positive and physically meaningful"
- `Re[i]` and `Pe[i]` already use `abs(mdot)` — no change needed
- These are all `@observed` in ChannelAndContacts — purely post-solve diagnostics, zero effect on solver or internal equations
- For Channel and ChannelHeatFlux, `v[i]` is a solver unknown (not @observed) but is not referenced on the RHS of any other equation, so sign convention is equally inconsequential for the solver

### Test structure (SIGN-04)
- New file: `test/test_sign_safety.jl` — per CLAUDE.md layout (new behavior domain → new test file)
- Three `@testset` blocks: one per channel variant (Channel, ChannelAndContacts, ChannelHeatFlux)
- Each testset runs a minimal closed loop with `mdot < 0` (negative pump or negative fixed mdot)
- Assertions per testset:
  1. Reversed temperature profile: `T[1] < T[2] < ... < T[n]` (temperature decreases axially under reverse heating)
  2. All `Re[i] > 0` for all cells
  3. Energy balance: `Q_wall ≈ abs(mdot) * cp_water(T_mean) * abs(T[n] - T[1])` within 1% rtol
- Add `include("test_sign_safety.jl")` to `runtests.jl`

## Specific Ideas

- The `inlet.T ~ instream(outlet.T)` bug was silent in all prior testing because under forward-only flow `inlet.T` gets zero weight in every `instream()` computation — the fix only matters when mdot < 0
- The Flapper (Phase 23) provides a solver restart before mdot reaches zero in the full loss-of-flow scenario, so the Jacobian kink from `ifelse()` at mdot = 0 is not a practical concern for Phase 24
