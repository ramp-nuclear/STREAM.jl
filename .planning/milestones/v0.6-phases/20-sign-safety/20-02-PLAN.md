```julia
const n_sign = 5
const T_inlet_sign = 313.15     # 40 C inlet
const T_wall_sign = 373.15      # 100 C wall
const mdot_neg = -0.490         # negative mass flow (reversed)
const L_sign = 0.6
const D_sign = 0.01
const geom_sign = PipeGeometry_circular(L_sign, D_sign)
```

**Testset 1: "SIGN-01/04: Channel reversed flow"**
- Build loop: `Pump(mdot0=mdot_neg)` -> `HeatExchanger(T_bc=T_inlet_sign)` -> `Channel(n=n_sign, geometry=geom_sign)` -> back to Pump
- Connections: `connect(pump.outlet, bc.inlet)`, `connect(bc.outlet, ch.inlet)`, `connect(ch.outlet, pump.inlet)`, `pump.inlet.P ~ 1.0e5`, `ch.thermal.T ~ T_wall_sign`
- Solve with `solve_steady`, initial guess via `steady_state_guess(T_inlet=T_inlet_sign, Q_wall=1e4, mdot_guess=abs(mdot_neg), n=n_sign)`, operating point includes `ssys.ch.inlet.mdot => mdot_neg`
- Assertions:
  1. `sol.retcode == ReturnCode.Success`
  2. Reversed temperature profile: `T_vals[1] > T_vals[n_sign]` (outlet at cell 1 is hotter than inlet at cell n under reverse flow with T_wall > T_inlet)
  3. Monotone decreasing: `all(T_vals[i] >= T_vals[i+1] for i in 1:n_sign-1)` (temperature decreases from cell 1 to cell n)
  4. All Re positive: `all(Re_vals .> 0)` where `Re_vals = [sol[ssys.ch.Re[i]] for i in 1:n_sign]`
  5. Energy balance: `isapprox(Q_wall_total, Q_advection; rtol=0.01)` where `Q_wall_total = sum(sol[ssys.ch.q_wall[i]] for i in 1:n_sign)` and `Q_advection = abs(mdot_neg) * cp_water(T_mean) * abs(T_vals[1] - T_vals[n_sign])` with `T_mean = (T_vals[1] + T_vals[n_sign]) / 2`

**Testset 2: "SIGN-02/04: ChannelAndContacts reversed flow"**
- Build loop: `Pump(mdot0=mdot_neg)` -> `HeatExchanger(T_bc=T_inlet_sign)` -> `ChannelAndContacts(n=n_sign, geometry=geom_sign)` -> back to Pump
- ChannelAndContacts needs thermal port connections: for each cell i, `cac.thermal_left{i}.T ~ T_wall_sign` and `cac.thermal_right{i}.T ~ T_wall_sign` (use `Symbol(:thermal_left, i)` pattern to reference ports, or use the same wiring pattern as test_channel.jl)
- Solve with `solve_steady`, same initial guess pattern
- Assertions (same as Testset 1 plus):
  1. `sol.retcode == ReturnCode.Success`
  2. Reversed temperature profile: `T_vals[1] > T_vals[n_sign]` and monotone decreasing
  3. All Re positive: `all(Re_vals .> 0)`
  4. All velocity positive: `all(vel_vals .> 0)` where `vel_vals = [sol[ssys.cac.velocity[i]] for i in 1:n_sign]`
  5. Energy balance within 1% rtol

**Testset 3: "SIGN-03/04: ChannelHeatFlux reversed flow"**
- Build loop: `Pump(mdot0=mdot_neg)` -> `HeatExchanger(T_bc=T_inlet_sign)` -> `ChannelHeatFlux(n=n_sign, geometry=geom_sign, T_wall=T_wall_sign)` -> back to Pump
- No thermal port connections needed (T_wall is a constructor parameter)
- Solve with `solve_steady`, same initial guess pattern
- Assertions (same as Testset 1):
  1. `sol.retcode == ReturnCode.Success`
  2. Reversed temperature profile: `T_vals[1] > T_vals[n_sign]` and monotone decreasing
  3. All Re positive: `all(Re_vals .> 0)`
  4. Energy balance within 1% rtol

Note on assertion direction (from RESEARCH.md analysis): Under `mdot < 0` with `T_wall > T_inlet`, physical flow enters at cell n (cold, at ~T_inlet) and exits at cell 1 (hot, heated by wall). Therefore T[1] > T[n] and the profile is monotone decreasing from cell 1 to cell n. The CONTEXT.md notation `T[1] < T[2] < ... < T[n]` was a labeling error — use the physically correct `T[1] > T[n]` direction.

Note on ChannelAndContacts thermal port wiring: Check test_channel.jl or test_composition.jl for the existing pattern for connecting thermal_left/thermal_right ports. The ports are named `thermal_left1`, `thermal_left2`, etc. (not array-indexed). Use `getproperty(cac, Symbol(:thermal_left, i))` or the direct symbolic name in connection equations.
