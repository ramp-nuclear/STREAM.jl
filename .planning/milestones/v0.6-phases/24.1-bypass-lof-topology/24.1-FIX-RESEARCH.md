## Root Cause: Two Bugs in Channel Stream Convention

Extensive MTK diagnostics (test results below) identified two distinct bugs.
Both must be fixed together for the parallel topology + channel inertia to work.

### Bug 1: Wrong Modelica Stream Convention in `port_in.T`

**Location:** `_channel_base_eqs` in `src/components/channel.jl` (also
propagated to `Channel` function in the same file).

**Current (wrong):**
```julia
push!(eqs, port_in.T  ~ instream(port_out.T))
```

**What this does wrong:** In Modelica stream semantics, `port.T` is the
temperature the component *offers* if flow exits through that port. For a
channel, `port_in.T` should be the temperature offered back through port_in
when flow reverses — that is `T[1]` (the first cell, which becomes the outlet
in reverse flow). Instead, the current code sets `port_in.T` to the external
mixing temperature arriving from the other side (`instream(port_out.T)`). This
creates a redundant constraint that MTK cannot resolve at 3-way junctions.

**Fix (correct Modelica stream convention):**
```julia
push!(eqs, port_in.T  ~ T[1])
```

This change applies in TWO places in `src/components/channel.jl`:
1. Inside `_channel_base_eqs` (the shared helper) — look for the port wiring block
2. Inside `Channel` function itself (it has its own port wiring, NOT via `_channel_base_eqs`)

Also applies to the return pipe `Channel` used as `ret` in the bypass topology —
same fix is needed there.

**Proof this is the fix (from MTK diagnostic test):**

With `port_in.T ~ instream(port_out.T)` (wrong):
```
ERROR: ExtraEquationsSystemException: 65 variables, 66 equations
Extra: 0 ~ ret2₊port_out₊mdot(t) + flap2₊port_out₊mdot(t) + ext2₊port_in₊mdot(t)
```

With `port_in.T ~ T[1]` (correct):
```
Full bypass (fixed ch): eq=14 uk=14  ← compiles perfectly
```

**Why this doesn't break series loop tests:** In a 2-port series connection,
`T[1]` and `instream(port_out.T)` converge to the same value at equilibrium
(the upstream component's outlet temperature). The energy equation still uses
`instream(port_in.T)` for the actual inlet temperature in forward flow — that
is unchanged.

### Bug 2: Explicit `ch.port_in.T ~ T_inlet` at 3-Way Junction

**Location:** In `build_loop_lof_bypass` builder function (or wherever the
bypass topology is assembled).

**Current (wrong):**
```julia
ch.port_in.T ~ T_inlet,   # <-- conflicts with stream mixing at 3-way junction
```

**What goes wrong:** At a 3-way junction (Node A: ine.port_out, ch.port_in,
flapper.port_in), MTK generates stream mixing equations for `port_in.T`. Adding
an explicit `ch.port_in.T ~ T_inlet` creates a SECOND equation for the same
variable — over-determination.

**Fix:** Remove the `ch.port_in.T ~ T_inlet` line entirely. Temperature is
reset by the `HeatExchanger` component (which constrains the outflow stream from
port_out, not the junction variable directly). HX sets `hx.port_out.T ~ T_bc`,
which propagates correctly through the stream mixing at Node A.

**Proof:** With `port_in.T ~ T[1]` AND without `ch.port_in.T ~ T_inlet`:
```
Fixed parallel Ch+Res+HX: eq=5 uk=5   ← compiles
Full bypass topology: eq=14 uk=14      ← compiles
```

### Change 1: Fix `_channel_base_eqs` in `src/components/channel.jl`

**Two modifications needed:**

**a) Add `Dt = Differential(t)` at top of `_channel_base_eqs` body** (before the `for i in 1:n` loop). The `t` variable is module-level.

**b) Modify the dP equation** to add inertia term AND fix port_in.T:

Current dP equation (in `_channel_base_eqs`):
```julia
push!(eqs, dP    ~ f_ch * (port_in.mdot * abs(port_in.mdot) /
                            (2 * rho_water(T[i_mid]) * A^2)) * (L / Dh)
                  + rho_water(T[i_mid]) * g_acc * L)
```

New dP equation:
```julia
push!(eqs, dP    ~ f_ch * (port_in.mdot * abs(port_in.mdot) /
                            (2 * rho_water(T[i_mid]) * A^2)) * (L / Dh)
                  + rho_water(T[i_mid]) * g_acc * L
                  + (L / A) * Dt(port_in.mdot))
```

**c) Fix `port_in.T` stream convention** in `_channel_base_eqs` port wiring block:

Current:
```julia
push!(eqs, port_in.T  ~ instream(port_out.T))
```

New:
```julia
push!(eqs, port_in.T  ~ T[1])
```

### Change 4: Rewrite `build_loop_lof_bypass` in `src/examples.jl`

**Replace the entire current `build_loop_lof_bypass` function** with this:

```julia
"""
    build_loop_lof_bypass(; n=10, L_ch=1.0, D_ch=0.01, T_wall=373.15, T_inlet=313.15,
                           L_over_A=1.75e5, g_acc=9.80665, R_ext=1.0e6,
                           threshold=0.01, dt_ramp=5.0) -> ODESystem

Build a loss-of-flow validation loop with bypass topology: real junctions,
parallel paths (heated channel vs Flapper shortcut), and channel momentum inertia.

Topology (4-node parallel network):
- Node A (top): ine output, ch input, flapper input (3-way junction)
- Node B (bottom): ch output, ret input (2-way)
- Node C (top): ret output, flapper output, ext_res input (3-way junction)
- Node D: ext_res output, hx, pump, ine (series)

Gravity signs:
- ch (ChannelHeatFlux, A->B, nominally downward): g = -g_acc (gravity assists downward flow)
- ret (Channel, B->C, nominally upward): g = +g_acc (gravity opposes upward flow)

Physics: Pump coasts to 0 dP. Inertia carries momentum. Channel flow decays.
Flapper opens when pump branch mdot (ine.port_in.mdot) drops to threshold.
After Flapper opens, flow redistributes: channel flow reverses to upward (NC),
buoyancy drives stable negative mdot in ch branch.
"""
function build_loop_lof_bypass(;
    n::Int    = 10,
    L_ch      = 1.0,
    D_ch      = 0.01,
    T_wall    = 373.15,
    T_inlet   = 313.15,
    L_over_A  = 1.75e5,
    g_acc     = 9.80665,
    R_ext     = 1.0e6,
    threshold = 0.01,
    dt_ramp   = 5.0,
)
    geom = PipeGeometry_circular(L_ch, D_ch)

    @named pump    = Pump(0.0)
    @named ine     = Inertia(L_over_A=L_over_A)
    @named hx      = HeatExchanger(T_bc=T_inlet)
    @named ch      = ChannelHeatFlux(n=n, geometry=geom, g=-g_acc, T_wall=T_wall)
    @named ret     = Channel(n=n, geometry=geom, g=g_acc)
    @named flapper = Flapper(threshold=threshold, dt=dt_ramp)
    @named ext_res = Resistor(R=R_ext)

    connections = [
        # D series branch: ext_res -> hx -> pump -> ine
        connect(ext_res.port_out, hx.port_in),
        connect(hx.port_out,      pump.port_in),
        connect(pump.port_out,    ine.port_in),
        # Node A (3-way): ine output -> ch input + flapper input
        connect(ine.port_out, ch.port_in, flapper.port_in),
        # Node B (2-way): ch output -> ret input
        connect(ch.port_out, ret.port_in),
        # Node C (3-way): ret output + flapper output -> ext_res input
        connect(ret.port_out, flapper.port_out, ext_res.port_in),
        # Boundary conditions
        pump.port_in.P   ~ 1.0e5,       # pressure anchor
        ret.thermal.T    ~ T_inlet,     # unheated return pipe wall BC
        flapper.ref_mdot ~ ine.port_in.mdot,  # Flapper monitors pump branch mdot
        # NOTE: do NOT add ch.port_in.T ~ T_inlet here.
        # Temperature at Node A is set by HX's outflow. Adding an explicit
        # ch.port_in.T constraint conflicts with MTK's stream mixing at the
        # 3-way junction and causes over-determination.
    ]

    @named sys = compose(
        System(connections, t; name=:sys),
        pump, ine, hx, ch, ret, flapper, ext_res,
    )

    t_compile = @elapsed ssys = mtkcompile(sys)
    n_eq = length(equations(ssys))
    n_uk = length(unknowns(ssys))
    @info "build_loop_lof_bypass compile time: $(round(t_compile; digits=2))s" n_equations=n_eq n_unknowns=n_uk

    return ssys
end
```

Key notes:
- `mtkcompile(sys)` without `fully_determined=false` — the fix makes it properly determined
- `g=-g_acc` for `ch` (downward, gravity assists), `g=g_acc` for `ret` (upward, gravity opposes)
- NO `ch.port_in.T ~ T_inlet` — this is the Bug 2 fix
- Flapper monitors `ine.port_in.mdot` (pump branch, not channel branch)
