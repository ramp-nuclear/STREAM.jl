**Inserted after:** Phase 27 (pressure-field)

**Milestone:** v0.7 Safety Physics & Pressure Field

---

## Why This Phase Exists

Phase 27-02 shipped per-cell `dp[i]` with friction + gravity only. The executor removed the
inertia term because adding `(dz/A)*Dt(port_in.mdot)` to n algebraic `dp[i]` equations caused
mtkcompile to promote mdot to a free implicit state variable with no determining equation →
all-NaN solutions in ChannelAndContacts (observed_mode).

The correct MTK fix is NOT to omit inertia, but to change the port pressure equation from
algebraic to a **momentum ODE** — the Bernoulli integral momentum equation — which explicitly
determines `Dt(mdot)` and allows `dp[i]` to remain algebraic (friction + gravity), with the
inertia contribution recoverable algebraically in the `P[i]` observed formula.

---

## Python STREAM Reference

Python STREAM's `pressure_diff` (in `stream/physical_models/pressure_drop/__init__.py`):

```python
def pressure_diff(T, Tw, fluid, mdot, pipe, dz, f=..., g=..., mdot2=None) -> Pascal:
    gravity  = rho * g * dz                          # per-cell
    friction = -Darcy_Weisbach(mdot, rho, dz, Dh, A, f)  # per-cell
    inertia  = 0 if mdot2 is None else -inertia_pressure(mdot2, dz, A)  # per-cell
    return friction + gravity + inertia

def inertia_pressure(mdot2, dl, A) -> Pascal:
    return mdot2 * dl / A    # (dz/A) * d(mdot)/dt per cell
```

Each cell contributes `(dz/A)*ṁ̇` to the inertia term. Over n uniform cells:
`sum of inertia = n*(dz/A)*ṁ̇ = (L/A)*ṁ̇`

## Architecture Change

### Current state (Phase 27-02 output — no inertia):
```julia
dp[i] ~ friction[i] + gravity[i]                      # algebraic
port_out.P - port_in.P ~ -sum(dp[i] for i in 1:n)     # algebraic
dP ~ sum(dp[i] for i in 1:n)                           # observed alias = friction+gravity only
P[i] ~ port_in.P - sum(dp[j] for j in 1:i)            # observed, no inertia
```

### Target state (this phase):

**dp[i] — algebraic, unchanged:**
```julia
dp[i] ~ f_i * (mdot*|mdot| / (2*rho*A²)) * (dz/Dh)  +  rho*g*dz
```

**Momentum ODE — replaces the algebraic port pressure equation:**
```julia
(L/A) * Dt(port_in.mdot) ~ (port_in.P - port_out.P) - sum(dp[i] for i in 1:n)
```
`Dt(mdot)` is now explicitly determined. MTK promotes `port_in.mdot` to an ODE state exactly
as it does in the standalone `Inertia` component. At steady state `Dt(mdot)=0`, the ODE
reduces to `port_in.P - port_out.P = sum(dp)` — identical to the old algebraic equation.

**P[i] observed — includes distributed inertia, no Dt() in @observed:**

From the momentum ODE:
```
(L/A)*Dt(mdot) = (P_in - P_out) - sum_all_dp
```
Inertia contribution from inlet to cell i:
```
i*(dz/A)*Dt(mdot) = (i/n) * [(P_in - P_out) - sum_all_dp]
```
Therefore:
```julia
P[i] ~ port_in.P - sum(dp[j] for j in 1:i)
       - (i/n) * ((port_in.P - port_out.P) - sum(dp[j] for j in 1:n))
```
Uses only port connector variables and dp[i] sums — no Dt() in @observed. ✓
At steady state the correction term = 0, same result as Phase 27. ✓
n=1 edge case: P[1] = port_out.P (single cell center = outlet). ✓

**dP observed — total pressure drop including inertia:**
```julia
dP ~ port_in.P - port_out.P
```
Previously `dP ~ sum(dp[i])` = friction+gravity only. Now matches Python STREAM semantics
where `sum(pressure_diff)` includes the mdot2 inertia term.

## Inertia Component Relationship

The standalone `Inertia` component remains unchanged. Its docstring must be updated to clarify:

- **Channel** now carries distributed inertia `(L/A)*Dt(mdot)` — no standalone Inertia needed
  for a single-channel loop
- **Standalone Inertia** is for *concentrated* inertia (fittings, sudden area changes, valves)
- **Channel + standalone Inertia in series**: both momentum ODEs contribute additively through
  MTK network topology — correct physics (distributed + concentrated). No over-constraint.

## MTK Pitfalls to Watch

1. **Do NOT add `Dt(mdot)` to dp[i] equations** — keeps dp[i] algebraic, avoids the original NaN bug
2. **Do NOT use `Dt()` in @observed** — use the algebraic reformulation of Dt(mdot) via port pressures
3. **vars=[] applies**: MTK auto-promotes `port_in.mdot` as ODE state when the momentum ODE is present — no need to list it explicitly in `vars`
4. **observed_mode=true in `_channel_base_eqs`**: the momentum ODE must be added in BOTH branches (observed and non-observed mode), since it's a port wiring equation not a HTC equation
5. **Pressure anchor required** for absolute P[i] values: a pump with `port_in.P ~ 1.0e5` must be present in the loop — this is pre-existing behavior, not new
