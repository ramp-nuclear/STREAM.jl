<objective>
Implement the §3.5 "Reset-to-empty rule" uniformly across the two tabs that
host user-editable numeric property fields: Properties (ParameterForm) and
BCs (BCsTabForm + modeEditors.ValueModeEditor). The Resources tab
(`gui/src/components/resources/ResourceRow.tsx` + `ResourcesTreePanel.tsx`)
has ONLY text-rename inputs — no numeric value editors — so it is out of
scope for this plan (W13 audit). Geometry / PowerShape numeric editors
that share NumericField live in `gui/src/components/sidebar/`
(GeometryResourceEditor.tsx, PowerShapeResourceEditor.tsx, AnchorsSection.tsx,
ModelOptionsPanel.tsx) — these are covered by the NumericField change in
Task 1 automatically because they all import the shared component. Cleared field → registry default applied; "required"
error fires only when there is no usable default. This is user-list item
#4 and is locked by D-14's "spec verbatim" mandate.

Purpose: today, blanking a NumericField on blur produces no error (line
180-183: empty string is just no-op) which means the field flickers between
"empty + nothing happens" and "user thinks the field is broken." The locked
rule says clearing must restore the registry default. This plan delivers
that single, uniform behavior across the sidebar.

Output: a centralized blank-on-blur reset handler used by NumericField,
TypeUnionField.ScalarInput, and the BCsTabForm value-mode scalar input;
matching vitest coverage proving the three-way conditional (default exists
/ required / optional).
</objective>
