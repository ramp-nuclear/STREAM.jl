<objective>
Retrofit the toolbox-drop default naming algorithm from "next-after-highest"
module-level counter (`getNextInstanceName` + `instanceCounters`) to **lowest-free
positive integer suffix** computed from the current store state on every call.
Mirrors the Phase 62 `nextResourceName` precedent (D-19 of `62-CONTEXT.md`).
Deletes the module-level mutable state entirely (D-18).

This plan is the foundation for the clipboard/duplicate naming (Plan 03).
Without it, paste would have to coexist with two contradictory naming
algorithms (lowest-free for resources, next-after-highest for components).

Purpose: per D-17 and D-18 — eliminate hidden-state desync bugs after
undo/redo (counter doesn't decrement) and after loadProject (counter is
per-session, doesn't reset to loaded values); unify with the Phase 62
resource-naming algorithm so paste and toolbox-drop use the same rule.

Output: a pure `nextInstanceName` function exported from `useStore.ts`;
the legacy module-level `instanceCounters` / `getNextInstanceName` /
`clearInstanceCounters` / `reconstructInstanceCounters` identifiers are
physically gone from the source.
</objective>

export function nextResourceName(
