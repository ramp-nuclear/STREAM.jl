<objective>
Reshape the v1.1 registry schema in `gui/src/registry/types.ts` (the TypeScript side) and stamp the new `stream_version`/`schema_version` on `gui/src/registry/components.json`. This plan does NOT rewrite component bodies — Plans 02/03/04 do that. It only establishes the schema vocabulary so the rewrite plans have somewhere to land.

Purpose: The registry is the single source of truth that downstream code (toolbox, property panel, code generator, validator) reads. Until the TypeScript schema admits the new fields, no rewrite plan can compile. D-02 mandates a clean break to schema_version 2.0.

Output: Updated `types.ts` with extended interfaces and a new `ExternalInput` type; `components.json` envelope bumped to `1.1.0` / `2.0` with no body changes yet.
</objective>

       - Add `type_union?: ReadonlyArray<"Real"|"Vector"|"Function"|"ReactivityController"|"Mark"|"Symbol">` (per D-10, D-12).
       - Add `input_modes?: ReadonlyArray<"scalar"|"vector"|"callable"|"controller">` (per D-10, D-12). The two fields appear together — when set, the `type` field is omitted.

    3. Extend the `FunctionOption` interface (per D-06, D-07, D-09):
       - Make `label` optional (some Phase 61 factory entries omit it; rewrite plans will keep it where it exists).
       - Extend `kind` union to add `"stateless"` (per D-07 — `dittus_boelter`, etc.). The legacy `"simple"` stays for backwards compatibility with unrewritten entries.
       - Add `geom_source?: "parent"` (per D-07).
       - Add `produces?: ReadonlyArray<"htc"|"friction">` (per D-09 — `regime_dependent` entries).

    4. Add a NEW interface `ExternalInput` (per D-03, D-05, D-11):

    5. Extend the `ComponentDefinition` interface (per D-03, D-13):
       - Extend `category` union to add `"Sources" | "Resources" | "Reactor Physics"`. Existing `"Hydraulic"` and `"Thermal"` stay.
       - Add `external_inputs?: ReadonlyArray<ExternalInput>` (per D-03 — top-level array per entry; absent on components with no external inputs).
       - Add `resource_kind?: string` (per D-13 — `ReactivityController` carries `"reactivity_controller"`).
       - `constructorModes` becomes OPTIONAL (per D-13: `ReactivityController` as a Resource has no MTK system and no constructor mode; new value-source components may still have constructorModes — leave optional for resilience).
       - `ports` stays required for canvas components; loosen to optional for Resource entries — `ReactivityController` has no ports per D-13.

    6. Do NOT delete `array` and `arrayParam` (legacy) from `Port` — they are still referenced by the existing test in `__tests__/registry.test.ts` and by unrewritten entries. Plan 05 sunsets them.

    7. After editing, `npm --prefix gui run build` (which executes `tsc && vite build`) must exit 0. The 12 existing component entries in components.json must still satisfy the extended schema unchanged (extensions are additive; nothing existing breaks).
