From gui/src/registry/types.ts (D-10):
```typescript
export interface Parameter {
  name: string;
  type?: "Real" | "Int" | "Bool" | "PipeGeometry" | "Function" | "Matrix" | "Vector" | "Symbol";
  type_union?: ReadonlyArray<"Real" | "Vector" | "Function" | "ReactivityController" | "Mark" | "Symbol">;
  input_modes?: ReadonlyArray<"scalar" | "vector" | "callable" | "controller">;
  unit?: string;
  default?: number | string | boolean | null;
  description?: string;
  required: boolean;
  positional: boolean;
  options?: FunctionOption[];
  // ...
}
```

`type` and `type_union` are MUTUALLY EXCLUSIVE. `input_modes` is paired 1:1 with `type_union[]`.

From gui/src/registry/components.json — the three concrete instances this plan must handle:
- WallTemperature.T_wall:  type_union: ["Real","Vector","Function"], input_modes: ["scalar","vector","callable"], unit: "K"
- HeatFluxSource.q:        type_union: ["Real","Vector","Function"], input_modes: ["scalar","vector","callable"], unit: "W/m^2"
- Channel.h_left / h_right: type_union: ["Real","Vector","Function"], input_modes: ["scalar","vector","callable"], unit: "W/(m^2 K)", default: 0.0

Existing field components the new branch reuses:
- `NumericField({ param, value, onChange })` from `./NumericField` — scalar editor (Int/Real); accepts a Parameter with type:"Real" and writes a number.
- `FunctionSelect({ param, value, onChange })` from `./FunctionSelect` — callable picker; expects param.options to be present. For type_union "callable" mode the registry does NOT provide options[] for h_left/T_wall/q, so this plan ships a minimal `CallableSignaturePicker` inline (fn(t) / fn(t,i) segmented + name Input) — same shape as BCsTabForm.tsx's FunctionModeEditor (lines 638-671 of BCsTabForm.tsx).

Storage encoding for the type_union value (must match StreamNode.tsx sourceLabelLine, lines 50-72):
- scalar mode  → number
- vector mode  → JS array (length n; the n value comes from sibling parameters.n — read but do not validate length here, the canvas label is permissive)
- callable mode → string (the function signature, e.g. "fn(t)" or a named function)
- absent       → undefined (renders `(unset)` destructive label per StreamNode.tsx:57-58)

The mode itself is NOT stored separately. The storage shape is the discriminator (typeof value === "number" → scalar, Array.isArray → vector, typeof === "string" → callable). On mount, derive the active mode from the existing value; if undefined, default to the first entry of `input_modes` (typically "scalar").
