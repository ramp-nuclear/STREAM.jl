### 6. promoteToSharedSource default-seed shape (useStore.ts:1361-1369)

Current shape:
```typescript
const consumerN = (consumerData.parameters?.n as number | undefined) ?? 1;
get().updateNodeParams(newNode.id, {
  parameters: { n: consumerN },
});
```

New shape — pre-seed the value parameter when known:
```typescript
const consumerN = (consumerData.parameters?.n as number | undefined) ?? 1;
const SOURCE_DEFAULT_SEED: Record<string, Record<string, number>> = {
  WallTemperature: { T_wall: 300.0 },
  HeatFluxSource: { q: 0.0 },
};
const valueSeed = SOURCE_DEFAULT_SEED[sourceCompId] ?? {};
get().updateNodeParams(newNode.id, {
  parameters: { n: consumerN, ...valueSeed },
});
```

Rationale for the chosen defaults:
- `T_wall = 300.0` (K) — room temperature; a sane neutral starting point that the user will likely overwrite. Picking 0 K would be physically suspicious; picking 600 K (hot fuel) implies an assumption.
- `q = 0.0` (W/m²) — heat-flux zero is the natural "no-source" default and matches `Channel.h_left` / `h_right`'s registry default. The user knows they need to set a positive value.

This is a one-time programmatic seed at spawn — the user can edit immediately via the Properties form (Plan 11). The destructive-red `(unset)` source-block label on freshly-promoted nodes goes away because StreamNode.tsx:57-58 returns `muted: true` only when value is undefined/null/empty-string. 300 is a number → muted: false → muted-gray label.
