## Decisions Made

1. **One BCPort target handle per symmetric pair, on the bottom edge.** Naming alignment with the primary external_input name (`T_wall_left`) lets `addEdge`'s existing CR-01 sibling-derivation flow naturally produce the symmetric mirror. The bottom edge avoids visual collision with the FlowPorts on left/right.

2. **BCPort invariant widened (Rule 3 auto-fix).** Phase 61 enforced "BCPort only on Sources." Plan 12 deliberately broadened this to "Sources (source-side) OR Hydraulic (target-side)." `StreamNode` dispatches at render time via `component.category`. Other categories (Reactor Physics, Resources, etc.) remain forbidden.

3. **Decoy overlay deletion.** With a real BCPort target handle, the whole-body dashed-outline + `"Connect BC"` overlay became a misleading visual hint pointing at a drop target that no longer differs from the actual handle. Deleted. `useConnection` hook usage + `getPortType` import + `isConsumerNode` / `dropActive` locals all became dead code and were removed.

4. **L→R→L+R cycle interaction deleted; chip is read-only.** Project-feedback (2026-05-14): the cycle only updated `edge.data.targetSide` without touching `bcMode`, producing silent state drift. Replaced with a derived label so the BCs tab is the single source of truth for BC state. The chip renders as a static `<span>` with `pointer-events: none`.

5. **Per-baseField edge lifecycle.** Per-side reconciliation (the original `_reconcileEdgesForBCMode`) tied each edge to one `externalInputName` (e.g. `T_wall_left`), but the consumer only has one BCPort handle for the pair. The new `_reconcileBCEdgesForBaseField` derives the desired edge set from the post-mutation bcMode in one pass, anchoring `targetHandle` to the consumer's real ReactFlow handle.

## Deviations from Plan

### Scope expansions (driven by manual smoke feedback)

**Iteration 1 of Task 4 (manual smoke) → "Bug A/B/C"-class findings reported.**
- *Bug A* (L→R cycle is purely cosmetic) and *Bug C* (tag re-render glitch) merged into a single design change: delete the cycle entirely, make the chip read-only.
- *Bug B* (asymmetric promote leaves the sibling unbound) deferred to Plan 13, which already owns the `promoteToSharedSource` work.

**Iteration 2 of Task 4 (manual smoke) → per-baseField edge contract.**
- User repro: symmetric promote → asymmetric → set LEFT to value → edge VANISHED instead of flipping to `R`. Same for asymmetric right-only promote.
- Root cause was that `targetHandle === externalInputName` keying broke when the registry exposes only one BCPort handle per pair. Replaced with per-baseField reconciliation as described above.

Both expansions are auto-fix-class (Rule 3): they address bugs that block RC-2's stated goal of "manual BCPort drag works end-to-end." No goal drift.
