# Phase 63.1 Plan 07: BCs-tab UX rework — Select dropdown + segmented Symmetric/Asymmetric control Summary

Replace the freestanding 5-pill `BCModePicker` with an inline shadcn `Select`
dropdown (D-11) and the custom `SymmetricToggle` switch with a labeled
`SegmentedButtonGroup` showing `Symmetric | Asymmetric` (D-12). Both
controls live entirely inside `BCsTabForm.tsx`; the freestanding
`BCModePicker.tsx` file is physically deleted from the repo, completing
the visual weight rebalance defined by the BCs-tab UX redesign.

## What Was Built

### Task 1 — Inline shadcn Select replaces BCModePicker (commit `de8ac31`)

**`gui/src/components/sidebar/BCsTabForm.tsx`:**

- Removed `import BCModePicker from "./BCModePicker"`. Imports of the
  shadcn `Select` primitives (`Select`, `SelectTrigger`, `SelectValue`,
  `SelectContent`, `SelectItem`) were already present (the file uses
  Select for the source-list dropdown).
- Inside `FieldRow`, replaced the `<BCModePicker .../>` JSX with:
  - A `<Label>` rendering the field's `displayLabel` (preserves the
    pre-existing heading-style label on top of each row).
  - A `<Select value={entry?.mode ?? ""} onValueChange={(m) => onModeChange(m as BCMode)}>`
    with `<SelectTrigger className="w-full">` carrying placeholder
    `Select BC mode...` and 5 `<SelectItem>` children with values
    `value` / `profile` / `function` / `mark` / `source` and labels
    `Value` / `Profile` / `Function` / `Mark` / `Source` verbatim (per
    UI-SPEC §"Mode Dropdown — Options" and the original
    `BC_MODE_OPTIONS` table).
  - Conditional inline destructive hint
    `<p className="text-xs text-destructive/80 mt-[6px]">BC required — select a mode</p>`
    rendered when `entry === undefined` — verbatim copy from the
    legacy `BCModePicker.tsx:51` per UI-SPEC §"Copywriting Contract".
  - Wrapped Select + hint in `<div className="flex flex-col gap-[6px]">`
    so the hint stacks naturally below the trigger.
- Header comment updated: "One inline shadcn Select per visible group
  as the BC mode picker (Phase 63.1 D-11 replaced the legacy 5-pill BC
  mode picker)."

**`gui/src/components/sidebar/BCModePicker.tsx`:** physically deleted.
`git rm` removed it; no remaining consumer in `gui/src`.

**`gui/src/components/sidebar/__tests__/BCModePicker.test.tsx`:**
physically deleted. The test's only subject (`BCModePicker`) is gone.

**`gui/src/components/sidebar/SegmentedButtonGroup.tsx`:** consumer list
in the header comment updated to drop the `BCModePicker` reference (now
just `ModeToggle` + `BCsTabForm sub-pickers`).

**`gui/src/components/sidebar/__tests__/BCsTabForm.test.tsx`:** RED-first
updates to drive the new contract:
- "renders one symmetric toggle + one BC mode dropdown..." now asserts
  `getByRole("button", { name: "Symmetric" })` + `getByRole("button", { name: "Asymmetric" })`
  for the Task 2 SegmentedButtonGroup AND
  `getAllByRole("combobox").length === 1` for the new Select.
- "expands to two stacked BC mode dropdowns..." clicks the
  `Asymmetric` segmented button and asserts `combos.length === 2`.
- New test: "renders the entry's current mode label on the Select
  trigger when entry is set" — verifies the trigger displays `Value`
  when an entry exists and the required-unset hint is suppressed.
- Source-mode-with-existing-sources combobox count bumped from
  `>= 1` to `>= 2` since the BC mode picker is now also a combobox.

### Task 2 — Labeled SegmentedButtonGroup replaces SymmetricToggle (commit `e2e1e6e`)

**`gui/src/components/sidebar/BCsTabForm.tsx`:**

- Deleted the local `SymmetricToggle` function component (and its
  `SymmetricToggleProps` interface) — the entire ~30-line block at the
  former lines 337–369 that rendered the custom `<button role="switch">`
  with the "Symmetric (L = R)" `<Label>`.
- Inside `GroupBlock`, replaced the `<SymmetricToggle .../>` JSX with:
  ```tsx
  <div className="mb-[8px]">
    <SegmentedButtonGroup
      options={[
        { value: "sym", label: "Symmetric" },
        { value: "asym", label: "Asymmetric" },
      ]}
      active={isSymmetric ? "sym" : "asym"}
      onChange={(v) =>
        setBCSymmetric(nodeId, group.baseField, v === "sym")
      }
      size="sm"
    />
  </div>
  ```
- `SegmentedButtonGroup` was already imported in the file (used by the
  Profile-preset and Function-signature pickers); no new import.
- Inline comment above the segmented control documents the copy lock-in
  rule (UI-SPEC §"Copy lock-in") and the boolean-translation contract.

**Store boundary unchanged:** `setBCSymmetric(nodeId, baseField,
boolean)` — the third argument is still a boolean. The string→boolean
translation (`v === "sym"`) is performed at the `onChange` callsite in
the UI, never inside the action. `grep -c "setBCSymmetric"` returns 6
(definitions + call sites), all preserved.
