  <behavior>
    - Closed loop containing one Gravity(H=+10) and one Gravity(H=-10) → net = 0 → no result.
    - Closed loop containing one Gravity(H=+10) and nothing else → net = +10 ≠ 0 → 1 ValidationResult severity 'error' validatorId 'gravity_sum_per_loop' description names the loop participants and the net value '+10.00 m'.
    - Closed loop with no Gravity components → net = 0 → no result.
    - Closed loop with two Gravity components traversed in opposite directions → signed sum must respect direction; e.g. Gravity(H=+10) traversed source→target adds +10, traversed target→source adds -10. The rule MUST use the edge.source / edge.target orientation when summing.
    - Tolerance: |net| < 1e-6 counts as zero (numerical tolerance for user-entered floats).
  </behavior>
  <action>
    Create gravitySumPerLoop.ts exporting `gravitySumPerLoop: Validator` with id 'gravity_sum_per_loop', severity 'error', scope ['nodes', 'edges'].

    Run logic:
      - Call findHydraulicLoops to get the closed loops.
      - For each loop, walk loop.edgeIds in order; for each edge, look up the edge in snapshot.edges and check both endpoints; if either endpoint is a Gravity component, fetch its `H` parameter from node.data.parameters and add it to the running sum (sign determined by traversal direction — see <behavior>).
      - If |sum| >= 1e-6, emit ONE ValidationResult per offending loop.
      - Targets: all Gravity node ids in the loop (kind:'node') + the Gravity `H` field on each (kind:'field', fieldPath:'H') so the property panel highlights H.
      - Stable id: `gravity_sum_per_loop::${sortedLoopNodeIdsJoined}`.

    Test file: behavior block; fixtures construct a 3-node closed loop with two Gravity nodes and verify the signed sum.

    Register in index.ts.

    Pitfall note (in JSDoc): the signed-traversal direction is determined by which side of the edge the Gravity node sits on. Walking a loop edge in source→target order: if the Gravity is on the source side (edge.source === gravityId), add +H; if on the target side, add -H. (Or whichever convention is consistent with the per-channel signed gravity invariant in §4 — the executor SHOULD confirm via a simple two-Gravity test that the net comes out to zero when expected.)
