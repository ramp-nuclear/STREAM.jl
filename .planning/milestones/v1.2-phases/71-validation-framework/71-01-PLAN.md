       **FixAction MUST be defined as exactly this discriminated union (3 kinds; apply closures take a store-handle parameter so RESEARCH §Pitfall 7 is mitigated — closures read fresh state via `get()`, never close over local snapshot copies):**

       ```ts
       import type { StoreApi } from 'zustand';
       import type { AppState } from '../../store/useStore';

       // StoreSetter / StoreGetter mirror zustand's runtime signatures.
       // The apply closures receive these at CLICK time (from
       // useStore.setState / useStore.getState in the ValidationPanel) so the
       // closure never captures a stale snapshot from rule-run time.
       export type StoreSetter = StoreApi<AppState>['setState'];
       export type StoreGetter = StoreApi<AppState>['getState'];

       export type FixAction =
         | {
             kind: 'lossless-sync';
             label: string;                                      // engineering voice, e.g. "Sync n to 10"
             apply: (set: StoreSetter, get: StoreGetter) => void;
           }
         | {
             kind: 'value-transfer-picker';
             leftLabel: string;                                  // e.g. "Use 0.5"
             rightLabel: string;                                 // e.g. "Use 0.6"
             applyLeft:  (set: StoreSetter, get: StoreGetter) => void;
             applyRight: (set: StoreSetter, get: StoreGetter) => void;
           }
         | {
             kind: 'navigation-only';
             label: string;                                      // e.g. "Go to component"
             // No apply closure — clicking maps to the row's existing
             // click-to-focus handler in ValidationPanel (Plan 09).
           };
       ```

       Notes:

         - The `StoreApi<AppState>['setState']` type alias lifts zustand's actual setState signature (partial-merge + replace overloads) — rule files don't need to know the details; they just call `apply(set, get)` and the closure body uses `set({ ... })` and `get()`.
