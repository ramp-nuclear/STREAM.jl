A "simple loop" in STREAM.jl terminology means a closed FlowPort loop: Pump → Channel → HeatDiffusion-coupled channel → Pump. The Python STREAM `build_loop` example (in `src/examples.jl`) is the reference. For the Phase 62 .scp fixture, we want the SIMPLEST realistic project that uses BOTH a Geometry Resource AND at least one PowerShape Resource. Recommended:
- 1 Pump
- 1 ChannelAndContacts (refers geometry_ref to a single Geometry resource `mtr_channel`)
- 1 HeatDiffusion (refers power_shape_ref to a z_cosine PowerShape resource `axial_cos` for the simplest non-trivial form)
- 2 FlowPort edges closing the loop (pump.out -> cac.in; cac.out -> pump.in)
- 2 ThermalPort edges connecting CAC to HD (left + right pairs per Phase 60 fuel_assembly convention)
- model_options.g_default = 9.80665, name = "simple_loop"
- format_version: "2.0"

- mtr_assembly.scp (optional second; planner picks; recommended for verifying the file_loaded codegen path end-to-end). Would need `gui/export_examples/shapes/example_cosine.csv` companion (a small uniform-ones CSV).

The Tauri WebView is needed for in-app file I/O. The smoke test for INV-CG-05 does NOT need the GUI running — it just needs:
1. The .scp JSON valid (verified by `deserializeProject` parsing it without error)
2. The codegen output, generated by feeding the parsed state into `generateCode`, run through bin/jl

We can run that smoke test as a vitest spec that imports `deserializeProject` + `generateCode`, generates Julia code, writes it to a temp file, runs `bin/jl <temp>`, and asserts exit 0 and a success log line. ALTERNATIVELY, the smoke test is a bash script that uses `node -e '...'` to drive deserialize + generate, then runs bin/jl. Either works; pick whichever fits the test infrastructure of this repo.

Simpler choice: the smoke test is a bash script committed at `gui/export_examples/smoke.sh` that uses `node` to invoke a small JS driver. That driver imports projectIO and codeGenerator (both available as TypeScript that vitest's TS pipeline already compiles for tests). The driver: deserialize simple_loop.scp → generateCode → writeFileSync to /tmp/simple_loop_gen.jl → exec `bin/jl /tmp/simple_loop_gen.jl` and check exit status.

Even simpler: just commit a vitest spec at `gui/src/lib/__tests__/codeGenerator.smoke.test.ts` that does the same with `child_process.execSync("bin/jl /tmp/simple_loop_gen.jl")` — vitest spawns from a node process which can execSync. This makes the smoke a normal `npx vitest run` member. Beware: vitest tests typically don't shell out to Julia; this is a non-standard pattern. Acceptable as a Phase 62 verification gate; if it becomes flaky (Julia daemon must be running), the test can be marked `it.skipIf(!daemonReachable, ...)` or moved to a separate `npm run smoke` script.

Decision: keep it as a vitest spec for consistency with the rest of the test surface, marked with a `it.skipIf(!process.env.STREAM_DAEMON || !fs.existsSync(...))` guard so CI without the daemon doesn't fail. Document in the action.
