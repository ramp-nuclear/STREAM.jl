## What ships

### Codegen output shape

For a Channel with `geometry_ref = geo-uuid-1` and an HD with `power_shape_ref = ps-uuid-cos`:

```julia
# =============================================================================
# Generated by STREAM Composer
# =============================================================================
using ModelingToolkit, STREAM
using ModelingToolkit: t_nounits as t

# ---------------------------------------------------------------------------
# Resources
# ---------------------------------------------------------------------------
geom_main = PipeGeometry_rectangular(0.5, 0.01, 0.003)
power_shape_axial_cos_for_hd_1 = cosine_power_shape(10, 5; amplitude=1.0)

@named ch_1 = Channel(; n=5, geometry=geom_main)
@named hd_1 = HeatDiffusion(; nz=10, nx=5, ..., power_shape=power_shape_axial_cos_for_hd_1)

...
```

### Four Power Shape kinds (D-22 + CONTEXT.md Specifics)

| Kind          | Emit form                                                                                        |
| ------------- | ------------------------------------------------------------------------------------------------ |
| `uniform`     | `power_shape_<name>_for_<hd> = ones(nz, nx)`                                                     |
| `z_cosine`    | `power_shape_<name>_for_<hd> = cosine_power_shape(nz, nx; amplitude=<a>)`                        |
| `file_loaded` | `power_shape_<name>_for_<hd> = rebin_extensive(readdlm(joinpath(@__DIR__, "<path>"), ','), (nz, nx))` |
| `unset`       | `power_shape_unset_for_<hd> = ones(nz, nx)  # TODO: fill in your power shape`                    |

`using DelimitedFiles  # for file_loaded power shapes` is emitted conditionally — only when at least one `file_loaded` power shape exists in `resources.powerShapes`.

### Pitfall 4 collision warning (verbatim)

```
# WARNING: Resource name "<name>" collides with component instance name "<other>" — generated code will not compile; rename the Resource.
```

Triggered when a Geometry or PowerShape resource name matches any node's `instanceName` already in the canvas. Emitted as a comment BEFORE the resource's assignment line. Phase 71 owns the full validation framework; for Phase 62 the warning is the entire mitigation.

### Missing-ref warning

```
# WARNING: geometry_ref missing on <instance>
# WARNING: power_shape_ref missing on <instance>
```

Emitted when an `_ref` UUID does not resolve to a record in `resources.geometries` / `resources.powerShapes`. The constructor arg renders as `geometry=missing` / `power_shape=missing` — the resulting Julia compiles to a clean error pointing the user at the missing reference.

## Decisions made

### Per-consumer Power Shape variable naming

CONTEXT.md showed both `power_shape_mtr` (one per Resource) and `power_shape_mtr_for_hd_1` (one per consumer) as candidates. We adopted **always per-consumer** unconditionally:

- **Why:** Two HeatDiffusions with different `(nz, nx)` cannot share a single emitted variable. To support that with a per-Resource emission, the codegen would need to scan-and-decide (any consumer with non-matching dims forces per-consumer; otherwise single emit). Cost is low (a few redundant identical lines when multiple HDs share `(nz, nx)`) and the simpler shape is easier to reason about when debugging generated scripts.
- **Variable name format:** `power_shape_<resource.name>_for_<hd.instanceName>` (or `power_shape_unset_for_<hd.instanceName>` for the sentinel).

### Optional 5th `resources` argument

Plan signature proposed `(nodes, edges, bcs, activeLayer, resources)` — dropping `getComponent`. That's not viable because `detectThermalTopology` calls `getComponent(...)` and the existing 32-case `codeGenerator.test.ts` calls `generateCode(nodes, edges, bcs, mockGetComponent)`. Adopted:

```typescript
export function generateCode(
  nodes: Node[],
  edges: Edge[],
  bcs: BCEntry[],
  getComponent: (id: string) => ComponentDefinition | undefined,
  resources?: CodegenResources,   // Phase 62 new optional arg
): string
```

When `resources` is omitted (legacy 4-arg path), `formatPipeGeometry` is reached via the `resolveRef === undefined` fallback in `formatParamValue`, emitting inline `PipeGeometry_*(...)` from a value-object — the pre-Phase-62 behavior. The 14 new resources-aware tests in `codeGenerator.resources.test.ts` use the 5-arg path. The pre-existing 32 tests in `codeGenerator.test.ts` continue to use the 4-arg path unchanged. **No test cases in the pre-existing file needed modification.**

`activeLayer` was not threaded; the plan-text mentioned it but no acceptance criterion or action body referenced it.
