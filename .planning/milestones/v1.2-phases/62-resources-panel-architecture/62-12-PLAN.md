<objective>
Fix the `ResourceReferencePicker` row layout so `+ New…` (and `Edit…`) are
fully visible at the SidebarPanel's default width (320px) and at the
minimum resize width (200px). Today the row is laid out as
`[Select grows-flex][+ New…][Edit…]` with `gap-[8px]` but no overflow
strategy; at narrow widths the rightmost button is clipped out of the
viewport because the Select's `flex-1` keeps it from shrinking past its
intrinsic content width and the Tooltip wrapper around the disabled
`Edit…` button has no `flex-shrink-0` constraint.

This is the primary creation entry point for resources. With the button
clipped, the user has no in-form path to create a Geometry / Power Shape
from the field — they have to discover the Resources tab tree's `+`
button instead. Verification Step 5 failed because of this.

<current_layout_failure>
Today's `ResourceReferencePicker.tsx` ships:
```
<div className="flex items-center gap-[8px]">
  <div className="flex-1 min-w-0">
    <Select ...>...</Select>
  </div>
  <ResourceCreationButton trigger={<Button variant="outline" size="sm">+ New…</Button>} ... />
  {isEditDisabled ? <Tooltip>...<span tabIndex={0}><Button size="sm" disabled>Edit…</Button></span>...</Tooltip> : <Button size="sm">Edit…</Button>}
</div>
```

`+ New…` and `Edit…` are intrinsic-content-wide (their text + horizontal
padding from `size="sm"` ≈ 70-78px each, plus the gap-8 spacers = ~170px
non-shrinkable on the right). Combined with the minimum Select trigger
width (~80-100px) and the surrounding container padding, the row's
intrinsic width exceeds the available 280-300px inner width on default,
so the Select forces overflow and the rightmost button gets clipped by
the parent's `overflow: hidden` (or simply wrapped off-screen).

The Tooltip's wrapping `<span tabIndex={0} className="inline-flex">`
contains the disabled button but has no `flex-shrink-0`, and the
`+ New…` and `Edit…` buttons themselves lack `shrink-0`. The Select
container is `flex-1 min-w-0` so it CAN shrink, but the buttons winning
the size race is the bug: the Select shrinks too far and the buttons
keep their intrinsic width plus they push past the container edge.
</current_layout_failure>

<chosen_strategy>
Use a **two-row wrap-when-narrow** layout via `flex-wrap` plus a
`basis`/`min-w-0` discipline:

- Outer container: `flex flex-wrap items-center gap-[8px]`
- Select wrapper: `flex-1 min-w-0 basis-full sm:basis-0` — at narrow
  widths the Select takes the full row; at wider widths it sits inline.
- `+ New…` and `Edit…`: stay intrinsic-width; no `flex-1`. They wrap to
  the second visual row when the Select takes `basis-full`. Add
  `shrink-0` defensively so they never get squished into ellipsis.

This satisfies:
- Default (320px sidebar, ~280-300px inner): the picker either fits in
  one row (if buttons + Select min-width < 280) OR wraps onto two rows
  with both buttons fully visible on row 2. Either way, no clipping.
- Min resize (200px sidebar, ~180px inner): always wraps to two rows.
  Visible.

Reject the icon-collapse alternative from VERIFICATION.md Option (b)
because the `+ New…` and `Edit…` labels carry verbatim UI-SPEC copy that
multiple existing tests assert; collapsing to icons would invalidate
those test assertions and require copy-pass changes that belong to
62-15.

Reject Option (c) (bump sidebar default width) because the
panel-resize-overflow-bounds work is explicitly deferred to Phase 72
(`.planning/todos/pending/panel-resize-overflow-bounds.md`). A
preemptive default-width bump would step on that future plan's design
space.
</chosen_strategy>
