<objective>
Add the `fuel_assembly` composition helper to `src/composition/helpers.jl` and
export it from `src/STREAM.jl`. The helper walks the four alternating CAC↔Plate
variants from §3.12 of the v1.2 design contract:

1. Channel-bookended (k plates, k+1 channels) — `bookend=:channel` / inferred
2. Plate-bookended (k+1 plates, k channels) — `bookend=:plate` / inferred
3. Mixed (equal counts, orientation pinned by `start`) — `bookend=:mixed`
4. Closed annular ring (equal counts, wrap around) — `closed=true`

Purpose: closes the gap where reactor fuel assemblies currently require
hand-rolled `connect()` chains. Phase 61's GUI codeGenerator will emit this
helper call after detecting the alternation topology.

Output: a new public function `fuel_assembly` + an updated export line in
`STREAM.jl`. Tests + handoff note are deferred to plan 60-02.
</objective>

    `function fuel_assembly(channels::Vector{<:ModelingToolkit.AbstractSystem}, plates::Vector{<:ModelingToolkit.AbstractSystem}; bookend::Symbol = :auto, start::Union{Symbol,Nothing} = nothing, closed::Bool = false, name::Symbol)`

    Validation order (fail fast, before any `_infer_n` call):
    1. `bookend in (:auto, :channel, :plate, :mixed)` — else `throw(ArgumentError("fuel_assembly: bookend must be :auto, :channel, :plate, or :mixed, got :$bookend"))`. Use `ArgumentError` (NOT plain `error()`), per 60-PATTERNS.md File 1 (b) recommendation — this aligns with D-06 test expectations in plan 60-02. The kwarg-validation idiom shape is borrowed from `one_sided_connection` line 262; only the exception type differs.
    2. `start === nothing || start in (:channel, :plate)` — else `ArgumentError` with message `"fuel_assembly: start must be :channel, :plate, or nothing, got :$start"`.
    3. Length sanity: `length(channels) >= 1` and `length(plates) >= 1` — else `ArgumentError` naming both lengths. (Discretion bullet in D-04 / CONTEXT `<decisions>` last block: this check fires here, after kwarg type validation, to produce the cleanest error.)
    4. Resolve effective bookend:
       - `nc, np = length(channels), length(plates)`
       - inferred bookend: `nc == np + 1 → :channel`; `np == nc + 1 → :plate`; `nc == np → :mixed`; else `ArgumentError("fuel_assembly: cannot infer bookend from lengths channels=$nc, plates=$np — must be equal, or differ by exactly 1")`.
       - If `bookend == :auto`, set effective bookend := inferred.
       - Else (caller passed an explicit non-:auto), if explicit != inferred → `ArgumentError("fuel_assembly: bookend=:$bookend contradicts lengths channels=$nc, plates=$np (would infer :$inferred)")`.
    5. `start` cross-checks (D-03):
       - effective_bookend == :mixed && start === nothing → `ArgumentError("fuel_assembly: bookend=:mixed requires start=:channel or start=:plate")`.
       - effective_bookend != :mixed && start !== nothing → `ArgumentError("fuel_assembly: start=:$start is only valid when bookend=:mixed (got bookend=:$effective_bookend)")`.
    6. `closed` cross-checks (D-04):
       - closed && nc != np → `ArgumentError("fuel_assembly: closed=true requires equal lengths, got channels=$nc, plates=$np")`.
       - closed && effective_bookend != :mixed → `ArgumentError("fuel_assembly: closed=true requires equal lengths (resolved bookend must be :mixed), got effective bookend :$effective_bookend")`. (Equal-length case already resolved to :mixed in step 4, so this is a defense-in-depth check.)
       - If `closed && start === nothing`, default `start = :channel` (D-04 says `start` is "ignored" for a ring; pick `:channel` as the canonical orientation so the wraparound pair has a deterministic direction. Document this in the docstring.).

    Per-cell wiring (D-04 — flat compose, mirror `plate(...)` lines 217–230):
    - `n = _infer_n(channels[1])` — single call, caller responsibility for homogeneity (D-05).
    - Build the alternation as an ordered Vector{Any} `seq` of (kind::Symbol, sys) entries, where `kind ∈ (:c, :p)`:
      - `bookend=:channel`: `c1, p1, c2, p2, …, pk, c_{k+1}` (channels and plates strictly alternate; sequence starts and ends with `:c`).
      - `bookend=:plate`: `p1, c1, p2, c2, …, ck, p_{k+1}` (starts and ends with `:p`).
      - `bookend=:mixed, start=:channel`: `c1, p1, c2, p2, …, ck, pk` (starts `:c`, ends `:p`).
      - `bookend=:mixed, start=:plate`: `p1, c1, p2, c2, …, pk, ck` (starts `:p`, ends `:c`).
    - Walk adjacent pairs `(seq[m], seq[m+1])` for m in 1:length(seq)-1, emitting one thermal-port comprehension per pair, choosing the face-orientation per the established wiring convention from `plate(...)` lines 219–228:
      - `(:c at left, :p at right)` → `connect(port(c, :thermal_right, i), port(p, :thermal_left, i)) for i in 1:n`
      - `(:p at left, :c at right)` → `connect(port(p, :thermal_right, i), port(c, :thermal_left, i)) for i in 1:n`
      This preserves the spatial-absolute L/R convention used throughout `helpers.jl` (avoiding the convention disagreement called out in STATE.md "Blockers/Concerns").
    - When `closed=true`, append one additional wrap pair at the end. With `start=:channel` semantics on a closed loop (CONTEXT `<decisions>` last bullet — Claude's Discretion item): wrap connects `(seq[end], seq[1])` using the same orientation logic as above. Since the equal-length mixed sequence has alternating kinds, `(seq[end].kind, seq[1].kind)` is always one channel + one plate, so the wrap comprehension naturally falls out of the same dispatch.
