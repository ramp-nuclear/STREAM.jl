## Surface Contracts

### Surface 1 — Presets Tab Trigger (4th left-panel tab)

- **Tab value:** `"Presets"`
- **Keybind:** Ctrl+4 (bare Ctrl only; no Shift/Alt/Meta) — mirrors Ctrl+1/2/3 pattern in App.tsx
- **Icon:** `BookMarked` from lucide-react (defaulting: represents a saved/curated collection; planner may substitute `LayoutTemplate` if preferred)
- **Icon size:** `size-5` (20px), same as existing Boxes/Library/Settings2 icons
- **Tab button size:** 32×32px, `rounded-md`, `hover:bg-accent`
- **Active state:** `text-primary`; inactive: `text-muted-foreground hover:text-foreground`
- **Tooltip:** `side="bottom"`, text `"Presets"`
- **Tab strip height:** 40px (h-[40px]) — unchanged from existing layout
- **Depth:** bg-chrome (tab strip strip)
- **Store type extension:** `activeLeftTab` union gains `"Presets"` variant

### Surface 2 — Presets Tab Body

Overall structure: full-height scrollable column, `bg-panel`, `p-2 overflow-y-auto`.

#### Section headers (Project / Library)

- Layout: `flex items-center justify-between gap-1 pl-[8px] pr-[4px] mt-[8px]`
- Label: `text-xs font-semibold uppercase tracking-wide text-muted-foreground`
- Collapse chevron: `ChevronDown` (16px) rotated 0° when expanded, -90° when collapsed; `transition-transform duration-150`; on left of label or right — default right (matches common sidebar patterns)
- Section is collapsible via local component state (`useState(true)` — expanded by default)
- **No** `+` button on section headers (presets are created from the canvas, not from the panel)

#### Entry list

- Container: `space-y-px` (1px gap between rows) inside a `<ul role="list">`
- Entry row: `h-[22px] px-[8px] text-[13px] flex items-center gap-2 cursor-grab select-none min-w-0 overflow-hidden hover:bg-accent rounded-sm`
- Drag handle: `GripVertical` icon from lucide-react, `h-3 w-3 text-muted-foreground shrink-0`, leftmost column; shown always (not just on hover, for discoverability)
- Entry name: `truncate flex-1` — truncated with full name in tooltip (Tooltip on the name span)
- Description: NOT shown inline — shown as Tooltip on hover (`side="right"`, max-width 200px, wraps). If description is empty, no tooltip.
- Context menu: Radix `ContextMenu` wrapping the entry row (`ContextMenuTrigger asChild`)

#### Empty states

| Section | Empty state copy |
|---------|-----------------|
| Project (no project open) | "Open a project to use the Project store." (muted-foreground, text-xs, px-[8px] py-[4px]) |
| Project (project open, no presets) | "No project presets yet." / "Multi-select components and right-click to save." (two-line; first line muted-foreground font-medium, second line muted-foreground text-xs) |
| Library (no presets) | "No library presets yet." / "Save a selection to add your first template." (same two-line pattern) |

Loading/init skeleton: brief skeleton rows while watcher initializes — 2 skeleton `<li>` elements at `h-[22px]` with `bg-muted animate-pulse rounded-sm`.

### Surface 3 — Preset Entry Context Menu

Rendered via Radix `ContextMenuContent` (matches ResourceRow pattern — shadcn `context-menu` component).

| Item | Style | Action |
|------|-------|--------|
| Rename | `ContextMenuItem` (default) | Enters inline rename mode on the entry row |
| Delete | `ContextMenuItem variant="destructive"` | Opens delete-confirmation modal |
| Reveal in Finder/Explorer | `ContextMenuItem` (default) | Tauri shell.open on parent folder |

Menu order: Rename → Delete → (separator) → Reveal in Finder/Explorer.

#### Inline rename

- Replaces the entry name span with a shadcn `Input` component (the project-wide select-on-focus chokepoint wrapper)
- Height: `h-[24px]`, padding: `py-0 px-[6px]`, text: `text-[13px]`, `shadow-none`
- Validation: `[A-Za-z0-9_-]+` live on every keystroke; collision with existing filename in same store blocks commit
- Error state: `border-destructive ring-destructive/30`, error message in `title` attribute (tooltip) — same as ResourceRow pattern
- Commit: Enter or blur
- Cancel: Escape (restores original name, no error shown)
- On commit: rename `.scpr` file AND update `name` field inside JSON (D-09)

### Surface 5 — Save-as-Preset Modal

Uses Radix `Dialog` (same chrome as Phase 67 Settings / About / AutoRecoverRestore).

| Element | Spec |
|---------|------|
| Component | `Dialog` / `DialogContent` |
| Width | Default DialogContent width (matches existing modals — ~400px) |
| Padding | Default DialogContent padding from dialog.tsx |
| Shadow | Default DialogContent shadow from dialog.tsx |

**Field order (top to bottom):**

1. `DialogHeader` with `DialogTitle`: "Save as Preset"

2. **Name field group** (`flex flex-col gap-[8px]`)
   - `Label className="text-[13px] font-semibold leading-[1.4]"` → "Name"
   - `Input` using the project-wide select-on-focus chokepoint wrapper
   - Input `placeholder="e.g. mtr-fuel-assembly"`
   - Validation: `[A-Za-z0-9_-]+` live on keystroke; empty = required error; collision with existing `.scpr` in chosen store = error
   - Error message: `text-destructive text-xs leading-[1.4]` below the Input
   - Reset-to-empty rule (§3.5): empty field is required error (no default name), no auto-default applied
   - Select-on-focus: Input uses the project's shared `<Input>` wrapper which auto-selects on focus (per feedback memory)

3. **Description field group** (`flex flex-col gap-[8px]`)
   - `Label className="text-[13px] font-semibold leading-[1.4]"` → "Description"
   - `Textarea` (shadcn — add if not already installed), `rows={3}`, `placeholder="Optional description shown on hover"`
   - No validation; optional

4. **Store radio group** (`flex flex-col gap-[8px]`)
   - `Label className="text-[13px] font-semibold leading-[1.4]"` → "Store"
   - Two `RadioGroup` items (shadcn `radio-group` — add if not installed):
     - `"Library"` — label "Library (user-global)" — **default selected**
     - `"Project"` — label "Project (this project)" — disabled when no project is open; disabled state: `opacity-50 cursor-not-allowed`
   - When Project is disabled, show muted helper text: `text-xs text-muted-foreground` → "Open a project first."

5. `DialogFooter` (right-aligned, gap-[8px]):
   - `Button variant="ghost"` → "Cancel" (closes dialog, no action)
   - `Button variant="default"` → "Save" (disabled when Name is empty or has validation error)

**Field groups are separated by `gap-[16px]` in a `flex flex-col` container.**

**ESC:** closes dialog (Dialog default via `onOpenChange`)

**On Save success:** close dialog; file-system watcher picks up the new `.scpr` and populates the Presets tab entry list.

**Error toast for old/broken .scpr files:** If a watched file cannot be parsed (bad JSON, unknown format_version, missing `kind: "preset"`), surface a destructive toast: "Could not read preset file: {filename}. File may be corrupt or from an incompatible version." Toast uses the existing toast/notification pattern in the project (planner verifies the toast API used in prior phases).

### Surface 6 — Canvas Right-Click "Save selection as preset…"

Context menu addition to `NodeContextMenu` (rendered via `DropdownMenu` in CanvasPanel).

- Entry: `DropdownMenuItem` → "Save selection as preset…"
- Visibility: rendered only when selection count ≥ 2 (hide entirely when < 2, do not disable)
- Position: above the `DropdownMenuSeparator` / Delete item (group with constructive actions, not destructive)
- On select: opens Save-as-Preset modal (Surface 5)

### Surface 7 — File Menu Additions

Two new `MenubarItem` entries in `FileMenu.tsx`, below the existing separator after "Save As...":

```
Save As...
────────────────────────
Load preset…
Save selection as preset…       [disabled when selection < 2]
────────────────────────
Export to Julia…
```

| Item | Style | Disabled state |
|------|-------|---------------|
| Load preset… | `MenubarItem` | Never disabled |
| Save selection as preset… | `MenubarItem` | `disabled` prop when `selectedNodeCount < 2`; text renders at `opacity-50` (Radix default disabled treatment) |

Shortcut display: none (no keyboard shortcut for these entries — consistent with existing "Export to Julia…" entry which also has no shortcut hint).

### Surface 8 — Drag-from-Presets-Tab

Interaction follows ToolboxItem drag pattern (`draggable` HTML attribute + `onDragStart` setting `dataTransfer`).

- **Drag payload type:** distinct MIME type (e.g. `application/stream-preset`) carrying preset filename + store path — separate from component drag `application/stream-component`
- **Drag image:** generic preset icon overlaid with the preset name — use `DragEvent.dataTransfer.setDragImage` with a small off-screen element (`BookMarked` icon + name text, same styling as ToolboxItem drag). Defaulting to generic icon (not mini-render) per CONTEXT.md Claude's Discretion.
- **Cursor during drag:** `cursor-grabbing` on the row (`:active` override)
- **Drop placement:** bbox-center at cursor position on release (D-16)
- **Canvas drop handler:** reads `application/stream-preset` MIME type; decodes preset, mints new UUIDs, places at cursor, auto-selects all placed components

### Surface 9 — Selection Extension Preview (D-12 auto-extend highlight)

Before the Save-as-Preset modal opens, components pulled in by the BC-edge auto-extend rule (D-12) are highlighted on the canvas:

- **Highlight treatment:** outline on newly-added (extended) components: `2px dashed oklch(0.769 0.188 70.08)` (chart-3 amber-ish tone, distinct from the blue selection ring and the existing dashed BC-edge style) — `outline-offset: 2px`
- Duration: highlight is applied from the moment "Save selection as preset…" is triggered until the Save modal is dismissed (closed or saved). On dismiss, highlights clear.
- **Visual semantics:** user sees (a) their explicit selection in the normal blue selection ring, (b) the auto-extended components in the amber dashed outline; explicit vs. auto-included distinction is clear at a glance.
- **Assumption (A-07):** A short toast or inline status text at the bottom of the modal states how many components were auto-extended: "2 additional component(s) included via BC connections." Omitted if zero auto-extended.

## Interaction Contracts

### Keyboard navigation

| Key | Surface | Action |
|-----|---------|--------|
| Ctrl+4 | Global (window) | Switch left tab to Presets |
| Enter | Inline rename | Commit rename |
| Escape | Inline rename | Cancel rename (restore original name) |
| Escape | Save-as-Preset modal | Close modal, discard |
| Escape | Delete confirmation modal | Close modal, no action |
| F2 | Preset entry row (focused) | Enter inline rename mode |
| Tab / Shift+Tab | Save modal fields | Move between Name → Description → Store radio → Save → Cancel |

### Focus management

- Save modal: focus lands on the Name Input on open (autoFocus or useEffect focus)
- Delete modal: focus lands on Cancel button on open (safe default for destructive dialogs)
- After inline rename commit: focus returns to the renamed row

### Auto-select after load

All components placed via drag-from-preset or File → Load preset… are selected immediately after placement (consistent with Phase 65 clipboard paste auto-select behavior in `clipboard.ts`).

### Smart-name-increment

Component names and embedded resource names are incremented using the existing `clipboard.ts:60` and `useStore.ts:1748` helpers (no new logic). See §3.5 for the exact algorithm.

### Watcher debounce

File-system watcher events are debounced ~200ms before mutating the presets store slice. Coalesces rapid editor-save bursts.

### No back-compat

`.scpr` files that cannot be parsed as v1.0 (format_version: "1.0", kind: "preset") produce a destructive error toast and are ignored. No migration, no fallback. Old files break.
