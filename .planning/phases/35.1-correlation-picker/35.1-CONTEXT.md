# Phase 35.1: Correlation Picker - Context

**Gathered:** 2026-04-02
**Status:** Ready for planning

<domain>
## Phase Boundary

Activate factory correlations in the Channel sidebar. When the user selects `regime_dependent`, `elenbaas_htc`, or `maximal_htc` from the correlation dropdown, reveal nested sub-parameter fields below the parent dropdown. Update the registry schema to carry sub-parameter definitions. Description surfacing via info icon is also introduced in this phase and applied consistently to ALL sidebar fields going forward.

Factory correlation editing was explicitly deferred from Phase 35. Phase 36 code generation consumes the structured store values written here.

</domain>

<decisions>
## Implementation Decisions

### Description Surfacing
- **D-01:** Every field label gets a small ⓘ icon to the right. Hovering shows a shadcn `Tooltip` with `param.description` text. Applied to ALL sidebar field types: NumericField, FunctionSelect, PipeGeometryPicker sub-fields, and new factory sub-fields. Not just Phase 35.1 — retrofit existing components too.
- **D-02:** No secondary text below labels (too much vertical noise in 320px sidebar). Tooltip-on-label-hover rejected (zero discoverability).

### Factory Sub-field Layout
- **D-03:** Sub-fields render inline below the parent dropdown, indented with a left border accent (`border-l-2 pl-3` or equivalent). No expand/collapse animation — they appear immediately when a factory is selected and disappear immediately when switching to a simple closure.
- **D-04:** Sub-fields within the indented block use the same components as regular fields: `FunctionSelect` for Function-type sub-params (sub-dropdowns show simple closures only, never factories), `NumericField` for Real sub-params. On-blur validation applies identically to sub-fields.
- **D-05:** When switching from a factory back to a simple closure, the sub-field values are discarded (not persisted). When switching between two different factories, the previous factory's sub-param values are discarded.

### Store Value Shape
- **D-06:** Simple closures continue to be stored as plain strings: `parameters["htc_correlation"] = "dittus_boelter"`.
- **D-07:** Factory selections stored as structured objects:
  ```ts
  parameters["htc_correlation"] = {
    kind: "factory",
    value: "regime_dependent",
    subParams: {
      htc_forced: "dittus_boelter",
      htc_natural: "elenbaas_htc",
      threshold: 1.0
    }
  }
  ```
  Phase 36 detects factory vs simple with `typeof value === "string"` (simple) vs `value.kind === "factory"` (factory).
- **D-08:** Export a `FactoryCorrelationValue` TypeScript interface from `registry/types.ts`:
  ```ts
  export interface FactoryCorrelationValue {
    kind: "factory";
    value: string;
    subParams: Record<string, unknown>;
  }
  ```

### Registry Schema Extension
- **D-09:** Add `sub_parameters` field to factory-kind `FunctionOption` entries in `components.json`. Each entry uses the same `Parameter` schema already defined. Update `FunctionOption` interface in `types.ts`:
  ```ts
  export interface FunctionOption {
    value: string;
    label: string;
    kind: "simple" | "factory";
    sub_parameters?: Parameter[];  // only present when kind === "factory"
  }
  ```
- **D-10:** Factory sub-parameter definitions to add to `components.json`:
  - `regime_dependent`: `htc_forced` (Function, required, options=simple HTC only), `htc_natural` (Function, required, options=simple HTC only), `threshold` (Real, default=1.0, unit="—", description="Gr/Re² threshold for NC detection")
  - `elenbaas_htc`: `b` (Real, required, unit="m", description="Channel gap width"), `L` (Real, required, unit="m", description="Channel length"), `Dh` (Real, required, unit="m", description="Hydraulic diameter"), `g` (Real, default=9.80665, unit="m/s^2", description="Gravitational acceleration")
  - `maximal_htc`: `htc1` (Function, required, options=simple HTC only), `htc2` (Function, required, options=simple HTC only)

### Recursion Cap
- **D-11 (revised 2026-04-02):** Sub-dropdowns for `htc_forced`, `htc_natural`, `htc1`, `htc2` list simple closures (`dittus_boelter`, `constant_Nusselt`) AND `elenbaas_htc` (factory with Real sub-params only). They do NOT list `regime_dependent` or `maximal_htc` (recursive factories). This matches ROADMAP SC-5 example: `htc_natural=elenbaas_htc(b=0.003, L=0.6, Dh=0.0025)`. Enforced by the registry: options arrays include `elenbaas_htc` with `kind: "factory"` + its 4 Real `sub_parameters`.

### Simple Closures (unchanged from Phase 35)
- **D-12:** `dittus_boelter`, `constant_Nusselt` (HTC) and `blasius_friction`, `laminar_friction` (friction) remain simple — no sub-fields. `constant_Nusselt` always uses its default Nu=8.235 from the GUI.
- **D-13:** `marco_han_nusselt` is NOT in STREAM.jl exports — do not add to picker.

### Claude's Discretion
- Exact Tailwind classes for the left-border indented sub-field container
- Whether the ⓘ icon uses a lucide-react icon or shadcn's built-in
- Default value pre-population for factory sub-fields (use registry `default` if present, otherwise leave empty/blank)

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `FunctionSelect.tsx`: Already renders factory options as `disabled` with tooltip. Phase 35.1 removes the `disabled` branch and replaces it with conditional sub-field rendering below the `<Select>`. The sub-field container is a new JSX block, not a separate component.
- `NumericField.tsx`: Reused as-is for Real sub-params (b, L, Dh, g, threshold). Needs ⓘ icon addition.
- shadcn `Tooltip` + `TooltipProvider`: Already imported in `FunctionSelect.tsx` — reuse for ⓘ icon tooltip across all field components.
- `validateReal`: Already in `@/lib/validation` — sub-field Real params use the same validator.

### Established Patterns
- On-blur validation (D-06 from Phase 35): all fields validate on `onBlur`, not `onChange`. Sub-fields follow the same rule.
- Registry-driven rendering: `param.options` drives dropdown content. Sub-params read from `option.sub_parameters` — same pattern, one level deeper.
- `gap-[16px]` between fields, `gap-[8px]` within a field (label + input + error). Sub-field container uses the same spacing.
- Zustand update pattern: `updateNodeParams(nodeId, { parameters: { ...current, [name]: newValue } })`.

### Integration Points
- `FunctionSelect.onChange` currently calls `(v: string) => onParamChange(param.name, v)`. When factory selected, it must instead call `onParamChange(param.name, { kind: "factory", value: v, subParams: {} })` — sub-param changes update the nested `subParams` object.
- Phase 36 code gen reads `parameters["htc_correlation"]`: if string → emit bare identifier; if `kind === "factory"` → emit `value(subParams as kwargs)`.
- ⓘ icon addition: `NumericField`, `FunctionSelect`, `PipeGeometryPicker` all follow the same `<Label>{param.name} <ⓘ tooltip></Label>` pattern. Consistent across all field types.

</code_context>

<specifics>
## Specific Ideas

- ⓘ icon: small `lucide-react` `Info` icon (h-3 w-3) inline after the label text, wrapped in shadcn `<Tooltip>`. The icon is `text-muted-foreground` and non-interactive except for tooltip trigger.
- Sub-field container: `<div className="border-l-2 border-muted pl-3 mt-2 flex flex-col gap-[12px]">` — left border accent visually connects sub-fields to parent dropdown.
- When a factory is selected: parent `FunctionSelect` renders the indented block as a sibling `<div>` below the `<Select>` component (not inside it).
- Sub-dropdown for htc_forced/htc_natural/htc1/htc2: reuse `FunctionSelect` with a trimmed `options` array (simple only) derived from `sub_param.options` in the registry.

</specifics>
