# Plan 1: Types and Registry Schema

**Phase:** 35.1
**Goal:** Extend TypeScript interfaces and `components.json` so the full factory correlation schema (including sub-parameters) is in the registry and type-safe.
**Depends on:** None

## Context

`registry/types.ts` currently defines `FunctionOption` without `sub_parameters`. `components.json` already has factory options (`regime_dependent`, `elenbaas_htc`, `maximal_htc`) with `"kind": "factory"`, but NO `sub_parameters` arrays. This plan adds the missing interfaces and data; all downstream UI plans depend on this.

Three components share identical `htc_correlation` option structure: `Channel` (lines 46–52), `ChannelAndContacts` (lines 118–122), `ChannelHeatFlux` (lines 204–208). All three must receive `sub_parameters` — 9 blocks total (3 factories × 3 components). RESEARCH.md §"Repetition concern" acknowledges this: it is an intentional copy, not a bug.

## Tasks

### Task 1: Extend `registry/types.ts` — add `FactoryCorrelationValue` and update `FunctionOption`

**File:** `gui/src/registry/types.ts`
**Lines:** 11–15 (current `FunctionOption`) and after line 15 (new `FactoryCorrelationValue`)

Add `sub_parameters?: Parameter[]` field to `FunctionOption` (per D-09). Add new exported `FactoryCorrelationValue` interface (per D-08).

The complete updated `types.ts` interfaces section:

```typescript
// After existing FunctionOption (lines 11-15), replace with:
export interface FunctionOption {
  value: string;
  label: string;
  kind: "simple" | "factory";
  sub_parameters?: Parameter[];  // only present when kind === "factory"; per D-09
}

// New interface per D-08 — add after FunctionOption:
export interface FactoryCorrelationValue {
  kind: "factory";
  value: string;
  subParams: Record<string, unknown>;
}
```

No other interfaces in `types.ts` change. The `Parameter` interface (lines 17–26) already has `options?: FunctionOption[]` which now transitively supports sub-options through the `FunctionOption.sub_parameters` field.
