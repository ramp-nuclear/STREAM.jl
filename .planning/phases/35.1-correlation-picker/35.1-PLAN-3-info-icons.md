# Plan 3: Info Icons — Retrofit All Sidebar Field Labels

**Phase:** 35.1
**Goal:** Add the ⓘ info icon + shadcn Tooltip to every field label across all sidebar components: `NumericField`, `PipeGeometryPicker`, and `InstanceNameField`.
**Depends on:** Plan 2 (`FunctionSelect` already gets its icon in Plan 2)

## Context

D-01: Every field label gets a small `lucide-react` `Info` icon (h-3 w-3, text-muted-foreground) to the right. Hovering shows a shadcn `Tooltip` with `param.description`. Applied to ALL sidebar field types — `FunctionSelect` already done in Plan 2, three remaining components need retrofitting.

RESEARCH.md documents the exact current label JSX for each:
- `NumericField.tsx` lines 33–35: plain `<Label>{param.name}</Label>`
- `PipeGeometryPicker.tsx` `DimensionField` lines 47–49: plain `<Label>{label}</Label>` with no description
- `InstanceNameField.tsx`: NO label element at all

The `Info` icon + `TooltipProvider`/`Tooltip` pattern is already established in Plan 2's `FunctionSelect`. Implement it identically here.

`PipeGeometryPicker` uses an internal `DimensionField` sub-component that takes a plain `label: string`. Since these sub-fields have no registry `Parameter`, descriptions must be added as static strings in the `circularFields`/`rectangularFields` arrays. The sub-fields are `L`, `D`, `W`, `H`.

`InstanceNameField` has no `param` object. Add a `<Label>` element above the `<Input>` with hardcoded description text: `"Julia variable name for this component in generated code"`.

### Task 3: Add label + info icon to `InstanceNameField.tsx`

Update the returned JSX block. The current return (lines 28–40) is a bare `<div>` with just `<Input>` and error. Add a `<Label>` above with the ⓘ icon:
```tsx
return (
  <div className="flex flex-col gap-[8px]">
    <Label className="text-[13px] font-semibold leading-[1.4] flex items-center gap-1">
      Name
      <TooltipProvider>
        <Tooltip>
          <TooltipTrigger asChild>
            <Info className="h-3 w-3 text-muted-foreground cursor-default" />
          </TooltipTrigger>
          <TooltipContent>
            Julia variable name for this component in generated code
          </TooltipContent>
        </Tooltip>
      </TooltipProvider>
    </Label>
    <Input
      value={localValue}
      onChange={(e) => setLocalValue(e.target.value)}
      onBlur={handleBlur}

    />

      <p className="text-destructive text-xs">{error}</p>
    )}
  </div>
);
```

Note: `InstanceNameField` has no registry `param` — the description is hardcoded (RESEARCH.md §"InstanceNameField has no description metadata"). The `TooltipProvider` is placed unconditionally (no `description &&` guard needed since it is always a known string).
