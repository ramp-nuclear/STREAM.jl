## Spacing Scale

Source: existing codebase uses 8-point Tailwind scale throughout (confirmed in Toolbar.tsx, App.tsx). No deviation for Phase 67.

| Token | Value | Usage in Phase 67 |
|-------|-------|-------------------|
| xs | 4px (`gap-1`, `px-1`) | Icon gap within menu triggers |
| sm | 8px (`gap-2`, `px-2`) | Titlebar horizontal padding, button spacing in strips, macOS window control circle gap |
| md | 16px (`px-4`) | Menu content inner padding |
| lg | 24px | Not used in this phase (no section-level spacing) |
| xl | 32px | Secondary strip height (`h-8`) |
| 2xl | — | Not used in this phase |
| 3xl | — | Not used in this phase |

### Inherited Exceptions

The following values deviate from the 4-multiple rule. They are **carryovers from the existing `Toolbar.tsx` contract** — not new choices introduced in Phase 67. The executor MUST NOT change them; doing so would alter the existing visual contract and risk layout regressions.

| Value | Pixel size | Why it is here | Executor instruction |
|-------|-----------|----------------|----------------------|
| `h-9` | 36px | Matches the current `Toolbar.tsx` height exactly (established pre-Phase 67) | Keep as-is. Do not change to `h-8` (32px) or `h-10` (40px). |

All other spacing values introduced in Phase 67 are on the 4-multiple scale. Specifically, macOS window control circles use `gap-2` (8px) — not `gap-1.5` (6px). 8px spacing between 12px circles produces appropriate visual separation consistent with the traffic-light convention.

## Layout Contract

### Visual Hierarchy

The drag region (center, `flex-1`) is the dominant visual void in the titlebar. Its empty expanse frames the menus on the left and the window controls on the right — this is intentional, not dead space. The executor must ensure the drag region truly expands to fill all remaining horizontal space (`flex-1 h-full`) so that the left and right clusters read as anchored edges against a wide, grabbable center.

### Strip 1 — CustomTitlebar (36px / `h-9`)

Full-width, `bg-muted border-b`, positioned as the first child of the root `<div className="flex flex-col h-screen w-screen overflow-hidden">` — OUTSIDE the `<div className="flex flex-1 min-h-0">` row.

Left-to-right layout (`flex items-center`):

| Slot | Content | Classes / Notes |
|------|---------|----------------|
| App icon | `<img>` referencing `icons/32x32.png` at 20px | `w-5 h-5 ml-2 shrink-0` |
| Project name | `basename(currentFilePath)` without extension; `"Untitled"` if dirty+unsaved; empty if clean+unsaved | `text-xs text-muted-foreground ml-1 select-none truncate max-w-[120px]` |
| Dirty dot | Literal `●` character when `isDirty === true` | `text-xs text-muted-foreground ml-0.5 select-none` |
| File menu | `<FileMenu>` (existing component, relocated) | existing pattern |
| Edit menu | New `<DropdownMenu>` with items per D-10 | see Menu Content section |
| View menu | New `<DropdownMenu>` with submenu per D-11 | see Menu Content section |
| Help menu | New `<DropdownMenu>` with items per D-12 | see Menu Content section |
| Drag region | `<div data-tauri-drag-region className="flex-1 h-full" onDoubleClick={toggleMaximize}>` | Must fill all remaining center space |
| Window controls | `<WindowControls>` component | Always right-side (D-13) |

### Strip 2 — SecondaryToolbar (32px / `h-8`)

Full-width, `bg-muted border-b`, immediately below CustomTitlebar in the root `flex flex-col` — also OUTSIDE the `flex flex-1 min-h-0` panel row.

Left-to-right layout:

| Slot | Content | Source |
|------|---------|--------|
| Layer toggle | Existing `<ToggleGroup>` from Toolbar.tsx (Hydraulic/Both/Thermal) | Moved from Toolbar.tsx center section |
| Code preview toggle | Existing `<Button>` (Code2 icon + "Code" label) from Toolbar.tsx | Moved from Toolbar.tsx left section |
| Export button | Existing `<Button>` (Download icon + "Export" label) from Toolbar.tsx | Moved from Toolbar.tsx right section |

ThemeMenu is removed from the secondary strip (per D-03) — theme moves to View menu.

### Window Controls component

| Platform | Visual style |
|----------|-------------|
| macOS | Three filled circles `w-3 h-3 rounded-full` with `gap-2` (8px) between them; at rest: `bg-[#ff5f57]/40`, `bg-[#ffbd2e]/40`, `bg-[#28c840]/40` (dimmed); on group hover: full opacity colors; no icons |
| Windows / Linux | Three icon buttons using Lucide `Minus`, `Maximize2`, `X`; `variant="ghost" size="icon"`; Close hover: `bg-destructive text-destructive-foreground`; Min/Max hover: `hover:bg-muted-foreground/20` |

Platform detection: call `platform()` from `@tauri-apps/plugin-os` once on mount, store in component state (`useState<"macos" | "windows" | "linux" | null>`). `@tauri-apps/plugin-os` is NOT currently in `package.json` — planner must add it.

## Interaction Contract

### Drag region

| Interaction | Behavior |
|------------|---------|
| Click-and-drag on `data-tauri-drag-region` area | Moves the OS window (handled by Tauri natively via the attribute) |
| Double-click on `data-tauri-drag-region` area | Calls `getCurrentWindow().toggleMaximize()` |
| Right-click on `data-tauri-drag-region` area | No action (do not add a context menu to the drag region) |

### Menu triggers

| Interaction | Behavior |
|------------|---------|
| Click on menu trigger | Opens DropdownMenu |
| Click outside open menu | Closes menu (Radix default) |
| Escape key inside open menu | Closes menu (Radix default) |

The drag region must be a sibling of the menu triggers — it must not wrap them. Menu trigger events must not bubble to the drag region.

### Window controls (all platforms)

| Button | Click action |
|--------|-------------|
| Minimize | `getCurrentWindow().minimize()` |
| Maximize / Restore | `getCurrentWindow().toggleMaximize()` |
| Close | `getCurrentWindow().close()` — Tauri close-requested guard in App.tsx handles unsaved-changes dialog |

### App.tsx layout integration

The new structure for the `return` block (after AutoRecover gate):

```
<div className="flex flex-col h-screen w-screen overflow-hidden">
  <CustomTitlebar ...props />       {/* NEW — 36px, full-width */}
  <SecondaryToolbar ...props />     {/* NEW/REFACTORED — 32px, full-width */}
  <div className="flex flex-1 min-h-0">
    {/* left panel, canvas, right panel — unchanged */}
  </div>
  <BottomPanel />
</div>
```

The existing `<Toolbar>` inside `<div className="flex flex-col flex-1 min-w-0">` is removed. `SecondaryToolbar` is NOT scoped to the center column.

## Platform-Specific Notes

### `@tauri-apps/plugin-os` — not yet in package.json

The planner must include a task to install this plugin:
```
npm install @tauri-apps/plugin-os
```
And add it to `src-tauri/Cargo.toml` and the Tauri plugin list in `tauri.conf.json` if required by the v2 plugin system. The executor must verify the plugin is registered before implementing `WindowControls.tsx`.

### `decorations: false` — tauri.conf.json

Add to `app.windows[0]`:
```json
"decorations": false
```

This removes the OS chrome entirely. On Linux/WSL, this eliminates the GTK decorations. On macOS, it removes the traffic-light buttons and title bar. On Windows, it removes the native title bar. Phase 67 supplies replacements for all three platforms.
