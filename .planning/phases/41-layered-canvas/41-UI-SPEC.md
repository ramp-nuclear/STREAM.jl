### Layer Toggle Active State Colors

The layer toggle uses category accent colors to reinforce which layer is active:

| Toggle State | Active Background | Active Text |
|-------------|-------------------|-------------|
| Hydraulic | `bg-blue-500/15` | `text-blue-700` |
| Both | `var(--accent)` (neutral, shadcn default) | `var(--accent-foreground)` |
| Thermal | `bg-amber-500/15` | `text-amber-700` |

Inactive toggle items use shadcn ToggleGroup default (transparent background, `text-muted-foreground`).

### Dimming Treatment

| Element | Active Layer Style | Dimmed Style |
|---------|-------------------|--------------|
| Node card | `opacity: 1` | `opacity: 0.2`, `pointer-events: none` |
| Node handles (all) | `opacity: 1` | `opacity: 0.2`, `pointer-events: none` |
| Edge | `opacity: 1` | `opacity: 0.15` |
| Dual-layer node (ChannelAndContacts) in single-layer view | `opacity: 1` | Never fully dimmed -- always `opacity: 1` |
| Dual-layer node: off-layer handles | N/A | `opacity: 0.2`, `pointer-events: none` |

Dimming values:
- **Nodes: opacity 0.2** -- low enough to clearly indicate non-interactivity, high enough to preserve spatial context
- **Edges: opacity 0.15** -- slightly lower than nodes because edges are thinner and need more contrast reduction to feel subordinated
- **Transition: 150ms ease** -- CSS `transition: opacity 150ms ease` on nodes and edges for smooth layer switching

Accent reserved for: canvas node left-border stripe, toolbox category indicator, layer toggle active state background (as listed above).

## Layer Toggle Component Spec

### Placement

In `Toolbar.tsx`, add a centered `<div>` between the left section (FileMenu + Code) and the right section (Export). The toolbar uses `justify-between` on its outer flex container; the layer toggle occupies a new middle section.

```
[FileMenu] [file.jl *] [Code]    [Layer: [Hydraulic] [Both] [Thermal]]    [Export]
  ^-- left section                    ^-- center section                    ^-- right section
```

### Markup

Use shadcn `ToggleGroup` with `type="single"` and `variant="outline"`:

```
<div className="flex items-center gap-1.5">
  <Layers className="h-3.5 w-3.5 text-muted-foreground" />
  <span className="text-xs font-semibold text-muted-foreground select-none">Layer</span>
  <ToggleGroup type="single" value={activeLayer} onValueChange={...}>
    <ToggleGroupItem value="Hydraulic" ...>Hydraulic</ToggleGroupItem>
    <ToggleGroupItem value="Both" ...>Both</ToggleGroupItem>
    <ToggleGroupItem value="Thermal" ...>Thermal</ToggleGroupItem>
  </ToggleGroup>
</div>
```

### Visual Treatment (D-10: must be prominent)

1. **Layers icon** (from lucide-react) at 14px before the label -- signals "this controls visibility/layers"
2. **"Layer" label** in 12px semibold muted text -- immediately identifies purpose
3. **Active item** gets category-tinted background:
   - Hydraulic active: `bg-blue-500/15 text-blue-700 border-blue-300`
   - Both active: default shadcn active state (`data-[state=on]:bg-accent`)
   - Thermal active: `bg-amber-500/15 text-amber-700 border-amber-300`
4. **ToggleGroupItem size**: `size="sm"` (height 32px, padding 8px 12px, text 14px)
5. The toggle group has a `border rounded-md` outline wrapper to visually group the three items as a single segmented control

### Keyboard: Tab Cycling (D-11)

- `Tab` key cycles layers: Hydraulic -> Both -> Thermal -> Hydraulic
- Only intercepts when the `CanvasPanel` container div has focus (or a child that is not an input/textarea/select)
- Implementation: `onKeyDown` handler on CanvasPanel container `div` (which already has `tabIndex={0}`)
- Guard: `if (e.target instanceof HTMLInputElement || e.target instanceof HTMLTextAreaElement || e.target instanceof HTMLSelectElement) return;`
- Action: `e.preventDefault(); e.stopPropagation(); store.cycleLayer();`
- `cycleLayer()` store action: rotates `Hydraulic -> Both -> Thermal -> Hydraulic`

## Toolbox Filtering Spec (D-04, D-05)

### Filter Logic

```typescript
function isComponentVisibleInLayer(comp: ComponentDefinition, activeLayer: string): boolean {
  if (activeLayer === "Both") return true;
  const hasFlow = comp.ports.some(p => p.type === "FlowPort");
  const hasThermal = comp.ports.some(p => p.type === "ThermalPort");
  if (activeLayer === "Hydraulic") return hasFlow;
  if (activeLayer === "Thermal") return hasThermal;
  return true;
}
```

- ChannelAndContacts has both FlowPort and ThermalPort -> visible in all three views
- ChannelHeatFlux has only FlowPort (T_wall is a parameter) -> visible in Hydraulic and Both
- HeatDiffusion and ConstantTemperature have only ThermalPort -> visible in Thermal and Both
- All other components (Pump, Channel, etc.) have only FlowPort -> visible in Hydraulic and Both

### Category Headers

When filtering hides all components in a category, the category heading is also hidden. In Hydraulic view, the "Thermal" category heading disappears (HeatDiffusion and ConstantTemperature are hidden). In Thermal view, the "Hydraulic" heading disappears for pure-hydraulic components. ChannelAndContacts appears under whichever category heading it belongs to in the registry ("Thermal" category per existing registry).

## Node Dimming Spec (D-01, D-02, D-03)

### Determining Dim State

For each node on the canvas:

```typescript
function isNodeDimmed(node: Node, activeLayer: string, getComp: Function): boolean {
  if (activeLayer === "Both") return false;
  const comp = getComp(node.data.componentId);
  const hasFlow = comp.ports.some(p => p.type === "FlowPort");
  const hasThermal = comp.ports.some(p => p.type === "ThermalPort");
  const isDualLayer = hasFlow && hasThermal;
  if (isDualLayer) return false; // Never fully dimmed
  if (activeLayer === "Hydraulic") return !hasFlow;
  if (activeLayer === "Thermal") return !hasThermal;
  return false;
}
```

### Applying Dim State

Option A (recommended): Set `node.style = { opacity: 0.2, pointerEvents: "none", transition: "opacity 150ms ease" }` in a derived selector or before passing nodes to ReactFlow. This keeps StreamNode.tsx unchanged.

Option B: Pass `data.dimmed` boolean and apply className in StreamNode. Less preferred because it requires StreamNode changes AND style overrides.

### Edge Dimming

For each edge, determine if it should be dimmed based on the ports it connects:

```typescript
function isEdgeDimmed(edge: Edge, nodes: Node[], activeLayer: string): boolean {
  if (activeLayer === "Both") return false;
  // Thermal edges (amber dashed) are dimmed in Hydraulic view
  // Flow edges are dimmed in Thermal view
  const isThermalEdge = edge.data?.edgeType === "thermal";
  if (activeLayer === "Hydraulic") return isThermalEdge;
  if (activeLayer === "Thermal") return !isThermalEdge;
  return false;
}
```

Edge dimming: `style={{ opacity: 0.15, transition: "opacity 150ms ease" }}`.

### Handle Dimming for Dual-Layer Nodes (D-08)

In Thermal view, ChannelAndContacts is fully visible but its FlowPort handles (port_in, port_out) are dimmed and non-interactive. In Hydraulic view, its ThermalPort handles (thermal_left[], thermal_right[]) are dimmed and non-interactive.

Implementation: StreamNode handle rendering checks `activeLayer` from store. If the handle's port type does not match the active layer view, apply `opacity: 0.2; pointer-events: none` to that handle element. In Both view, all handles are active.

## Persistence Spec (D-12)

### StreamProject Schema v2

```typescript
interface StreamProject {
  version: 2;
  nodes: SerializedNode[];
  edges: SerializedEdge[];
  bcs: BoundaryCondition[];
  activeLayer: "Hydraulic" | "Both" | "Thermal";
}
```

### Backwards Compatibility

```typescript
function deserializeProject(json: string): StreamProject {
  const parsed = JSON.parse(json);
  if (parsed.version === 1) {
    return { ...parsed, version: 2, activeLayer: "Both" };
  }
  return parsed;
}
```

`serializeProject` always writes `version: 2` with `activeLayer` included.
