    **Patch C — keydown handler branch.** Inside the existing `handleKeyDown` block (~line 203), AFTER the `Ctrl+` (backtick) branch and BEFORE the `} catch (err)` clause (so this lives inside the try block), insert the Ctrl+P branch. The structure is exact and the line ordering is load-bearing for Pitfall 1:

    1. Line 1: `if ((e.ctrlKey || e.metaKey) && e.key === "p" && !e.shiftKey) {`
    2. Line 2: `  e.preventDefault();` — MUST be the FIRST statement inside the branch. No state read, no logging, no input-focus check precedes it. This synchronous placement is what defeats the OS/browser Print dialog (Pitfall 1).
    3. Line 3: input-focus guard — if `e.target` is an HTMLInputElement / HTMLTextAreaElement / HTMLSelectElement / contentEditable, `return;` (preventDefault already swallowed the print shortcut; the guard only skips the palette toggle).
    4. Line 4: `setPaletteOpen((v) => !v);`
    5. Line 5: `return;`

    The grep gate in `<verify>` enforces this layout: `grep -A3 'e.key === "p"' gui/src/App.tsx | grep -q 'e.preventDefault()'` requires `e.preventDefault()` to appear within 3 lines of the branch entry. If the input-focus check is moved BEFORE `e.preventDefault()`, the gate still passes (preventDefault would be on line 4 of the A3 window) — but DO NOT do that. The intent is preventDefault-first, then guard, then toggle. The 3-line window is a safety margin, not a license to reorder.

    Decision note for the in-input guard: the existing Ctrl+` handler RETURNS WITHOUT preventDefault when typing in inputs (so backtick still types into the input). For Ctrl+P, the print-leak risk is more serious than for backtick, so we keep `preventDefault()` BEFORE the input-focus check. The input-focus check only skips the palette toggle — not the preventDefault. This is intentional and stricter than the Ctrl+` precedent. Verified against RESEARCH.md Pitfall 1.

    **Patch D — render mount.** Inside the JSX render, find the `<UnsavedChangesDialog>` mount (around line 506 per RESEARCH.md).     Do NOT add Ctrl+P to the Ctrl+1/2/3 separate useEffect block (~line 279) — that block guards bare-Ctrl-only and is for tab switching; Ctrl+P belongs in the main shortcut block.

    Do NOT change any other behavior in App.tsx. Specifically: do NOT modify the kbLock pattern, do NOT touch the Esc clear-pins handler, do NOT change the existing shortcut branches.
