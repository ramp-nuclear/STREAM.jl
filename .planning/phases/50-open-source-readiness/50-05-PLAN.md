<task type="auto">
  <name>Task 2: Add missing power equation to mtr_assembly.jl</name>
  <files>examples/mtr_assembly.jl</files>
  <action>
In examples/mtr_assembly.jl, find the `conns = [` array (around line 90-99). Add one equation at the end of the array, before the closing `]`:

```julia
    rods.hd.power ~ POWER,
```

The final conns array must look like:

```julia
conns = [
    connect(pump_l.port_out, hx_l.port_in),
    connect(hx_l.port_out, rods.cac_l.port_in),
    connect(rods.cac_l.port_out, pump_l.port_in),
    pump_l.port_in.P ~ 1.0e5,
    connect(pump_r.port_out, hx_r.port_in),
    connect(hx_r.port_out, rods.cac_r.port_in),
    connect(rods.cac_r.port_out, pump_r.port_in),
    pump_r.port_in.P ~ 1.0e5,
    rods.hd.power ~ POWER,
]
```

Root cause: HeatDiffusion declares `power` as an MTK @variables unknown (not a parameter). The constructor argument `power=POWER` only provides an initial guess, not a governing equation. Without `rods.hd.power ~ POWER` in the conns array, the system has 92 equations but 93 unknowns (power is unconstrained), causing an under-determined error at mtkcompile/solve_steady time.

Also remove the `fully_determined=false` kwarg from the mtkcompile call on line 101 — it was a workaround for this missing equation and should not suppress the error permanently. The line should become:

```julia
ssys = mtkcompile(sys)
```

This ensures future equation count mismatches surface immediately rather than being silently masked.
  </action>

  </verify>
  <done>examples/mtr_assembly.jl conns array contains `rods.hd.power ~ POWER` and mtkcompile is called without `fully_determined=false`. The system is fully determined (93 equations, 93 unknowns).</done>
</task>
