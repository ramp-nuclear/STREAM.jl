<objective>
Reconfigure the ReactFlow canvas interaction matrix from v0.8 defaults to the
drawio convention codified in §3.5: left-marquee + right-drag-pan + right-
click context-menu, with the 5px/250ms disambiguation locked by D-12. This
plan ALSO confirms the existing Del/Backspace key path correctly deletes
edges (it already does via ReactFlow's `deleteKeyCode` — line 223 of
CanvasPanel.tsx — but Phase 65 must add a regression test).

This is the substrate that Plans 04 (context menus) and 06 (snap-to-grid)
build on. It deliberately does NOT implement the menu UI — only the
handlers that fire when a "menu-worthy" right-click happens. Plan 04 wires
those handlers to the shadcn ContextMenu component.

Purpose: per D-12, distinguish intentional right-pan from intentional
right-click menu without over-suppressing either.

**Disambiguation architecture (locked at plan time):** ReactFlow @xyflow/react
v12 (^12.10.2 per gui/package.json) does NOT internally filter
`onPaneContextMenu` based on `panOnDrag` state — it forwards the React
synthetic contextmenu event regardless of whether a right-pan just
completed. The browser-native `contextmenu` event ALSO fires after a
right-button drag on most platforms (Linux/X11, Windows; macOS varies).
Therefore the threshold check cannot live inside the ReactFlow callbacks
alone — by the time the React handler runs, the browser may have already
shown its native menu. We attach a **window-level capture-phase
`contextmenu` listener** that calls `event.preventDefault()` when the
preceding right-mousedown→right-mouseup gesture exceeded the
5px/250ms threshold. The ReactFlow callbacks (`onPaneContextMenu`,
`onNodeContextMenu`, `onEdgeContextMenu`) check the same threshold and
only update internal state when the gesture qualifies as a "menu-worthy"
right-click; otherwise they are no-ops (state stays null, no Composer
menu opens). This is branch (b) of the checker's B2 disambiguation; we
do NOT rely on ReactFlow's defaults to filter the React event.

Output: CanvasPanel.tsx with the new interaction props; a reusable
`useRightClickContextMenu` hook with vitest unit coverage of the threshold
logic + the window contextmenu suppression path.
</objective>

```typescript
export interface ContextMenuState {
  kind: "pane" | "node" | "edge" | null;
  targetId: string | null;        // node id or edge id; null for pane
  screenX: number;
  screenY: number;
}

export function useRightClickContextMenu(): {
  state: ContextMenuState;
  close: () => void;
  // ReactFlow event handlers (signatures match @xyflow/react props):
  onPaneContextMenu: (event: MouseEvent | React.MouseEvent) => void;
  onNodeContextMenu: (event: React.MouseEvent, node: Node) => void;
  onEdgeContextMenu: (event: React.MouseEvent, edge: Edge) => void;
};

// Internal architecture:
//   1. window 'mousedown' listener (bubble phase): on button === 2, record {x,y,t} into a ref.
//   2. window 'mouseup'   listener (bubble phase): on button === 2, record {x,y,t} of the release
//      and compute the gesture's Manhattan distance + duration.
//   3. window 'contextmenu' listener (CAPTURE phase, true): if the last gesture was a drag
//      (over threshold), call event.preventDefault() — suppresses the OS-native menu.
//      Runs BEFORE ReactFlow's React handler.
//   4. The three ReactFlow callbacks check the same threshold and only setState when
//      the gesture qualified as a quick-short right-click. Otherwise they no-op
//      (state stays null — no Composer menu opens).
```
