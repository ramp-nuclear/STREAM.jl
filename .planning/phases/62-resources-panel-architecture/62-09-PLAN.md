<objective>
Refactor `gui/src/components/sidebar/SidebarPanel.tsx` into a selection-kind router per CD-05 + RESEARCH Pattern 4. The router branches on the store-derived `selectionKind` discriminator (computed in 62-02): `"component"` shows the existing Component editor body (today's behavior), `"resource"` shows the appropriate ResourceEditor (in edit mode) for the selected resource, `"none"` shows the no-selection prompt with the variant copy depending on whether the user is in the Resources tab vs other tabs (UI-SPEC §"Right Properties panel — no-selection body").

Add the right-panel header text variation per D-06: `Properties` (component), `Geometry: <name>` / `Power Shape: <name>` (resource), `Properties` + `No selection` body (no selection or Project tab). A single header line reads the discriminator.

Add the global Esc-key handler implementing the UI-SPEC cascade tail. Items 1-3 of the cascade (popover-close, rename-cancel, context-menu-close) are owned by their respective component layers — in particular, 62-08's `ResourceCreationPopover.tsx` already calls `e.preventDefault() + e.stopPropagation()` in its `onEscapeKeyDown` so the global listener does NOT fire when an open popover absorbs the Esc. This plan only adds the final cascade step (item 4 — selection-clear): a `useEffect` listener on `document` that, when reached, calls `clearSelection()` if `selectionKind !== "none"`.

Output: rewritten `SidebarPanel.tsx`, one new test file covering the router branches + header text + Esc cascade tail.
</objective>
