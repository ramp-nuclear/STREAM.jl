<!-- Existing shadcn shim conventions in gui/src/components/ui/ — extracted by reading tabs.tsx, scroll-area.tsx, dropdown-menu.tsx once -->

The project's shadcn surface (new-york style, zinc base, cssVariables enabled per `gui/components.json`) uses this exact pattern:
- Each shim file imports the relevant Radix primitive from the `radix-ui` aggregator package (e.g., `import { Tabs as TabsPrimitive } from "radix-ui"`) — NOT from `@radix-ui/react-tabs`. This is verified in `tabs.tsx` line 1 and `scroll-area.tsx` line 2.
- Each shim re-exports a set of named components: `Popover`, `PopoverTrigger`, `PopoverContent`, `PopoverPortal`, ... mapping to the primitive's parts.
- Styling uses `cn(...)` from `@/lib/utils` plus Tailwind utility strings; the typical Content classes are along the lines of `"z-50 w-72 rounded-md border bg-popover p-4 text-popover-foreground shadow-md outline-hidden data-[state=open]:animate-in data-[state=closed]:animate-out ..."` for popover-style surfaces.

The canonical shadcn upstream source for both files is at:
- https://ui.shadcn.com/docs/components/popover  (popover.tsx)
- https://ui.shadcn.com/docs/components/context-menu  (context-menu.tsx)
The "new-york" variant is what `gui/components.json` declares (`"style": "new-york"`). Both shadcn upstream sources are TypeScript-first and import from `@radix-ui/react-popover` / `@radix-ui/react-context-menu` — convert the imports to the `radix-ui` aggregator namespace pattern that this project uses (see `tabs.tsx` for the model).

Per UI-SPEC §"Registry Safety": no `npx shadcn add` invocation against an external registry is required. The files are hand-written wrappers around the transitively-available Radix primitives. Both Radix packages are confirmed available:
- `@radix-ui/react-popover@1.1.15` (package-lock.json line 1410)
- `@radix-ui/react-context-menu@2.2.16` (package-lock.json line 1841)

Per UI-SPEC §"Popover surface": fixed visual width is set at the consumer site (e.g., `style={{ width: 280 }}` on `<PopoverContent>`) — the shim does NOT bake 280px in; it provides a sensible default that the consumer overrides.

Per UI-SPEC §"`+ New…` anchored popover":
- `side="right" align="start" sideOffset={4} collisionPadding={8}` are consumer-supplied props
- `onInteractOutside={(e) => e.preventDefault()}` is the non-default knob — the shim MUST pass this prop through transparently (it does by default, since it just spreads `...props` to PopoverPrimitive.Content)

Pitfall 1 focus-return workaround (RESEARCH §"Pitfall 1" + UI-SPEC §"Focus return on dismiss"): consumers explicitly call `triggerRef.current?.focus()` after `setPopoverOpen(false)`. The shim does NOT implement this; the consumer (62-08) does. The shim simply provides the primitive surface.
