# Phase 63.1 Plan 03: Anchors slice + persistence Summary

Introduce the per-node `anchors: Record<string, AnchorEntry>` store slice
(D-02 at-most-one), physically delete the legacy `bcs: BCEntry[]` slice
plus its `addBC` / `removeBC` actions, migrate `removeNode`'s cleanup from
`bcs.filter` to an immutable `anchors[nodeId]` purge, and swap the `.scp`
v2.0 schema field from `bcs` Array to `anchors` Record on both serialize
and deserialize. Per D-14, no legacy fallback — old `.streamgui` files
drop their anchor data on load.

## What Was Built

### Task 1 — `gui/src/lib/anchors.ts` pure module (commit d72060e)

40-line types-only module exporting:

```ts
export interface AnchorEntry {
  portField: "port_in.P" | "port_out.P";
  value: number;
}
export interface CodegenAnchorsState {
  anchors: Record<string, AnchorEntry>;
}
```

Module header copies the `bcMode.ts` purity contract verbatim — zero React,
zustand, or @xyflow runtime imports — and documents the five downstream
consumers (useStore.ts, codeGenerator.ts, projectIO.ts, AnchorsSection.tsx
in Plan 06, StreamNode.tsx in Plan 08). Sentinel-by-absence (D-02): a
missing key means no anchor, no `{kind: "unset"}` record. D-01 lock-in is
written into the header: `portField` is restricted to two pressure-port
literals, no other anchor kind can land in this phase.

`grep -E "^import [^t]" gui/src/lib/anchors.ts | grep -v "^import type"`
returns nothing. tsc green (zero new errors).

### Task 2 — useStore.ts anchors slice + legacy deletion (commit 8beb4f1)

**Type additions** (AppState + CanvasSnapshot):
- ADD `anchors: Record<string, AnchorEntry>` field
- ADD `setAnchor(nodeId, entry): void`
- ADD `clearAnchor(nodeId): void`
- REMOVE `bcs: BCEntry[]` field
- REMOVE `addBC: (bc: BCEntry) => void`
- REMOVE `removeBC: (index: number) => void`

**Action bodies** (Pattern A + Pattern B):
```ts
setAnchor: (nodeId, entry) => {
  get()._pushSnapshot();
  set({ anchors: { ...get().anchors, [nodeId]: entry }, isDirty: true });
},
clearAnchor: (nodeId) => {
  get()._pushSnapshot();
  const next = { ...get().anchors };
  delete next[nodeId];
  set({ anchors: next, isDirty: true });
},
```

**`removeNode` cleanup migration:**
```ts
const nextAnchors: Record<string, AnchorEntry> = { ...anchors };
delete nextAnchors[nodeId];
set({ ..., anchors: nextAnchors, ... });
```
Replaces the legacy `bcs: bcs.filter((bc) => bc.nodeId !== nodeId)` line.
Same per-node lifetime invariant; anchor entries never survive their host
node.

**Snapshot plumbing:** `_pushSnapshot`, `undo`, `redo` all copy `anchors`
along the same lines they previously copied `bcs`.

**`validateAndGate` transitional adapter:** `validation.ts` still types
its 3rd argument as `BCEntry[]`. The store synthesizes the adapter on
demand:
```ts
const bcsAdapter: BCEntry[] = Object.entries(anchors).map(
  ([nodeId, entry]) => ({ nodeId, portField: entry.portField, value: entry.value }),
);
const result = validateTopology(nodes, edges, bcsAdapter, getComponent);
```
The "No pressure boundary condition" gate continues to fire correctly.
Plan 04 retires the adapter.

**Persistence call sites:** `saveProject`, `saveProjectAs`,
`loadProjectFromPath`, and `newProject` swap `bcs:` for `anchors:` in
their respective `set({...})` / `serializeProject({...})` arguments.

**`grep -nE "\bbcs\b" gui/src/store/useStore.ts` → 0 matches.** Comment

**`grep -cE "\b(addBC|removeBC)\b" gui/src/store/useStore.ts` → 0 matches.**

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] BCPanel.tsx rewired to anchors slice**

- **Found during:** Task 3 tsc gate.
- **Issue:** `BCPanel.tsx` directly subscribed to `state.bcs`, `addBC`,
  and `removeBC`, which Task 2 removed. tsc failed with 3 type errors.
- **Fix:** Replace bcs/addBC/removeBC with `anchors / setAnchor /
  clearAnchor`, iterate `Object.entries(anchors)` instead of `bcs.map`,
  keep the same UI (component + port + value inputs, BCRow chips).
- **Rationale:** Plan 05 deletes BCPanel.tsx outright; this is a
  transitional rewire so the bottom-panel "BCs" tab keeps working between
  Plans 03 and 05. Scope-bounded (single file, no new behavior).
- **Files modified:** `gui/src/components/BCPanel.tsx`.
- **Commit:** 429f747.

**2. [Rule 3 — Blocking] Toolbar.tsx + CodePreview.tsx + codeGenerator.smoke.test.ts synthesize a BCEntry[] adapter**

- **Found during:** Task 3 tsc gate.
- **Issue:** All three sites pass `state.bcs` / `project.bcs` to the
  legacy `generateCode(...)` 3rd argument (still typed `BCEntry[]`).
  Removing `bcs` from the store broke them.
- **Fix:** Add `const bcsAdapter: BCEntry[] = Object.entries(anchors).map(...)`
  immediately before each `generateCode` call. The legacy `BCEntry`
  re-export from `../lib/codeGenerator` is intact, so the adapter
  type-checks without further changes.
- **Rationale:** Plan 04 retires the `generateCode` BCEntry[] parameter
  (it becomes `CodegenAnchorsState`); the adapters disappear there. Per
  the plan: "Codegen and validation modules will be updated in Plan 04 —
  they currently still take a bcs param; after this plan, no one passes
  bcs to them, but their signature still exists. Plan 04 retires the
  signature."
- **Files modified:** `gui/src/components/Toolbar.tsx`,
  `gui/src/components/CodePreview.tsx`,
  `gui/src/lib/__tests__/codeGenerator.smoke.test.ts`.
- **Commit:** 429f747.

**3. [Rule 3 — Blocking] validateAndGate adapter in useStore.ts**

- **Found during:** Task 2 implementation.
- **Issue:** `validation.ts:validateTopology` still types its 3rd arg
  `BCEntry[]`. After removing the `bcs` slice the only callers (saveProject,
  validateAndGate) had nothing to pass.
- **Fix:** Synthesize a BCEntry[] at the `validateAndGate` call site
  from `Object.entries(anchors)`. The "No pressure boundary condition"
  system error gate continues to fire when `anchors === {}`.
- **Rationale:** Same as #2 — Plan 04 retires the BCEntry[] parameter on
  validateTopology. Without the adapter, the validation gate would
  silently fail-open (always say "no pressure BC" because nothing reaches
  it), regressing safety until Plan 04 lands.
- **Files modified:** `gui/src/store/useStore.ts`.
