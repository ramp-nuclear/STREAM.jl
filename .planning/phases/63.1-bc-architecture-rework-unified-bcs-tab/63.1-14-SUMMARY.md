# Phase 63.1 Plan 14: BC-Mode Parity for WT.T_wall / HFS.q (GAP-RC-4) Summary

SourceValueEntry discriminated union + 3-mode Properties dropdown closes BC-mode parity gap between BCsTabForm consumer-side and ParameterForm source-side for WallTemperature.T_wall and HeatFluxSource.q.

## What Was Built

### Task 1 — sourceValueEntry.ts (TDD)

New module `gui/src/lib/sourceValueEntry.ts`:
- `SourceValueEntry` — 4-arm discriminated union: `{mode:"value",value:number}` | `{mode:"profile",preset:"cosine",...}` | `{mode:"profile",preset:"file",...}` | `{mode:"function",...}`
- `isSourceValueEntry(v: unknown): v is SourceValueEntry` — runtime guard used by codegen, sourceLabelLine
- `defaultSourceValueEntry(value: number): SourceValueEntry` — factory seeding value-mode entries

12 tests: 10 guard cases + 2 factory cases. All GREEN.

### Task 2 — modeEditors.tsx (refactor)

Extracted `ProfileModeEditor` and `FunctionModeEditor` from `BCsTabForm.tsx` into `gui/src/components/sidebar/modeEditors.tsx`. BCsTabForm re-imports from there. ParameterForm imports from there. No prop-shape changes.

`onUpdate` type loosened from `(e: BCModeEntry)` to the 3-arm union `ProfileEntry | FunctionEntry | {mode:"value",value:number}` — structurally a subtype of BCModeEntry so BCsTabForm callers continue to type-check.

### Task 3 — ParameterForm TypeUnionField extension (TDD)

`TypeUnionField` gains `isSourceValueParam: boolean` prop. When `true` (Sources-category component), renders a 3-option Mode dropdown (Value/Profile/Function) and dispatches per-mode editor body. When `false` (Channel.h_left/h_right, Hydraulic), preserves scalar-only Plan 11 behaviour with "edit in generated Julia" hint.

`handleModeChange` seeds canonical SourceValueEntry shapes on mode switch. ScalarInput `onChange` wraps as `{mode:"value",value:v}` when `isSourceValueParam=true`.

15 tests passing (7 new Plan 14 + 8 updated RC-1/regression).

### Task 4 — codeGenerator SourceValueEntry emission (TDD)

`formatParamValue` gains:
1. `isSourceValueEntry(value)` guard before the `switch(param.type)` — dispatches: value→`formatReal`, profile→`${inst}_${param.name}_profile`, function→`value.functionName || "<UNSET_FUNCTION>"`
2. Bare-number legacy fallback for `type_union` params (pre-Plan-14 files emit `formatReal` not `String(N)`)
3. `emitContext?: { instanceName }` parameter threaded from `emitComponentDeclaration`

`sourceEmitPlan` walk added after bcEmitPlan loops: iterates Sources-category nodes, emits profile-var assignment lines (`${inst}_T_wall_profile = cosine_T_wall_profile(n, 1.0, 1.0)` / file-load variant) and function stub lines before `@named` declarations.

40/40 tests GREEN.

### Task 5 — StreamNode + useStore (TDD)

`StreamNode.sourceLabelLine`: `isSourceValueEntry` dispatch before legacy shape checks — renders `T_wall = N K` (value), `T_wall = profile (cosine/file)` (profile), `T_wall = fn(t)` (function), unchanged `(unset)` destructive-red for absent entry.

`useStore.promoteToSharedSource`: `SOURCE_DEFAULT_SEED` updated from `{T_wall: 300.0}` to `{T_wall: defaultSourceValueEntry(300.0)}` — spawned source stores new entry shape from first write.

33/33 tests GREEN.
