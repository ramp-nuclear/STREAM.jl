# Phase 63.1: BC architecture rework — unified BCs tab - Context

**Gathered:** 2026-05-13
**Status:** Ready for planning

<domain>
## Phase Boundary

Rework the BC architecture that shipped in Phase 63 to address three classes of problems surfaced by use-testing: (a) correctness bugs in what shipped, (b) wrong default for the dominant case (Sources-as-canvas-nodes is over-engineered when there's one channel, one BC, one value), (c) the mode picker pill UX advertises the rarest action.

The phase delivers a single coherent rework that bundles the bug fixes and the redesign together — fixing CR-01/02/03 in isolation while planning to delete the Sources-on-canvas surface next phase would be wasted work.

**In scope:**
- Unified BCs tab as the single surface for every binding on a component (Anchors section + External Inputs section)
- Hide `WallTemperature` / `HeatFluxSource` canvas nodes by default; opt-in via inline "Promote to shared source" action from the BCs tab
- Replace 5-pill `BCModePicker` with a dropdown
- Replace "L=R" switch with a labeled `Symmetric | Asymmetric` segmented control
- New `anchors: Record<nodeId, AnchorEntry>` slice replacing the legacy `bcs: BCEntry[]` slice; delete the freestanding BCPanel
- Canvas indicator (small marker) on anchored ports/nodes
- Selector-derived validation state (replaces stored `errorTagsByNodeId`) — fixes the stale-ring bug class
- Bug fixes: CR-01 (BC-edge drag), CR-02 / CR-03 (`setBCSymmetric` edge holes), click-vs-drag selection not refreshing Properties, n-mismatch ring not clearing

**Out of scope:**
- Gravity-reference anchor UI (stays per-component `Gravity(H)`)
- Transient-initial-conditions anchor UI (deferred to a later phase; not v1.2)
- Migration of Phase-63-era `.streamgui` files (heavy-dev project, old files break)
- General GUI visual polish / design pass (Phase 72)
- The Phase 71 validation framework itself — 63.1 only sets the selector-derived foundation

</domain>

<decisions>
## Implementation Decisions

### Anchors section scope

- **D-01:** Pressure anchor is the ONLY kind of anchor exposed in the BCs-tab Anchors section in this phase. Gravity reference stays a per-component property via `Gravity(H)` and `check_gravity_mismatch` (unchanged). Transient initial conditions are deferred to a later phase — `solve_transient` continues to source ICs from `steady_state_guess` or user-supplied as today.

### Anchor data path

- **D-02:** Introduce a new store slice `anchors: Record<nodeId, AnchorEntry>` where `AnchorEntry = { portField: "port_in.P" | "port_out.P", value: number }`. The Record shape enforces at most one anchor entry per component (overwriting on second set is the correct semantics). Multiple components MAY have anchor entries; the Phase 71 validation framework enforces the global "exactly one anchor per loop" invariant — 63.1 does not implement that global validator.
- **D-03:** Delete the legacy `bcs: BCEntry[]` slice and the freestanding `BCPanel.tsx`. All anchor rendering moves into the per-component BCs tab Anchors section. Single source of truth, single rendering site.
- **D-04:** The Anchors section only renders for components that have a `FlowPort` (Pump, Channel, ChannelHeatFlux, ChannelAndContacts, Resistor, Inertia, HeatExchanger, …). Components without a flow port (e.g. `WallTemperature`, `HeatFluxSource`) never display the Anchors section.
- **D-05:** Codegen iterates `Object.entries(anchors)` and emits `${instanceName}.${portField} ~ ${value}` lines. This replaces the current `bcs[]` codegen path.

### Sources-as-canvas-nodes (hidden by default)

- **D-06:** Sources toolbox category removed from the default toolbox. Inline BCs in the BCs tab are the default.
- **D-07:** "↗ Promote to shared source" trigger is a **button next to the mode dropdown** in the External Inputs row of the BCs tab. (No right-click menu; no auto-promote on second-bind detection.) Discoverability over implicit magic.
- **D-08:** When invoked, "Promote to shared source" spawns the corresponding `WallTemperature` / `HeatFluxSource` node on the canvas at a reasonable default position, replaces the inline value on the originating component with a reference to that node, and creates the dashed BC edge.

### BCs tab layout

- **D-09:** Two clearly-labeled sections inside the right-sidebar BCs tab: **Anchors** (top) and **External Inputs** (below). Same panel, same tab — not unified under the 5-mode picker because the pressure anchor has a global "exactly one per loop" invariant and a fixed scalar shape that doesn't fit the picker fiction.
- **D-10:** The BCs tab stays in the right sidebar next to Properties. Visual weight shifts happen inside the panel (D-11, D-12), not by relocating the tab.

### Mode picker + symmetric toggle UX

- **D-11:** Replace the 5-pill `BCModePicker` with a **dropdown**. Mode-change is rare; value-edit is common. The value editor gets the full row width; mode is one click away in the dropdown.
- **D-12:** Replace the "L=R" symmetric switch with a labeled **segmented control: `Symmetric | Asymmetric`**. Strips the engineer-speak ambiguity about which state the toggle is currently in.

### Canvas indicators

- **D-13:** The canvas displays a small visual indicator on ports/nodes that carry an anchor entry. Discoverability of the global anchor state matters when validation flags a loop with missing or duplicate anchors. The exact visual treatment (icon vs ring vs badge) is a UI-phase decision; the principle is locked here.

### Migration / back-compat

- **D-14:** **No migration path** for Phase-63-era `.streamgui` files. STREAM.jl and the Composer GUI are in heavy development; old saved files are accepted to break. Do NOT write a schema upgrader, a "load old shape" fallback, or a parallel legacy UI. See memory `feedback_no_back_compat_during_heavy_dev` for the durable rule.

### Validator architecture (n-mismatch ring + future validators)

- **D-15:** Delete the stored `errorTagsByNodeId` slice. Replace with a **memoized selector** (`selectNodeErrors(nodeId)` or equivalent) that reads current `nodes`, `edges`, `bcMode`, `anchors`, `bcSymmetric` and computes the ring/error state on demand. No stored cleanup step exists because there is no stored state to go stale.
- **D-16:** Rationale: CR-03, the n-mismatch ring-stale bug, and the click-vs-drag stale-Properties bug all share one root cause — stored derived state going stale relative to authoritative state. Patching one event handler at a time keeps creating new variants of the same bug. Selector-derived eliminates the entire bug class by construction.
- **D-17:** Memoize the selector (`reselect`-style or zustand-shallow-equal) so render cost stays trivial. Graph sizes are small (tens of components, not thousands) — recompute on every store mutation is acceptable; memoization is for re-render avoidance, not for correctness.
- **D-18:** All current consumers of `errorTagsByNodeId` (canvas node ring rendering, any badges) must be migrated to read through the selector. No parallel-storage shortcut.
- **D-19:** Phase 71 validation framework is expected to extend this same pattern (each validator = a selector). 63.1 sets the foundation but does NOT implement the full framework.

### Bug fixes in scope

- **D-20:** **CR-01** — `addEdge` BCPort branch in `gui/src/store/useStore.ts:1047-1062` must write the `bcMode` entry when a BC edge is canvas-dragged. `63-REVIEW.md` has drop-in fix code. If the Sources-on-canvas surface is also being hidden by default in this phase, the CR-01 fix still ships because the canvas surface remains available via the "Promote to shared source" path — wiring must work there too.
- **D-21:** **CR-02 / CR-03** — `setBCSymmetric(true)` in `gui/src/store/useStore.ts:~1298` must handle the `leftEntry === undefined && rightEntry !== undefined` case (CR-02) and must also resync the BC edges and n-mismatch tags after mirroring (CR-03). With D-15 in place, the n-mismatch resync part of CR-03 disappears because the ring is no longer stored — only the edge-sync part remains.
- **D-22:** **Click-vs-drag selection bug** — clicking a node refreshes Properties; click-and-drag must do the same. Investigate whether the drag handler swallows the selection change event.
- **D-23:** **N-mismatch ring lifecycle bug** — subsumed by D-15. The ring becomes a derived value and clears automatically when the underlying mismatch is fixed. Verify this empirically in the smoke test.

### Claude's Discretion

- Where the user delegated explicitly ("do what you really think is best"): D-02 / D-03 / D-04 / D-05 (anchor data-path shape) and D-15 / D-17 / D-18 (validator architecture choice — selector-derived over event-driven or store-mutation-driven).
- Visual treatment of the canvas anchor indicator (D-13) — icon vs ring vs badge — is open for UI-phase.
- Default canvas position for the spawned shared-source node on "Promote to shared source" (D-08) — pick a sensible default; treat as a small UX choice during planning.
- Memoization library choice for the selector (D-17) — pick whatever fits the existing zustand patterns; do not introduce a new dependency unless necessary.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- **`bcMode` slice + `bcModeKey` composite key** — keep for the External Inputs section; only the picker UI changes (D-11). State shape stays.
- **`bcSymmetric` slice + `setBCSymmetric`** — keep, fix the two transition-edge holes (D-21), replace surface UI with segmented control (D-12).
- **`_revertBCModeForEdge` private mutator** — already factored out; the new `anchors` slice can mirror this pattern if a similar revert path is needed.
- **`useStore` undo discipline** (Phase 63 extension at useStore.ts:132-133) — `bcMode`, `bcSymmetric`, `errorTagsByNodeId` are undoable. The new `anchors` slice MUST follow the same discipline; selector-derived state by definition needs no undo entry.
- **Phase 62 Resources slice discipline** (`useStore.ts:1112`) — the new `anchors` slice should follow the same isolation pattern.
- **`BCEntry` shape + codegen emission** (`codeGenerator.ts:39-43`) — has the right field semantics (`portField: "port_in.P" | "port_out.P"`, `value: number`); reuse the shape inside the new `AnchorEntry` and adapt the emission loop.

### Established Patterns
- **Codegen is pure** — no React/zustand imports; pass state shapes through `CodegenBCsState` (`codeGenerator.ts:83`). The new `anchors` slice must be passed through a similar typed shape, not imported from the store.
- **Composite-key dicts** (`bcMode`, `bcModeKey`) — Record-of-string-keys is the project's idiom for "per-component-per-input" state. The new `anchors` slice uses `Record<nodeId, AnchorEntry>` (no composite key needed because there is only one anchor per node).
- **Sentinel values for "unset"** (`SENTINEL_UNSET_POWER_SHAPE_UUID` in codegen) — keep the absence-of-key idiom for `anchors` instead of a sentinel; an entry not present means "no anchor on this component".

### Integration Points
- **Phase 71 validation framework** — D-15..D-19 set the selector-derived foundation. Planner should NOT implement multi-validator infrastructure here, only the one selector needed for n-mismatch + missing/duplicate anchors as a derived view.
- **Phase 66 code-preview rework** — will consume whatever codegen path D-05 produces. Codegen contract change should be clean (single anchor emission loop) to make 66's structured `CodeSection[]` easier.
- **Phase 64 connection routing** — the dashed BC edge from "Promote to shared source" (D-08) lives in the same edge-routing surface 64 reworks. Plan must avoid stepping on Phase 64's autoflip work; if 64 ships first, 63.1 inherits its routing.

</code_context>

<specifics>
## Specific Ideas

- "Feels amateur" — the original user feedback that motivated B (hidden Sources by default). Keep the dominant-case flow (one channel, one BC, one value) to a single visible surface (the BCs tab).
- "Engineer-speak" — the user's word for why the `L=R` toggle confuses; segmented `Symmetric | Asymmetric` labels are intentionally plain English.
- "↗ Promote to shared source" — the user-spoken label for the action, with the up-right arrow indicating "elevate this to a higher-level shared resource". Keep this exact wording in the UI unless a clear improvement surfaces in UI-phase.

</specifics>

<deferred>
## Deferred Ideas

- **Gravity reference as a BCs-tab anchor** — stays per-component `Gravity(H)` for now. Reconsider if multi-loop networks with shared potential-energy datums become common.
- **Transient initial conditions in the BCs tab** — defer to a future phase; needs its own discuss-phase about state-variable IC semantics and how it relates to `steady_state_guess`.
- **Auto-promote on second-bind detection** — explicitly rejected for 63.1 (D-07); revisit if user testing shows the explicit button is missed too often.
- **Right-click context menu on BC rows** — not in 63.1; could be added in Phase 65 (interaction model overhaul) alongside other right-click affordances.
- **Phase 71 full validation framework** — 63.1 only sets the selector-derived foundation. The pluggable validator registry, validation panel UX, click-to-focus, action buttons, status-bar indicator, and the full initial rule set (per ROADMAP §Phase 71) remain in Phase 71's scope.
- **Visual treatment of the canvas anchor indicator** — UI-phase decision; the principle (D-13) is locked here.

</deferred>
