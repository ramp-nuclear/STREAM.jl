# Phase 63.1 Plan 09: Toolbox Sources Hide + Canvas Anchor Indicator Summary

**Canvas-surface changes for the unified BC architecture: Sources category removed from the default toolbox (registry kept for programmatic spawn); StreamNode now renders a small filled-circle anchor glyph next to anchored FlowPort handles.**

## Performance

- **Duration:** ~25 min
- **Started:** 2026-05-13T19:40:00Z (approx — agent spawn)
- **Completed:** 2026-05-13T20:04:45Z
- **Tasks:** 2
- **Files modified:** 3

## Accomplishments

- **D-06 — Toolbox Sources hide.** ToolboxPanel.tsx no longer renders the Sources category header or its WallTemperature / HeatFluxSource drag rows. The `getComponentsByCategory("Sources")` call, the `sourceComponents` / `visibleSources` locals, and the Sources `<div>` block + `.map(...)` are all deleted. Registry entries in `components.json` are untouched, so Plan 08's `promoteToSharedSource` (which spawns those nodes programmatically via `addNode`) keeps working.
- **D-13 — Canvas anchor indicator.** StreamNode.tsx renders a 6×6 px filled circle (`w-1.5 h-1.5 rounded-full bg-foreground`) absolutely positioned next to whichever FlowPort handle has its `portField` recorded in the `anchors` slice. The indicator carries `data-testid="anchor-indicator"` and `aria-label="Pressure anchor"` per UI-SPEC §"Canvas Anchor Indicator". The indicator dims with the handle (`opacity-20`) when the node is in dual-layer dimmed-flow mode.
- **Rules-of-hooks compliance.** The per-handle anchor selector is hosted in a new `FlowPortHandle` sub-component, declared above the StreamNode default export. The previous `flowPorts.map((port) => <Handle …/>)` body is rewritten to delegate to `<FlowPortHandle nodeId={id} port={port} dimFlowHandles={dimFlowHandles} />`, eliminating the would-be hooks-in-loops violation.
- **Plan 01 RED test flipped GREEN.** `gui/src/components/__tests__/StreamNode.anchor.test.tsx` (Plan 01 Wave-0 stub) now passes — both the "indicator renders when anchored" and "indicator absent when not anchored" assertions are green.

## Decisions Made

- **Anchor indicator offsets** — The UI-SPEC §"Canvas Anchor Indicator — Position" recommends `(-6, -6)` as a starting point but explicitly invites refinement if the value clips. The implementation uses `±10` on the perpendicular axis and `−3` on the parallel axis (`left: -10, top: -3` for left-side handles; mirrored for right/top/bottom). This puts the 6-px dot fully outside the 12-px handle's hit region — the dot reads as a port-level marker without overlapping the handle's drag affordance.
- **Sub-component scope** — `FlowPortHandle` lives inside `StreamNode.tsx` rather than its own file. Its sole reason for existing is rules-of-hooks compliance for the anchor selector; nothing else consumes it. Co-locating keeps the per-handle logic next to the rest of the node-render code without adding file fanout.
- **Test rewrite vs. delete** — `ToolboxPanel.test.tsx` was rewritten in place rather than deleted. The Phase 62 D-30 + Phase 63 D-24 tests asserted *presence*; the rewritten Phase 63.1 D-06 tests assert *absence* of the same affordances. Keeping the file under its original name preserves the suite shape for future tooling that maps test files to component files by name.
