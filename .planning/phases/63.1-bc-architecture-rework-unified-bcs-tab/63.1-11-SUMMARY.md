## Decisions Made

1. **Scalar-only editor; no per-cell vector editor.** First implementation passed all GREEN tests with a scalar/vector/callable mode picker, a 1-cell-per-row `VectorEditor` (sized off sibling `parameters.n`), and a `fn(t)`/`fn(t, i)` callable signature picker. Smoke feedback rejected this: per-cell entry at realistic `n` (20+) is unusable, and signature pickers add UI noise. The whole picker came out; only scalar input remains. **Storage-shape consequence:** the editor never writes a vector or string from the GUI. Vector and callable values must originate in the generated Julia.

2. **Always-overwrite for legacy non-scalar values.** If `nodeData.parameters[<paramName>]` is an array or string (e.g. an older project file), the input renders empty (no `vector[N]` badge, no `fn(t)` chip), and the first scalar edit cleanly overwrites the shape. Aligned with [feedback_no_back_compat_during_heavy_dev]; rejected alternatives "read-only badge with reset" and "hide editor entirely".

3. **BC-mode parity (Value / Profile / Function) deferred to new Plan 63.1-14.** Second smoke iteration surfaced a genuine design gap: the BCs tab on a consumer Channel/CHF offers `value | profile | function | mark | source`, but the WT/HFS Properties tab now exposes only Value. Because "you can promote anything to WT", these option sets should match (minus `mark`/`source`, which don't apply on the source itself). This requires extending the storage shape of `nodeData.parameters[T_wall|q]` from `number` to a `BCModeEntry`-like union (value/profile/function), wiring the existing `BCsTabForm` `ProfileModeEditor` / `FunctionModeEditor` sub-components into `ParameterForm`, and updating codegen + `StreamNode.sourceLabelLine`. **Out of RC-1 scope** — RC-1 was "type_union params render at all"; that goal is achieved. The parity work is logged as Plan 14 and the deferred-items entry below.

4. **Test rewrites under Rule 3 auto-fix.** When the scalar/vector/callable picker was removed, the corresponding mode-picker tests were dropped and replaced with negative assertions (`queryByRole(...)).toBeNull()`) plus a new "overwrite non-scalar value" test. Original RED → GREEN provenance preserved in commits `bc33364` → `40cdebb` → `5125f89`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] Pre-existing `ResourceReferencePicker` missing `TooltipProvider` wrapper**
- **Found during:** Task 1 test write (Channel render path mounts `ResourceReferencePicker` for `geometry`)
- **Issue:** `ResourceReferencePicker.tsx` uses `<Tooltip>` without an inline `<TooltipProvider>` — relies on the App-level provider (`App.tsx:217`). Tests outside the App tree crash with "Tooltip must be used within TooltipProvider".
- **Fix:** Wrapped the Channel-render test in `<TooltipProvider>` (mirrors existing pattern in `ResourceReferencePicker.test.tsx:56-62`).
- **Files modified:** `gui/src/components/sidebar/__tests__/ParameterForm.test.tsx`
- **Verification:** Channel test passes; no regression to existing ResourceReferencePicker tests.
- **Committed in:** `40cdebb` (Task 2 commit).

**2. [Rule 3 — Auto-fix] Test mode-inference assertion used `unmount()+rerender` (invalid React Testing Library usage)**
- **Found during:** Task 2 GREEN cycle.
- **Issue:** `rerender` requires the same root; after `unmount()` the root is destroyed and `rerender` errors with "Cannot update an unmounted root."
- **Fix:** Replaced with three sequential `render()` / `unmount()` cycles.
- **Committed in:** `40cdebb`.

**3. [Rule 3 — Scope adjustment] Removed vector and callable editors per smoke feedback (rewrite, not auto-fix)**
- **Found during:** Task 3 human-verify.
- **Fix:** Refactored `TypeUnionField` to scalar-only; deleted `VectorEditor` and the inline callable signature picker; dropped `SegmentedButtonGroup` import.
- **Committed in:** `5125f89`.
