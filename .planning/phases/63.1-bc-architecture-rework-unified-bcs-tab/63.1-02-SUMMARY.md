# Phase 63.1 Plan 02: Selector-derived validator foundation Summary

Replace the stored `errorTagsByNodeId` slice + inline `_checkBCNMismatch`
mutator with a pure memoized selector `selectNodeErrors(state, nodeId): string[]`,
deleting the slice + actions + undo plumbing + tag-helper functions entirely
and migrating the only non-test consumer (StreamNode.tsx) to read through
the selector. This eliminates the stored-derived-state bug class (D-16) that
produced CR-03's residual n-mismatch ring and the click-vs-drag stale-Properties
bug, and lands the Phase 71 validator-as-selector foundation (D-19).

## What Was Built

### Task 1 — `selectNodeErrors` pure selector (commit d397b15)

New file `gui/src/lib/selectors/nodeErrors.ts` (95 lines). Exports:

```ts
export interface NodeErrorsInput {
  nodes: Node[];
  edges: Edge[];
  bcMode: Record<string, BCModeEntry>;
  bcSymmetric: Record<string, boolean>;
  anchors: Record<string, { portField: "port_in.P" | "port_out.P"; value: number }>;
}
export function selectNodeErrors(state: NodeErrorsInput, nodeId: string): string[];
```

- Type-only imports (`Node`, `Edge` from `@xyflow/react`; `BCModeEntry` from
  `../bcMode`) — purity-clean per RESEARCH Pattern C.
- The `anchors` field is declared on `NodeErrorsInput` for forward-compat
  (Phase 71 validators) but the body does not yet consume it; the field is
  documented with `// reserved: anchors used by future validators (Phase 71)`.
- Body iterates `Object.entries(state.bcMode)` once, branching on whether the
  current `nodeId` is on the consumer side (key prefix match) or the source
  side (entry.sourceNodeId match), and pushes the literal tag
  `'bc-n-mismatch'` (kept verbatim from useStore.ts:1372 for grep-compat
  with downstream Phase 71 work) when both ends have `typeof === "number"`
  and disagree. A `break` after the first push deduplicates.
- All four Plan-01 RED tests in `src/lib/selectors/__tests__/nodeErrors.test.ts`
  flipped GREEN: bc-n-mismatch detection, n-match returns [], value-mode
  returns [], auto-clear on matching n.
