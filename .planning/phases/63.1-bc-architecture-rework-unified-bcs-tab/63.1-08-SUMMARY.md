# Phase 63.1 Plan 08: Promote-to-shared-source flow (D-07, D-08) Summary

Hoists the `BCsTabForm.handleNewSource` flow into a single store action
`useStore.promoteToSharedSource(consumerNodeId, externalInputName)` and
surfaces it as a `↗ Promote to shared source` ghost button next to the
Mode Select on every eligible External Inputs row. The legacy
`+ New <SourceKind>` outline button inside the source-mode editor is
deleted — Promote supersedes it (D-07 discoverability over implicit
mode-then-spawn). Plan 01's RED test `promoteToSharedSource.test.ts`
flips to GREEN as the empirical proof that the store action implements
the locked contract.

## What Was Built

### Task 1 — `promoteToSharedSource` action in useStore.ts (commit `c5e6104`)

**`gui/src/store/useStore.ts`:**

- AppState interface: added the action type declaration next to the
  other BC actions (line ~270), with a docstring locking the spawn-offset
  contract (-160 / -40), the n-seed-before-setBCMode discipline, and the
  no-op semantics when consumer node is missing or `source_component` is
  not resolvable from the registry.
- Action body added immediately above `setBCSymmetric` (~line 1232) at
  the same indentation as the other BC actions. The body follows
  PATTERNS.md §"promoteToSharedSource action" verbatim:
  1. Resolves `consumer` from `state.nodes.find` — returns early if not
     found.
  2. Reads `consumer.data.componentId` and calls `getComponent(...)`,
     then `.external_inputs?.find(e => e.name === externalInputName)
     ?.source_component`. If `sourceCompId` is undefined, returns
     without mutating (no snapshot, no state change — the Promote button
     should not render in this case anyway, defense-in-depth).
  3. Captures `beforeIds` set, calls `get().addNode(sourceCompId, {
     x: consumer.position.x - 160, y: consumer.position.y - 40 })` per
     RESEARCH §A6.
  4. Diffs `get().nodes` against `beforeIds` to identify the
     freshly-added node (RESEARCH A2 — addNode returns void; the diff
     trick is the proven safe identifier).
  5. Reads `consumerN = (consumer.data.parameters?.n as number) ?? 1`,
     calls `get().updateNodeParams(newNode.id, { parameters: { n:
     consumerN } })` — seeds n BEFORE setBCMode so the
     selectNodeErrors-derived bc-n-mismatch tag does NOT flag the
     brand-new pair.
  6. Calls `get().setBCMode(consumerNodeId, externalInputName, { mode:
     "source", sourceNodeId: newNode.id })` — the existing setBCMode
     action's edge-materialization branch creates the dashed BC edge
     automatically.

**Snapshot discipline (Pattern A):** `promoteToSharedSource` itself
does NOT call `_pushSnapshot()` at the top. The composed actions
(`addNode`, `updateNodeParams`, `setBCMode`) each push their own. Net
result: two snapshots per Promote click (one Ctrl+Z reverts the BC
mode dispatch, a second reverts the spawn + n-seed). Inline comment
documents this as acceptable behavior; future refactor may suppress
the inner snapshots if undo-granularity becomes a UX concern (the plan
explicitly tags this as out of scope).

### Task 2 — `↗ Promote to shared source` ghost button in BCsTabForm.tsx (commit `19e0580`)

**`gui/src/components/sidebar/BCsTabForm.tsx`:**

- `FieldRow` layout rework: wrapped the existing Mode Select + its
  required-unset hint inside a `<div className="flex flex-col gap-[6px]
  flex-1 min-w-0">` and added a sibling `<Button variant="ghost"
  size="sm" className="flex-shrink-0">` rendering literal "↗ Promote
  to shared source" (Unicode U+2197 verbatim). The outer container
  became `<div className="flex items-center gap-[8px]">` matching
  UI-SPEC §"Mode Dropdown — Layout":
  ```tsx
  Mode
  ┌──────────────────────┐ [↗ Promote]
  │ Value           ▾   │
  └──────────────────────┘
  ```
- Promote button click handler: `onClick={() =>
  useStore.getState().promoteToSharedSource(nodeId, externalInput.name)}`.
  No React-hook subscription needed — the button does not need to
  re-render on the result; the visibility rule (`!!externalInput.source_component
  && entry?.mode !== "source"`) drives the re-render through the
  existing `entry` prop subscription further up the FieldRow chain.
- Legacy `+ New <SourceKind>` outline button at lines 705-711 deleted:
  the `if (matching.length === 0) return <Button variant="outline" ...>
  + New {sourceCompId}</Button>;` branch is gone. The
  `handleNewSource` local function (lines 673-703) physically removed
  — its only call site was that deleted button.
- `SourceModeEditor` now renders the source-list Select unconditionally
  (the rare empty-list path simply shows an empty dropdown — users
  reach this by selecting `Source` from the mode dropdown after deleting
  the canvas source node; the Promote button is the dominant entry path
  for "I want a shared source on this binding").
- File header comment block (lines 1-35) and SourceModeEditor section
  comment updated to reference the new Promote flow and document the
  legacy-button removal so future readers do not re-introduce it.
