# Phase 63.1 Plan 10: Bug-fix sweep — addEdge BCPort, setBCSymmetric edge holes, click-vs-drag selection Summary

Closes the four named regressions identified in Phase 63 review (CR-01 / CR-02 / CR-03 / click-vs-drag) plus confirms D-23 auto-clearing. Each fix is a tight, surgical change to `useStore.ts` paired with a shared helper extraction (`_reconcileEdgesForBCMode`) so `setBCMode` and `setBCSymmetric` no longer duplicate the BC-edge add/remove logic. Plan 01's three RED test files (`useStore.addEdge.bcport.test.ts`, `useStore.setBCSymmetric.test.ts`, `useStore.onNodesChange.select.test.ts`) all flip GREEN — 24/24 across these three files plus 20/20 on the legacy `useStore.bc.test.ts` regression suite.

## What Was Built

### Task 1 — CR-01: addEdge BCPort branch writes bcMode entry (commit `d5f33b3`)

**`gui/src/store/useStore.ts` — addEdge BCPort branch (~L1032-L1080):**

The pre-existing branch detected BCPort source-type connections and called `set({ edges: finalEdges, isDirty: true })` but did NOT persist the corresponding `bcMode` entry. Result: codegen and any re-render diverged from the visible canvas state — the bcEdge appeared in the canvas without a matching source-mode bcMode entry.

The branch now materializes bcMode in the same set() call:

1. When `connection.targetHandle` is truthy, derives:
   - `key = bcModeKey(connection.target, connection.targetHandle)`
   - `baseField = stripSideSuffix(connection.targetHandle)` (e.g. "T_wall")
   - `symKey = ${connection.target}::${baseField}`
   - `symmetric = get().bcSymmetric[symKey] ?? true` (default ON per CD-05)
   - `siblingName = symmetric ? siblingExternalInputName(connection.targetHandle) : null`
2. Constructs `entry: BCModeEntry = {mode: "source", sourceNodeId: connection.source}`.
3. Builds `nextBCMode = {...get().bcMode, [key]: entry}`; if siblingName is truthy, also writes `nextBCMode[bcModeKey(connection.target, siblingName)] = entry`.
4. `set({ edges: finalEdges, isDirty: true, bcMode: nextBCMode })`.

The defensive `else` branch (no targetHandle) preserves the original set() call without a bcMode write.

### Task 2 — CR-02/CR-03: extract _reconcileEdgesForBCMode + fix setBCSymmetric (commit `99f742b`)

**`gui/src/store/useStore.ts` — new module-level helper (~L582-L668):**

`_reconcileEdgesForBCMode(edges, nodes, consumerNodeId, externalInputName, prevEntry, newEntry, _symmetric): Edge[]` — pure function that handles all four prev/new entry combinations for ONE consumer side:

| prevEntry | newEntry | Action |
| --- | --- | --- |
| source (X) | source (X) | no-op (idempotent — dup check) |
| source (X) | source (Y) | remove old edge + add new edge (swap) |
| source (X) | undefined or non-source | remove edge |
| undefined / non-source | source (Y) | add new edge |
| undefined / non-source | undefined / non-source | no-op |

The `_symmetric` arg is prefixed `_` and reserved for future use (callers handle sibling reconciliation themselves by issuing a second call). Pure — returns a new edges array; does NOT call `set()` or `_pushSnapshot`.

**`setBCMode` refactor (~L1242-L1266):**

The pre-existing ~70-line inline edge-materialization block (lines 1155-1226 in pre-Plan-10 source) is replaced with two helper calls:

```ts
let nextEdges = _reconcileEdgesForBCMode(
  state.edges, state.nodes, componentId, externalInputName,
  previous, entry, false,
);
if (siblingKey && siblingName) {
  nextEdges = _reconcileEdgesForBCMode(
    nextEdges, state.nodes, componentId, siblingName,
    state.bcMode[siblingKey], entry, false,
  );
}
```

Behavior preserved verbatim: the helper's add/remove/swap/no-op semantics match the inline block exactly (verified by `useStore.bc.test.ts` 20/20 GREEN, which exercises every setBCMode sub-case including source→source replacement and symmetric mirror).

**`setBCSymmetric` rewrite (~L1363-L1421):**

The pre-existing body only handled CR-03 (left → right copy) and did NOT touch edges at all. The new body:

1. Always builds `nextBCSymmetric = {...state.bcSymmetric, [symKey]: symmetric}`.
2. When `symmetric === true`, reads leftKey/rightKey/leftEntry/rightEntry, then branches:
   - **CR-02:** `leftEntry === undefined && rightEntry !== undefined` → spread + delete rightKey from nextBCMode AND call `_reconcileEdgesForBCMode(..., rightInputName, rightEntry, undefined, false)` to remove the dangling right-side bcEdge.
   - **CR-03:** `leftEntry !== undefined && leftEntry !== rightEntry` → `nextBCMode = {...state.bcMode, [rightKey]: leftEntry}` AND call `_reconcileEdgesForBCMode(..., rightInputName, rightEntry, leftEntry, false)` to add/remove the right-side bcEdge to match the mirrored mode.
   - **Other cases** (both undefined, or both equal): bcMode and edges unchanged; only bcSymmetric flips.
3. `set({ bcMode: nextBCMode, bcSymmetric: nextBCSymmetric, edges: nextEdges, isDirty: true })`.

When `symmetric === false`: bcMode and edges unchanged (only bcSymmetric flips).

### Task 3 — Click-vs-drag selection sync in onNodesChange + D-23 verification (commit `47be752`)

**`gui/src/store/useStore.ts` — onNodesChange (~L868-L889):**

The pre-existing body short-circuited on contentless events (pure select / dimension batches) and only mutated `state.nodes`. ReactFlow fires a pure-select batch on click-and-drag interactions, so `selectedNodeId` never updated and the Properties panel went stale.

A new select-sync loop runs BEFORE the isContentless early-return:

```ts
for (const c of changes) {
  if (c.type !== "select") continue;
  if (c.selected) {
    if (get().selectedNodeId !== c.id) {
      get().selectNode(c.id);
    }
  } else {
    if (get().selectedNodeId === c.id) {
      get().selectNode(null);
    }
  }
}
```

Both branches handled: `selected:true` syncs to `c.id` (no-op when already selected — avoids redundant set()); `selected:false` clears selectedNodeId when the deselected id matches the currently-selected node.

The plan's `<action>` only specified `selected:true`, but the second Plan-01 RED test (`useStore.onNodesChange.select.test.ts:54-62`) asserts that `selected:false` clears `selectedNodeId`. Both branches are needed for the test to flip GREEN — treated as Rule 1 (test pins the intent).

**Inline comment** `// D-22: sync selectedNodeId from ReactFlow select events (fixes click-vs-drag stale Properties)` provides grep/traceability. The rest of onNodesChange (snapshot push on remove, isContentless early-return, applyNodeChanges set) is preserved verbatim.
