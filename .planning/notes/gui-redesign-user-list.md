Now that I think about it, maybe we can just have a single ambiguous component in the GUI called channel. The base of all three channels is the exact same – geometry, gravity vector, all that. When they diverge depends on how you connect stuff to them and how:
  - Setting boundary conditions: If you give T_wall and h boundary conditions, it is a well-defined component of type "Channel". If you set q as a boundary condition, it is a well-defined component of type "ChannelHeatFlux". If you set just the T_wall boundary condition, then it has to be a component of type "ChannelAndContacts", which is fine and legal to do.
  - Thermal connection to a plate: If you connect it to a plate on at least one side, it is a well-defined component of type "ChannelAndContacts".

  The issue with this approach is that if you already know what you want to do, you are not allowed to just drag a "ChannelAndContacts" and set its properties, since only this channel variant requires setting correlations for the heat transfer coefficient and it would then only show if the channel is determined to be CAC.

  A possible solution is to show the ambiguous channel, but also allow just dragging the regular channel variants manually. I don't know about this.
