### Gaps

**GAP-01 (Integration, THRS-09): `_extract_channel_state` supports only `ChannelAndContacts`**

`src/analysis.jl` lines 94–101 and 107–115 access `channel_sys.T_wall_left[i]`, `T_wall_right[i]`, `q_wall_left[i]`, `q_wall_right[i]`, `velocity[i]`. These symbols exist only in `ChannelAndContacts`. Neither `Channel` nor `ChannelHeatFlux` define them. Calling `threshold_analysis(sol, ssys.chf)` where `chf` is a `ChannelHeatFlux` will produce a runtime error on the missing symbol, with no clear error message. The precondition (`channel_sys` must be `ChannelAndContacts`) is undocumented in the function signature or docstring.

**GAP-02 (Flow, THRS-09): No E2E test for the solve → extract → analyze pipeline**

All THRS-09 tests in `test/test_analysis.jl` construct `ChannelState` manually, bypassing `_extract_channel_state`. The MTK solution → `_extract_channel_state` → `ChannelState` path has zero test coverage. Integration failures in the extraction bridge would not be caught.

**GAP-03 (Integration, Phase 30): New correlations lack in-system integration tests**

`fully_developed_laminar_h_spl`, `developing_laminar_h_spl`, `maximal_htc`, `turbulent_friction`, `viscosity_correction` are tested only as standalone functions. None are plugged into a compiled `Channel` or `ChannelAndContacts` system. Failures in their `(Re, Pr, T_bulk, T_wall) -> Nu` interface with MTK symbolic tracing are undetected.
