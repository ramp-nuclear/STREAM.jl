## Anti-Patterns Verdict

**LLM assessment:** Mostly yes, this looks AI-generated. Not in a vibe-coded way — code is unusually well-engineered. But visual layer reads as "competent shadcn admin dashboard," the exact aesthetic PRODUCT.md anti-references by name. Four layer-accent colors being Tailwind defaults (blue/amber/violet/rose-500) is the most legible tell. Combined with ValidationPanel's AlertCircle/Triangle/Info icons + hover:bg-accent rows + text-muted-foreground chips, and WelcomeOverlay's "to get started" card-overlay, the app reads as a textbook AI-built React tool. The meta tell is the absence of distinctive visual identity.

**Deterministic scan:** Unavailable. detect.mjs entrypoint exists but bundled detector at detector/detect-antipatterns.mjs not in install. Audit pass covers most of what detector would have found.

**Visual overlays:** Unavailable. Tauri desktop, no live URL; no browser automation.

## Overall Impression

Biggest opportunity is establishing visual identity. STREAM Composer has all the parts of a serious tool — strong workflow, validation, perf discipline, keyboard story — wearing the clothes of a generic shadcn-admin dashboard. The redesign isn't about fixing UX problems; it's about making the surface read with the confidence of the underlying engineering.

Single biggest opportunity: decide canvas + layer-accent identity first. Canvas is the largest visual area, layer accents propagate everywhere; both currently use Claude-default values. Resolving them anchors color strategy + depth approach + type scale decisions in DESIGN.md.

## What's Working

1. Validation infrastructure is unusually strong. Live counts, click-to-focus navigation, per-field red-ring markers, severity filtering, mutually-exclusive node + severity filters. Data model + cross-component event dispatch are right; only the visual layer needs rebuilding.
2. Command palette + keyboard story. cmdk palette over every component instance + resource, Ctrl+P, Ctrl+Backtick, Ctrl+1-4, layer-aware connect, custom titlebar — scores 4/4 on flexibility, canonical "speed-of-thought" interaction.
3. Performance discipline. Primitive selectors, requestAnimationFrame-deferred .select(), zero-blur shadow doctrine on canvas-transformed nodes, perf comments throughout. Redesign must preserve this.

## Minor Observations

- Empty-state copy inconsistent: ValidationPanel engineering voice vs PresetsPanel + WelcomeOverlay consumer voice. Pick one register.
- ResponsiveTabsList suggests responsive-design awareness but this is a desktop-only app — possibly over-engineered.
- Validator-id chip (text-[10px] font-mono) useful for debug but visual noise for users; consider debug toggle.
- WindowControls hardcoded macOS hex defensible as platform mimicry but should still be tokens.
- AboutDialog uses "—" as fallback; consider screen-reader-friendly alternative.
- Five total Dialogs — reasonable for a desktop app, but SavePresetModal could be inline; AboutDialog could be a Popover.

## Questions to Consider

1. What if layer accents weren't color? Border style or icon decoration could carry the same signal without burning 4 hue slots and would survive color-blindness.
2. What if the canvas were the only lit surface and everything else were genuinely chrome-recessed (edge-only separators, no fill)?
3. What if first-run wasn't an overlay at all? An empty canvas with one terse caption ("⌘O · open project · ⌘N · new") in the bottom corner.
4. What if validation results lived inline on the canvas (per-node badge expanding on hover) instead of in a separate panel?
5. What if there were no shadows anywhere except focus indication? Forces commitment to tonal-layering-only depth.
6. What if toolbox/sidebar/bottom panel weren't cards but edge zones? Edge-only 1px separators, no rounded corners, no shadow — feels Houdini/TouchDesigner, not SaaS admin.
